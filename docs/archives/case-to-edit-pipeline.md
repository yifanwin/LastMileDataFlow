# Case 自动构造设计

## 当前范围

采用 **4 个主 Agent + 程序化场景编辑、观察和检查**。单场景输入直接定位 `val-103` 等指定场景，不检索其他房屋。当前交付 case1、case1.5、case3 的构造候选，不执行机器人移动或抓取。

实体机器人会实际加载并在初始化阶段采样放置。Agent 可给出移动收益假设，但不决定 case 成立。后续接入底盘候选搜索、CuRobo 比较与实际执行；当前不将它们作为构造前置条件。

完整物理场景不裁剪；局部 Scene Graph 只是供 Agent 使用的信息子集。没有最小编辑目标、受保护物体名单或人工权限审批。

## 完整流程及输入输出

| 模块 | 输入 | 操作 | 输出 |
|---|---|---|---|
| 输入解析 | 描述、场景、数量、种子、预算 | 精确解析单场景；dataset 未实现时明确拒绝 | 规范请求与来源 |
| Agent1 | 抽象描述、任务目标 | 每次重新规范化，不检索历史模板 | Case Template |
| 场景准备 | 来源、机器人模型、宽松检查配置 | 加载完整模型、观察物理演进、建立全局图 | 未编辑基准及全局图 |
| 局部候选 | 全局图、预算 | 按支撑面分层随机采样目标，先覆盖不同支撑；保留附近墙、家具、地面及支撑关联 | 局部候选 |
| Agent2 | 候选、模板、资产类别 | 选择或扩展局部上下文，提出 move/rotate/add/remove 方向 | 构造计划、工作区域假设、资产需求 |
| 初态采样 | 目标、真实机器人、局部几何 | 实际放置，检查地面、碰撞、限位及 head 可见性 | 少量合法候选与主初态 S0 |
| 观察与资产 | 计划、S0、THOR 资产库 | 拍 head、采样辅助相机；实际加载筛选资产 | 观察包、可加载资产候选 |
| Agent3 | 模板、局部图、计划、观察包、资产 | 生成 DSL 或结构化信息请求 | 提议/补图/扩展/资产/换目标请求 |
| 信息执行 | 请求、当前基准 | 程序实际执行，再回到原提议阶段 | 更新后的输入；或信息不足 |
| 编辑程序 | DSL、种子、未编辑基准 | 参数采样、事务编辑、静置、规则检查 | 实际操作、后图、物理结果 |
| 配对观察 | 前后状态、固定相机组 | 复用前图并拍后图，核对身份与机器人漂移 | head 与辅助配对包 |
| Agent4 | 配对包、前后局部图、规则结果 | 可见布局检查；必要时请求同候选补图；另给辅助意见 | 布局检查、信息请求、移动收益假设 |
| 程序汇总 | 检查、去重、预算 | 汇总构造结果，保存接受场景 | 独立的构造/case/任务状态 |

每个候选从未编辑基准独立生成，不在上个编辑上累计修改。构建操作不调用 `Simulation.begin()`；开始真实任务后禁止恢复、重置或传送。

## 三类构造机制

- **case1**：目标与支撑面、家具或障碍的关系改变，形成操作侧的几何差异。只增加距离不合格。
- **case1.5**：三个不同工作区域分别提出 A 空间受限、B 目标操作不利、C 相对更有利的假设。A 如果不能合法放置机器人，不强行作为 S0。
- **case3**：针对目标接近、抬升或撤离相关区域布置障碍，可增加真实资产，也可组合已有物体移动和旋转。杂物多不是充分条件。

要求真实可达、路径碰撞和收益的原始目标完整保留在 `task_hypotheses`。这些不是前后静态图的必过检查。

## 统一 Agent 契约

唯一 wire Schema 定义在 [`agents/contracts.py`](../src/lastmile_dataflow/agents/contracts.py)。Gateway 把同一 Schema 放进提示输入 `output_contract`、HTTP 结构化输出参数和本地 JSON Schema 校验。领域解析器继续检查引用、参数来源、DSL 和跨字段关系。

- Agent1：输出抽象 roles、requirements、invariants、semantic_checks、task_hypotheses；不输出具体资产或编辑坐标。
- Agent2：只选择提供的 context_id/work_region_id；尺寸键为 width/depth/height；可达差异均是假设。
- Agent3：`decision`、`information_request`、`proposals`。propose 必须非空提议且请求为 null；信息请求不能夹带操作。
- Agent4：`checks` 为固定 `layout:N` 键的对象；每项只有 status/reason/views。另返回 information_request 与 agent_assessment。

Agent4 不返回 sample_id、required、verdict、intent 或任务成功标签。程序绑定身份、保留未验证假设并聚合分项：有 fail 则 fail，有 unknown 则 uncertain，其余才 pass。通过项必须引用一组实际同名 before/after 图。

格式错误在同候选、同图片上有限修复，输入带错误路径与 previous_response。最终协议失败记 agent_protocol_error 并停止，不重新采样布局来“解决格式”。截断/拒绝、服务错误与协议错误分开记录。

HTTP 每个 provider 可配置 structured_output=auto/json_schema/json_object/text。auto 尝试 JSON Schema，明确不支持时有界降级，所有请求计入预算并缓存协商结果。本地严格校验始终保留，不能把 JSON mode 当作字段契约保证。显式格式不静默降级。

当前部署按用户要求仅启用 Xera / gpt-5.6-sol / Chat Completions + JSON Schema，DMX 禁用；设置 json_schema_strict=false 兼容动态字典/可选字段，程序本地检查不放宽。Agent3/4 只接收局部图的精简几何投影，完整精度图继续供物理和编辑程序使用。

## 机器人初态

默认目标为3个实际验证的初态，找到至少一个即可继续；在有界次数内不足3个不导致过滤。每个候选在独立初始化分支放置一台机器人，记录实际 head RGB、碰撞和可见性；选目标像素最多的合法候选为 S0。未选分支关闭，不同时放多台机器人。

初态放置只证明初始化合法和目标可见，不证明导航可达、机械臂可达。A/B/C 工作区域假设与观察初态分开。编辑前后 S0 和 head 一致，允许配置范围内自然漂移，不重新设置机器人。

## 动态相机和补图

观察包包含实际 head 图和辅助外部相机图；辅助图标记 not_robot_input=true。默认尝试两个辅助视角，上限3个；相机候选次数有界。

相机围绕请求的物体和工作区域生成，不直接接受 Agent 的任意相机坐标。按实际地面覆盖、相机附近几何射线、视锥、目标射线和渲染分割筛选；保留墙体，不用隐藏外墙使视图通过。几何工作区域的可见覆盖只是观察提示，不是底盘站立证明。

- case1 关注支撑面、家具及相关操作侧。
- case1.5 关注 A/B/C 地面及障碍占地。
- case3 关注桌面障碍及目标周围关系，可请求 top/side。

信息请求包含 kind、reason，可选 node_ids、work_region_ids、view_hint、radius_m、categories。

- aux_view：实际补图，回到原 Agent3/4 阶段；不重新编辑。
- expand_context：在配置范围内扩展局部图；物理场景不变。
- assets：实际检索可加载类别并加入当前资产候选。
- change_target：排队到新上下文和新初始化，不复用旧目标的观察基准。

Agent4 只允许请求辅助配对视图。编辑后新增视角时，用同一个新相机分别渲染保存的前后状态。相机参数、分辨率和基准灯光保持配对；所有图片绑定到更新后的 pair_id。遮挡后仍拍相同视角，不能自动把相机移到另一边伪装成配对。

信息不足与真实规则失败分开。补图预算耗尽不能把未知补成 pass。

## 物理与证据边界

长度米、时间秒、角度弧度；Z 向上右手系，四元数 [w,x,y,z]，旋转是相对角度。事务完整操作组静置后检查前后端点 invariant，不要求中间步骤一直有支撑。新增物体的支撑是 after goal。

原场景不要求全场景稳定窗口；编辑、新增和关联移动对象仍检查稳定。非有限状态、求解器异常、严重穿透和被扰动支撑仍检查。阈值由显式配置决定，Agent 不修改。

Agent 的移动收益意见保存在 agent_assessment，不参与构造硬验收。不因缺少 CuRobo、底盘运动或抓取证据而拒绝已经满足的静态构造条件，也不因此宣布任务成功。

后续 CuRobo 接入需要外层底盘 XY/yaw 候选、底盘空间/路径检查和同预算单臂规划比较。现有固定站位单臂封装不能直接作为底盘优化器。有限规划无解不等于绝对不可达，规划通过不等于实际抓取成功。

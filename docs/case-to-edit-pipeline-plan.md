## 1. 初版约定与边界

**目标：抽象描述 + 具体场景 → 自动角色绑定、多个编辑提议、参数采样 → 多个验收通过的编辑场景。** 正常运行不再人工填写实例 ID、支撑实例或具体坐标。

- **每次规范化**：Agent1 每个请求执行一次，不检索、不复用历史 Case Template；同一请求的样本共享本次模板。
- **不做最小编辑**：不惩罚位移、相对角度、对象数或操作数；不优先当前位姿、局部小范围或零编辑。
- **放开对象编辑范围**：新入口不建立 `editable/protected` 对象权限表，不做审批；已实现操作支持的普通场景实例，包括家具和支撑物，均可参与编辑。
- **不增加多余审计**：不要求资产人工资格标签，不为每个样本运行完整文件审计或逐字节交接审计；保留必要运行产物和失败原因。
- **Invariant 只看前后端点**：before 为编辑前静置场景；after 为整组编辑执行并静置后的场景，不要求中间步骤一直被支撑。
- **国际单位与相对旋转**：长度 m、时间 s、质量 kg、角度 rad；右手坐标系、世界 z 向上、四元数 `[w,x,y,z]`；默认绕物体原点相对旋转，明确 world/object 轴。
- **仍保留执行正确性与物理检查**：格式、引用、数值、资产能否编译，以及严重穿透、支撑和稳定性。它们不是对象权限审批。
- **构建与连续执行隔离**：只在构建会话编辑，不改源 XML/外部资产，不在 `Simulation.begin()` 后恢复或传送；机器人初始站位作为任务上下文，不扩展机器人关节编辑。
- **样本独立生成**：每个试次从同一静置基线开始；整组操作一次验收。失败回滚，成功导出后下一试次仍从基线开始。
- **结论分开**：物理合法、编辑要求、视觉语义分别判定；真实机器人困难与任务成功不在初版证明，`case_condition` 和未执行的 `task_completion` 保持 `unknown`。

本轮约定用于新流程；旧入口保持可用，不通过把所有对象塞进旧白名单来伪装“无权限检查”。不修改项目所有者维护的 `AGENTS.md`。

## 2. 阶段总览与依赖

| 阶段 | 目标 | 主要交付 | 依赖 |
|---|---|---|---|
| S0 | 固定接口与语义 | 数据结构、样例、契约测试 | 无 |
| S1 | 无人工目标配置地建立场景事实 | 静置基线、Scene Graph、谓词查询 | S0 |
| S2 | 把符号编辑变成具体候选 | 编译器、联合采样、参数重放 | S1 |
| S3 | 执行并检查多物体编辑 | 通用构建适配、事务、前后检查 | S2 |
| S4 | 接入规范化与编辑提议 | Agent1、Agent2、文本到试次入口 | S3 |
| S5 | 接入成对三视图与视觉验收 | CameraRig、Agent3、接受/回滚 | S4 |
| S6 | 完成添加、删除和拓扑变化 | 资产选择、操作展开、图与状态更新 | S5 |
| S7 | 完成批量入口和真实验收 | CLI、预算、去重、真实运行结果 | S6 |

```text
S0 → S1 → S2 → S3 → S4 → S5 → S6 → S7
契约   场景图   编译采样   执行检查   文本Agent   视觉验收   拓扑编辑   批量交付
```

里程碑：**M1=S0–S3**，程序底座可测；**M2=S4–S5**，真实文本到 move/rotate 样本闭环；**M3=S6–S7**，四种操作和真实批量生成。阶段完成以验收为准，不以文件存在为准。

## 3. 分阶段任务

### S0：固定契约，避免各模块各自解释 DSL

目标：统一 Request、Case Template、Symbolic DSL、Executable DSL、Review 和 RunResult 的格式。
- [x] **S0-01**：新增 `construction/case_schema.py`、`construction/dsl.py`；模板包含原始意图、角色、参数、requirements、invariants、semantic_checks、pending_hypotheses，不含具体实例和坐标。
- [x] **S0-02**：定义提议 bindings、operations、goals、invariants、sampling；最终检查为模板条件与提议附加条件的合取，不能覆盖模板要求。操作字典描述实现能力，不是对象权限表。
- [x] **S0-03**：定义参数来源（用户输入/统一难度 profile/明确标注的启发式默认值）、坐标锚点和比较容差；不得把模型猜测的距离范围视为真实困难证据。
- [x] **S0-04**：固定相对旋转顺序、world/object 轴、`remove → delete` 适配；新增对象的支撑属于 after goals，删除对象与 after 必需角色/invariant 冲突记为语义失败。
- **交付**：带版本的数据结构、字段说明、最少 JSON fixture、`tests/test_case_edit_contracts.py`。
- **验收**：格式与引用错误可定位；required goal 的 `unknown` 不算通过；新增/删除端点、参数引用和单位测试通过。示例 JSON 不冒充生产配置。

### S1：先加载场景，再绑定目标与支撑

目标：不先要求人工填写 `BuildConfig.target/support`，即可得到可供 Agent 使用的场景事实。
- [x] **S1-01**：新增无目标绑定的准备入口，复用 `Simulation.from_source(target=None)` 与机器人初始化；真实静置后保存基线，解决现有 `BuildSession` 构造时即要求 target/support 的顺序问题。
- [x] **S1-02**：新增 `scenes/graph.py`，提取实例、部件、支撑区域和初始站位节点；元数据不足时标 `unknown`，不猜物体类别或操作能力。
- [x] **S1-03**：通过几何、接触和静置状态建立 `supported_by`，区分元数据归属与实际支撑；距离等数值按需查询，不建立全量两两关系。
- [x] **S1-04**：新增 `validation/predicates.py`；先实现 `supported`、`supported_by`、`distance_xy`、`distance_3d`、`direction_angle`、`inside_region`，固定距离锚点与方向来源；复杂支撑返回 unsupported/unknown。
- **交付**：实际 `Graph₀`、静置基线、谓词结果（测量值/状态/原因），以及 `tests/test_scene_graph.py`。
- **验收**：无需人工指定目标即可建图；悬空物体不因 parent 元数据被标为支撑；图中区域来自实际几何而非整件家具包围盒；固定实例名称可重新解析底层索引。

### S2：联合采样、相对旋转与按序编译

目标：给定符号提议和场景图，输出多组具体 move/rotate 操作，暂不依赖真实模型调用。
- [x] **S2-01**：新增 `construction/compiler.py`，解析绑定、参数与区域；world 轴左乘、object 轴右乘相对旋转，最后转换为世界位姿和 `[w,x,y,z]` 四元数。
- [x] **S2-02**：新增 `construction/sampling.py`，提供 uniform/grid/candidate；联合考虑足迹、边界、支撑高度和 case 条件，不独立随机 x/y/z 后期待成立。
- [x] **S2-03**：引入临时布局，按操作顺序更新几何；支撑物先移动时，后续放置必须使用新区域坐标。预测关系仅用于候选生成，不作为最终支撑事实。
- [x] **S2-04**：新候选路径不调用旧最小编辑排序；采用种子随机或覆盖性选择，保存实际采样参数；未找到候选返回 `search_exhausted`，不宣称数学无解。
- **交付**：具体候选列表、采样重放输入、`tests/test_edit_compiler.py` 与 `tests/test_edit_sampling.py`。
- **验收**：非零初始朝向及不同轴 world/object 组合正确；固定环境与种子可重放参数；大位移、多对象、较大角度不因改动幅度降权；测试 fixture 只用于验证程序逻辑。

### S3：打通通用编辑事务与前后规则检查

目标：执行整组 move/rotate，包括家具和邻近对象，不把新 DSL 再套回旧对象 ACL。
- [x] **S3-01**：抽出或适配 `runtime/build_session.py` 的执行正确性检查和事务机制；新入口不执行对象白名单/保护表策略，旧 `build` 配置与回归保持兼容，共享底层仿真能力。
- [x] **S3-02**：支持延迟绑定、多个放置区域及多实例操作，解除“所有物体默认落到 config.support”耦合；固定家具编辑复用 spec 修改、重编译和按名称迁移状态。
- [x] **S3-03**：新增 `validation/edit.py`，只在整组方案 before 和静置 after 检查 invariant；before 已不满足时记为该绑定不适用，不强行算一次成功修复。
- [x] **S3-04**：复用穿透、支撑、稳定性检查，检查实际受影响对象与邻域；新流程取消“未编辑邻居必须不动”的默认规则，普通变化不是失败。物理阈值统一配置，不由 Agent 放宽。
- [x] **S3-05**：完成基线恢复/独立分支、失败回滚和新结果导出；设计视觉复查前的待接受状态，禁止在 Agent3 通过前计为最终样本；不把旧 `initial_frozen_dir` 直接当通用快照入口。
- **交付**：可独立重试的构建执行接口，前后实际图与规则结果，`tests/test_case_edit_runtime.py`。
- **验收**：桌子和杯子可成组移动，中间暂时失去支撑不被逐步拒绝；最终悬空/严重穿透失败并回滚；合法邻居变化允许；下一试次无角度或拓扑累积；begin 后仍不能编辑或恢复。

### S4：接入 Agent1 和 Agent2，取消人工转换

- **交付**：文本到规则试次入口、prompt 与调用适配、`tests/test_case_edit_agents.py`，真实 Agent1/2 调用示例产物。
- **验收**：对适用输入，运行者只给抽象描述和场景，不手工补绑定/坐标；同一描述在不同实例命名下仍可工作；未知操作、格式失败与服务异常分类清楚；mock 不替代真实模型验收。

## 4. 接受条件与最少产物

接受一个编辑样本需要：必需角色存在、before/after invariant 通过、after goals 通过、物理合法、Agent3 pass，以及布局非重复/非基线。`pending_hypotheses=unknown` 不阻塞；必需规则条件 unknown 会阻塞。

```text
outputs/case_edits/<run_id>/
  request.json、template.json、result.json
  baseline/scene/、baseline/graph.json
  samples/<sample_id>/sample.json、graph_after.json、rgb/
  samples/<sample_id>/scene/   # 最终通过样本的场景
```

`sample.json` 合并提议、绑定、采样参数/种子、具体操作、规则/视觉结果和拒绝原因；记录场景与检查点身份、必要配置摘要，不新增独立审计链。失败保留已产生的图像，不伪造缺失图像或未执行轨迹。

实施从 **S0 的结构定义与 fixture** 开始；各阶段先运行相关测试，再运行已有回归。真实模型、GPU/资产测试单独执行，不能用简化 fixture 或 mock 的结果代替。

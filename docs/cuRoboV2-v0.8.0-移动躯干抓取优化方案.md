# cuRoboV2 v0.8.0：移动底盘＋单参数躯干的抓取优化方案

日期：2026-10-10，Asia/Shanghai。状态：**方案，尚未实施**。

## 1. 核查结果与最终约定

已核对本机 v0.8.0 标签中的 `MotionPlanner.plan_grasp`、warmup、URDF mimic 解析与 RBY1M 原始模型。方案可采用 **11 个连续规划自由度**，不再枚举躯干高度；需要迁移适配层，不能直接替换旧 Python 导入。

| 项目 | 最终约定 |
|---|---|
| cuRobo 版本 | 严格固定 v0.8.0，提交 `4ea77366ca48ee453e7df139e39fa6532af49f3b` |
| 活动关节 | base_x、base_y、base_theta＋活动臂 7 关节＋torso_1（h），共 11D |
| 躯干关系 | `[0,h,-2h,h,0,0]`，h 连续优化，不再离散搜索 |
| 离散选择 | 抓法候选 × 左右臂；h 由规划器联动求解 |
| 规划入口 | 完整原生 `MotionPlanner.plan_grasp`，接近/抓取/抬起都启用 |
| 内部尝试 | 每个 `plan_pose` 保留原生默认最多 5 次，不改成旧配置的 3 次 |
| 连续采集中 S1 | 首次操作＋最多 1 次重试，共最多 2 次；失败后换次优 S1 |
| 普通站位试验 | 每点默认 5 次独立试验，保持可配置 |
| 其他预算 | IK seeds=32、trajectory seeds=4、抓法候选上限=4、单次操作规划查询上限=12；保持现有超时，不继续加预算 |
| 输出规则 | 任务最少 1 段、最好 3 段成功连续轨迹；热图、四视频、S0 失败证据与整体计时保留 |

内部尝试、操作机会、采样试验是三种计数，不混用。内部 3→5 是用户明确接受的变更，不能宣称计算量完全不变。`plan_grasp` 内部包含目标集选解和三段规划，也不能只按一个顶层 API 调用计费。

本轮只新增方案文档，不更换依赖、不修改运行源码、不停队列、不改既有结果。

## 2. 版本与环境隔离

3. 不切换或修改用户的 `curobo/` main checkout；在工作目录内准备固定标签的独立依赖副本/安装来源。

6. 任何新采集使用新 run-id、冻结配置和源码摘要；旧结果只读，不跨版本原地续跑。

v0.8.0 有大幅 API 重构。当前 main 示例只是参考；具体调用与配置必须按固定标签实现。尤其该标签的 `MotionPlannerCfg.create` 不含当前 main 后来增加的部分参数，不能直接照搬 main 的配置关键字。

## 3. 用 mimic joint 建立 11D 模型

规划配置用原始 RBY1M URDF 的 **run-local 派生副本**，不修改 MuJoCo XML、原始 URDF 或共享资产。

| 真实关节 | 规划处理 |
|---|---|
| torso_0 | 固定为 0 |
| torso_1 | 独立活动关节，规划层别名 h |
| torso_2 | mimic torso_1，multiplier=-2，offset=0 |
| torso_3 | mimic torso_1，multiplier=1，offset=0 |
| torso_4、torso_5 | 固定为 0 |

核心 URDF 标记：

```xml
<!-- 添加到派生 URDF 中相应 joint 内；原有 origin、axis、link 保留。 -->
<mimic joint="torso_1" multiplier="-2" offset="0"/>
<mimic joint="torso_1" multiplier="1" offset="0"/>
```

v0.8.0 的 `LinkParams` 含 `mimic_joint_name`、`joint_offset`，URDF parser 会将 mimic 从独立活动自由度中合并。优先使用标准 URDF mimic，不修改 cuRobo 上游源码。

限位不是简单继承 torso_1 的原始范围：

- h 范围取 20D 协议 `[0,.738]` 与六个实际关节联动允许范围的交集。
- 用 `min/max(a*h_min+b, a*h_max+b)` 检查负倍率的端点，不依赖 parser 对负倍率的简化限位检查。
- h 的速度、加速度、jerk 上限由参与关节的实际上限除以 `abs(a)` 后取最小值；torso_2 的倍率 2 必须计入。
- 重建 11D cspace、默认姿态和权重，不截取旧 23D 数组后遗漏 h，也不把旧躯干强锁权重当成新 h 的固定约束。
- 初始化后按名称验证恰好 11 个活动关节；torso_2/3 不得作为额外自由度出现。实际库排序可能不同，运行层必须按 joint name 映射。

在理想联动初始化姿态下测试 h=0、中间值、.738 与若干内部值，检查双 TCP、躯干 link 和碰撞球 FK。mimic 是规划模型，不会把 MuJoCo 六关节变成机械硬连接；实际联动误差继续记录，真实碰撞检查继续使用实际几何。

## 4. 不再把 head／闲置 TCP 当作目标

每个活动臂规划器：

```text
tool_frames = [ee_left_tcp] 或 [ee_right_tcp]
head、闲置臂：相对关节配置锁定
torso_0/4/5：固定 0
torso_1：活动；torso_2/3：mimic
collision geometry：底盘、躯干、双臂、夹爪和 head 等保留
```

目标帧与碰撞 link 是两份独立配置。仅有活动 TCP 是目标，不表示删掉其余 link 的 FK、惯性或碰撞几何。核对现有 head 碰撞代理的覆盖；缺失部分只能派生到本地规划模型，不能以删除机器人部件绕过检查。

V2 warmup 通过 `tool_poses` 生成目标。将目标帧集合限制为活动 TCP，并禁止可视化配置自动把其他 link 加入目标集合，避免旧版辅助世界姿态目标的问题重新出现。

验收：warmup 前后以及连续两个不同抓取请求中，规划目标集合都只有活动 TCP；底盘/h 改变时，head 与闲置臂允许随整机改变世界位姿，但其自身关节配置仍固定。

## 5. 完整 plan_grasp 与抓法选择

每点仍从现有资产抓法中选最多 4 个候选，但采用方向/空间多样性排序，避免只保留初始底盘方向最有利的窄子集。候选总数不增加。对左右臂分别构造 `GoalToolPose`，h 不再绑定候选索引。

执行前调用：

```python
# 方案示意；不是已交付实现。
result = planner.plan_grasp(
    grasp_poses=grasp_goalset,
    current_state=measured_joint_state_11d,
    grasp_approach_axis="z",
    grasp_approach_offset=-0.08,
    grasp_approach_in_tool_frame=True,
    grasp_lift_axis="z",
    grasp_lift_offset=0.10,
    grasp_lift_in_tool_frame=False,
    plan_approach_to_grasp=True,
    plan_grasp_to_lift=True,
    disable_collision_links=[],
)
```

8cm 预抓取、10cm 总抬升对应当前操作尺度；最终接近目标的额外 1cm 偏移仍由现有配置控制，并在元数据明确记录。规划基准固定为水平世界坐标系，世界 Z 抬升不随着底盘转向变成工具轴撤离。

原生 plan_grasp 先选一个目标，再规划三段；**不是对所有抓法联合求最优整链，也不保证选中的抓法一定能完成后续段**。若已选抓法在后续失败，可从原有限候选集中移除该抓法、测试剩余候选/另一臂，但所有内部规划查询仍计入原单次操作上限 12；到预算即停止。不得悄悄增加候选或额外“无限 fallback”。

成功时保存目标集索引、抓法来源、活动臂、各段 11D 轨迹、每段状态与求解耗时。不要把三段分别规划的内部实现描述成联合全局优化。

在本工程增加薄适配器，保留对原生 `super().plan_grasp(...)` 的调用；通过其 `plan_pose` 入口统计目标集/三段查询、切换目标接触策略并在预测 lift 前配置持物几何。warmup 与正式操作使用不同上下文，warmup 不消耗单次操作的 12 次查询额度。原生每个 plan_pose 默认 5 次保持不变，不修改上游安装源码；异常时在 finally 恢复碰撞/附着/姿态 criteria，防止影响下一次请求。

## 6. 保留全部避碰，并精确处理抓取接触

原生 `disable_collision_links` 会禁用指定 link 的碰撞球，不能精确表达“手指只允许接触这个目标”。因此明确传空列表，不默认关闭手指、head、闲置臂、躯干或自碰撞。

正常抓取需要有允许的目标接触，不能要求手指与目标永远零接触。采用两层规划碰撞世界：

1. 非目标环境与完整机器人自碰撞：所有机器人碰撞球参与检查，沿用现有安全裕度和邻接结构的合理排除项，不扩大排除名单。
2. 目标专属碰撞检查：对目标保留所有非允许机器人部位的距离约束，仅在指定阶段允许活动手指与目标接触。目标不能对整个机器人完全消失。

第二层不是原生 API 的现成 pair-mask 承诺；需要本工程的目标专属 cost/validity 适配，作用于优化、终点与轨迹检查，不能只在末端做一个检查。其正确性是实施验收项：手指碰目标可通过，手指碰家具、手掌/躯干碰目标不得通过。若不能满足，应明确报不支持，不能退回全局关闭手指碰撞。

物理执行继续逐物理步用 MuJoCo 实际几何拒绝非允许接触、穿模和越界。规划插值轨迹也检查 2m 圆形工作空间，不能只靠底盘 x/y 的矩形关节边界。

抬起的持物碰撞必须覆盖目标：整链预规划中用预测 grasp 末态建立临时持物碰撞模型，实际闭爪后再按实测 TCP/物体位姿更新。都只是规划几何，不向 MuJoCo 添加焊接、吸附或瞬移。阶段切换与恢复在适配层实现，使用 V2 attachment manager 并保证异常后状态不污染下一次请求。

## 7. 将 11D 轨迹下发为现有 20D 动作

对每个轨迹点按名称读取 base、活动臂、h，转换为：

| 20D 槽位 | 下发内容 |
|---|---|
| `[0:3]` | 规划基准转换到世界系后的底盘目标减实测状态；yaw 用最短角差 |
| 活动臂 7D | 目标关节角减下发时实测关节角 |
| 闲置臂 7D | 保持锁定的相对关节配置，不固定其世界 TCP |
| 两夹爪槽位 | 当前阶段对应的绝对位置 |
| `[19]` | 该轨迹点的 h 绝对目标，统一桥接展开 `[0,h,-2h,h,0,0]` |

base、arm、h 使用同一个时间进度/缩放因子；h 不能直接跳到终点。h 的命令保持绝对语义，不能把 `delta_h` 直接写入 `[19]`。到段末同时检查底盘、活动臂、h 目标进度与实际 TCP；不再只检查原 10D。

夹爪不加入规划优化自由度，仍由阶段控制。先执行 approach/grasp，连续闭爪，再依据实际状态执行 lift。只有预规划轨迹与当前状态/碰撞模型仍一致才复用 lift；否则在剩余规划预算内重新规划，不能强行执行过期轨迹。

已有 torso_error_policy=record_only 保留；真实关节/执行器限位、碰撞、2m 工作空间和任务接触/保持规则不放松。实测六关节不完全在理想 mimic 曲线上时，记录其与单参数模型的残差，不用投影结果覆盖 MuJoCo 状态；启动 FK 精度测试与运行时真实状态校验分开。

## 8. 连续采集、S1 重试和已有数据契约

流程：

```text
每个合法站位独立试验 → 成功率/失败证据 → Gaussian 热图
→ 选 S0 与成功率高的 S1 → A* 连续导航
→ S1 操作（首次；必要时重试一次）
→ 成功则保存连续段；否则换下一个 S1，建立新的完整连续 attempt
```

S1 重试从当前实测状态开始，更新目标世界姿态、碰撞世界和规划起点。允许安全开爪/撤离恢复，但必须真实下发动作并进入同一记录，不能 reset/恢复快照/传送。

原代码的 winning_control 绑定 grasp、arm、torso_h；新版本只把已成功抓法/手臂作为优先项，**不得把历史 torso_h 重新锁死**。操作中允许底盘继续优化移动，S1 是导航到达的操作起点，不要求机器人整个操作都停在那个精确坐标。

最多两次机会不是必须耗尽：发生严重碰撞、数值异常、不可恢复状态或总超时应提前结束。原有目标位移安全检查保留/显式版本化，不以改宽阈值强迫重试。采样点五次独立 trial 不受 S1 重试次数影响。

保留原始 val 场景、初始点过滤、Gaussian 成功率区域图、S0 的失败证据和有执行时的视频。成功连续段保留全部导航、恢复动作及重试时间线，不把中间失败隐藏剪掉；四路视频与动作同步，分析型第三人称标注阶段与事实。最少 1、最好 3 段进入最终数据集的规则不变。

## 10. 验收与不能提前承诺的结论

**单元/结构回归：** mimic 倍率与负号、11D 名称集合、六关节限位交集、world/local 坐标、绝对 h 下发、warmup 前后目标集合、目标接触例外、持物恢复、异常清理、三层预算和视频时间线。

**真实模型验收：**

- Cup_30 S0042 原失败起点：验证完整三段规划、底盘/h 联动，以及真实闭爪/抬起/保持。
- Potato_17：不枚举高度，观察 h 是否能在联动约束下找到有效姿态；不能只凭 free IK 成功验收。
- AlarmClock_12：不强制最大 h，原碰撞站位检查实际是否仍碰撞及碰撞位置。
- 左/右臂各做测试；S0→S1 至少覆盖首次成功、可恢复失败后成功、失败提前中止三种计数路径。
- val103 完成所有合法站位的预定试验后生成热图，区分规划成功率、真实操作成功率和最终连续段数量。

不设置未经测试的“必达某成功率”承诺。某些原场景/抓法确实可能不可操作；失败要能定位到关节联动、IK、环境/自碰撞、轨迹优化、跟踪、未夹住或滑落，而不是混成“不可达”。

## 11. 已识别风险与来源

| 风险 | 处理方式 |
|---|---|
| 本地 main 和 v0.8.0 API 不完全一致 | 按固定标签源码实现，不使用 latest 文档中的新增参数 |
| 原生 plan_grasp 无全链候选最优保证 | 候选剩余集合继续搜索，但不超 4 候选/12 查询 |
| 目标接触与“全局不碰撞”冲突 | 只允许目标特定手指接触，不能关闭整个 link 的环境碰撞 |
| 实际六关节有联动误差 | 记录残差并继续实际几何安全检查，不修改实测状态 |
| 原生预规划没有真实抓住证明 | 真闭爪、实测持物模型、lift 再验证、保持验收 |
| 三段规划与重试耗时较长 | 不再叠加搜索预算；预热/缓存按模型身份复用，耗时如实记录 |

方案的视觉表达采用自由度/映射/里程碑表和文本执行链；不制作尚无实测数据的成功率预测图。

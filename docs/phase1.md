# 第一阶段：场景、机器人与统一记录底座

## 实现入口

- `scenes/source.py`：原始 ProcTHOR 或自定义 MJCF 来源，不要求 episode；实例/资产/名称映射与目标消歧。
- `scenes/initialization.py`：有限预算的有效底盘初态选择；从编译 room mesh 采样、地面 ray 与穿透检查。
- `robots/action.py`：严格 20 维协议及 torso 联动。
- `robots/rby1.py`：模型集中适配、夹爪位置伺服、相机、固定头、初始化、关节/执行器限位、实际 ctrl。
- `runtime/simulation.py`：模型挂接、状态/相机、物理 stepping、完整快照与恢复权限。
- `runtime/runner.py`：初始化→冻结→执行→落盘的短动作编排、状态分类与证据一致性检查。
- `recording/recorder.py`：所有 attempt 的配置、动作、现场、相机、视频、事件与独立结果。
- `validation/lightweight.py`：每个物理步的严重异常停止与轻微接触/反馈告警。
- `integrations/legacy.py`：显式旧 episode 转换，仅导入初态/新增资产/物体位姿。
- `integrations/waypoints.py`：规划绝对关节与导航子目标到统一动作的适配边界。

机器人信息不放到 case 脚本中；首批 case 类型可在 TaskConfig 中声明，但本阶段只执行 `short_action`。
未实现的成功条件或编辑请求直接拒绝，不能接受配置后忽略。

## 恢复和连续性

原始模型 + RBY1 的实际编译模型保存为 MJB，初态使用 `mjSTATE_INTEGRATION`，恢复不需要旧工程。
保存模型摘要、MuJoCo 版本、实例映射、固定头目标与控制时钟余数。
独立恢复检查文件完整性和机器人配置，创建新的 attempt、模型实例与轨迹。

`begin()` 后永久禁止 `restore_snapshot()`、`freeze()`、机器人 `initialize()` 和再次 `begin()`。
终止后的恢复也必须新建实例。相对动作在当前实测状态转换为位置伺服目标，连续执行不写 qpos。

使用 [MuJoCo 官方 Python API](https://mujoco.readthedocs.io/en/latest/python.html) 的模型挂接、Renderer 和 state APIs；
以实际安装版本验证快照兼容性，不假定跨 MuJoCo 版本二进制模型可复现。

## 轻量检查与标签

必需阻断：格式错误、非有限动作、非法步长、关节/执行器越界、严重非允许穿透、非有限物理状态、MuJoCo 警告。
允许正常地板支撑接触；极深底盘/地板穿透仍不豁免。轻微接触和头/躯干反馈差异记录告警。
固定底盘试验禁止底盘命令；实测移动超出当前声明范围时保留数据并标 `protocol_invalid`。

三个结果独立记录：

1. 场景有效性：这里只检查加载、初态与明显物理异常，并声明检查范围。
2. case 条件：`unknown`，等待第二/三阶段验证。
3. 任务完成：`unknown`，没有抓取/把手/放置验收器。

短动作跑通不是成功见证；保存短执行 MP4 不是重跑旧抓取。

## 验证方法

单元回归使用明确标注的**简化协议模型**，测试动作校验、原子下发、快照精确恢复、防重置、失败分类、
空轨迹无视频、渲染故障保留运动、导入转换/路径安全与证据检查，不证明真实 RBY-1 任务成功。

`tests/real_smoke.py` 显式加载原始 ProcTHOR + 真 RBY1，每所房屋选择不同的实际目标实例，
执行最多 6 步，保存三相机视频并解码核对帧数/尺寸；再从快照创建独立 attempt，比较完整初态。
可选旧样例以独立 fixture 转换后的初态恢复为回归，不从旧模块或旧模型加载。

实际运行结果与失败保留位置见 [交付总结](../reports/phase1/phase1-delivery.md)。

## 当前限制

- 初态采样只是有预算的安全起点选择，不是导航规划、可操作站位或最优站位搜索。
- 场景穿透阈值是已冻结的尺度相关启发式，尚未完成逐资产类别校准。
- 支撑对象、滑落/柜层/容器关系、邻近资产变化的编辑验收属于第二阶段。
- cuRobo 的原生世界模型、GPU 搜索、站位图属于第三阶段；当前只提供明确的规划结果/动作适配契约。
- 连续导航、VLA、失败检查点接管属于第四阶段；批量队列、续跑和数据集发布属于第五阶段。
- 当前 attempt 自包含模型，会重复存储；完整架构已预留共享场景版本的后续演进。
- 视频依赖可用 OpenGL/EGL 和 ffmpeg。资产通过只读外部路径指定，首轮编译涉及 NAS 大量读取。

# 代码导览（初学者版）

这是一份“怎么读这个工程”的入门说明。所有文件跳转都是相对本仓库根目录的链接，点一下即可打开对应源码。

> 阅读约定：本工程把**结论**分成三种独立状态——`success`（已证成功）、`failure`（已证失败）、`unknown`（未知）。
> 代码里大量 `status=...`、`reason=...` 都遵循这个约定。**“没执行”绝不被写成“失败”，“规划无解”绝不被写成“物理不可能”。**
> 这是理解整个工程最重要的前提。

---

## 0. 这个工程到底在干什么

一句话：**让一台 RBY-1 机器人在 MuJoCo 仿真房子里，按照固定的动作协议做动作，并把全过程（动作、状态、相机、视频、结果）完整、不可篡改地记录下来。**

它面向一个“五阶段数据采集管线”：

| 阶段 | 目标 | 当前状态 |
|---|---|---|
| 阶段一 | 场景/机器人/记录**底座**：能把房子加载进来、让机器人动、把一切存下来 | ✅ 已实现并有回归 |
| 阶段二 | **规则式场景构建**：把杯子等物体摆到桌面上，静置检查是否站稳，冻结场景 | ✅ 已实现（case1 已验证） |
| 阶段三 | **站位图 + 真实抓取采集**：在房子不同位置分别尝试抓杯子，记录成功/失败 | ✅ case1 已实现，case2/3 未验收 |
| 阶段四 | VLA 策略 + 连续导航 + 失败接管示教 | ⏳ 只有目录占位，无实现 |
| 阶段五 | 批量调度、断点续跑、数据集发布 | ⏳ 只有目录占位，无实现 |

**初学者最容易踩的坑**：看到 `src/lastmile_dataflow/navigation/`、`policies/` 这些目录就以为有导航/VLA 能力。
其实它们只有 `README.md`，里面明确写着“**规划目录，尚未实现**”。目录存在 ≠ 功能存在。

## 1. 先跑一次，建立直觉

在 `LastMileDataFlow/` 目录下（需要已装好依赖的环境）：

```bash
# 最简：加载 2 号房子，让机器人走 6 个控制步，存到 outputs/attempts/<id>/
DATAFLOW_PYTHON=.venv/bin/python bin/lastmile-dataflow run --house 2 --steps 6

# 审计刚才那次记录是否自洽（文件齐全、时间连续、视频帧数对得上）
DATAFLOW_PYTHON=.venv/bin/python bin/lastmile-dataflow audit outputs/attempts/<id>
```

跑完打开 `outputs/attempts/<id>/`，你会看到：`config.json`（冻结配置）、`trajectory.jsonl`（每步动作）、`observations/`（三相机图片）、`videos/`（MP4）、`result.json`（结论）。

**先看产物，再看产生产物的代码**，这是理解顺序的关键。

## 4. 五阶段数据流图

```
输入：CollectionJob + RobotConfig + TaskConfig + CollectionConfig
  │
  ├─ catalog    静态检索（SQLite，只解析 XML/metadata，不加载仿真）
  │                 └─▶ SceneCandidate / AssetCandidate
  │
  ├─ scenes + runtime   加载源场景 → 实例映射 / 几何事实 / 初始观察
  │
  ├─ construction ↔ agents   【阶段二】受限编辑候选 → 决策 → 编辑事务
  │                 │
  │                 ▼  runtime 静置(settle) + validation 落位/穿模检查
  │                 ▼  agents 复查 → 修复 / 回滚 / 预算退出
  │                 ▼  冻结 SceneVersion + Checkpoint
  │
  ├─ stations → planning → runtime   【阶段三】站位采样 → cuRobo 规划 → 真实执行
  │                 │
  │                 ▼  recording：成功与失败 attempt 都保存；规划无解不留假轨迹
  │                 ▼  validation：case 实证确认 / 反馈 construction
  │
  ├─ policies + navigation + planning   【阶段四 · 未实现】专家/VLA 连续执行
  │                 └─▶ demonstrations：失败现场 → 接管 / 新分支
  │
  └─ scheduling + exporting   【阶段五/已部分实现】有限预算队列 → 质量检查 → 数据集发布

recording 贯穿全链路；诊断信息只追加到事件/证据，绝不覆盖原结果。
```

## 5. 核心流程图：阶段一 `run` 一次 attempt

对应代码：[`runtime/runner.py` 的 `run_attempt()`](../src/lastmile_dataflow/runtime/runner.py)

```
                         ┌──────────────────────┐
                         │ CLI: run --house 2   │
                         └──────────┬───────────┘
                                    ▼
                    ┌───────────────────────────────┐
                    │ 1. 开 attempt 目录 + 冻结配置  │  recorder = AttemptRecorder(...)
                    └───────────────┬───────────────┘
                                    ▼
              ┌─────────────────────────────────────────────┐
              │ 2. 加载场景                                  │
              │    有 --snapshot ? from_snapshot()           │
              │    否则          → from_source()             │
              │    （挂接机器人 MJCF、编译模型、建实例映射）    │
              └───────────────────┬─────────────────────────┘
                                  ▼
              ┌─────────────────────────────────────────────┐
              │ 3. 初始化底盘（仅此时允许写 qpos）            │
              │    initialize_robot()：采样 XY + 地板 ray    │
              │    + 穿透检查，最多 max_initialization_trials│
              └───────────────────┬─────────────────────────┘
                                  ▼
              ┌─────────────────────────────────────────────┐
              │ 4. 冻结 scene/（model.mjb + initial.npz +   │
              │    version.json + instances.json + 校验和）  │
              └───────────────────┬─────────────────────────┘
                                  ▼
              ┌─────────────────────────────────────────────┐
              │ 5. sim.begin()  ← 从此禁止任何重置！          │
              └───────────────────┬─────────────────────────┘
                                  ▼
        ┌───────────────────────────────────────────────────────┐
        │ 6. for step in range(max_steps):                       │
        │      raw = 动作流 / 默认小幅摆臂 20 维动作              │
        │      sim.step(raw):                                    │
        │        robot.apply(raw) → 校验 → 原子写 ctrl           │
        │        按 20Hz 换算物理子步数，逐子步 mj_step           │
        │        每个子步 inspect_state()，出严重异常就停          │
        │      记录 trajectory.jsonl + 渲染三相机 + 追加视频帧     │
        │      严重异常 → execution_failed 并 break               │
        │      固定底盘漂移超限 → protocol_invalid 并 break       │
        └───────────────────────────┬───────────────────────────┘

              ┌─────────────────────────────────────────────┐
              │ 7. 存 final_snapshot + final_state          │
              │ 8. recorder.finish()：写 result.json +      │
              │    artifacts.json（全文件 SHA-256 清单）      │
              └─────────────────────────────────────────────┘

结果分级（status）：execution_complete / load_error / invalid_initialization /
                    invalid_control / execution_failed / protocol_invalid / infrastructure_error
三个独立结论（results）：scene_validity / case_condition / task_completion
```

## 7. 阶段二流程图（规则式场景构建）

对应代码：[`workflows/build.py`](../src/lastmile_dataflow/workflows/build.py) + [`runtime/build_session.py`](../src/lastmile_dataflow/runtime/build_session.py)

```
build_request(sources, ...)
  │
  ▼
run_build() / supervised_build()（隔离子进程，硬墙钟期限）
  │
  ├─ 1. BuildSession(...)  → 初始化机器人 + 选出支撑面 region
  │
  ├─ 2. initial_operations ? 一次性事务 : 直接 settle()
  │
  ├─ 3. validate()  ← 物理/构建要求是否全部通过
  │        │
  │        ├─ 通过 → 跳出循环
  │        └─ 不通过 → while 循环：
  │              4. candidates()  规则生成“最小改动”候选（移动/旋转/加/删）
  │              5. observe()     打包观察（可选渲染诊断图）
  │              6. 决策：规则取 cost 最小 / 有 backend 时走 DecisionGateway
  │              7. transact(operations)：
  │                   snapshot() 存检查点
  │                   _precheck() 权限/保护/拓扑校验
  │                   执行编辑 → settle() 真实静置 → validate(baseline)
  │                   通过 → committed；否则 restore() 回滚
  │              8. 失败候选加入 failed 集，重算 check，继续循环
  │
  ├─ 9. freeze(version_dir)：写 model_id / checkpoint_id / mapping_id
  │     再 from_snapshot 独立恢复，逐字节比对状态与现场必须完全一致
  │
  ├─ 10. 写 task_candidate.json；可选跑 6 步短动作交接回归
  │
  └─ 11. finally：写 result.json + artifacts.json（含成本）

结论：candidate_ready / candidate_ready_regression_pending / handoff_failed /
      budget_exhausted / interrupted / failed
注意：case_condition 与 task_completion 始终为 unknown，直到阶段三给出真实执行证据。
```

## 8. 阶段三流程图（站位图 + 真实抓取）

对应代码：[`workflows/stations.py`](../src/lastmile_dataflow/workflows/stations.py) + [`stations/execution.py`](../src/lastmile_dataflow/stations/execution.py)

```
station-map --build <build> --station-config <cfg> --run-id <id>
  │
  ├─ 校验 build 是 candidate_ready 且 scene_version/target/case_type 匹配
  ├─ 冻结输入快照（frozen_inputs.json，含 input_digest）
  ├─ Simulation.from_snapshot()  ← 独立恢复，不继承任何成功标签
  │
  ├─ A. 站位采样 coarse_samples()：probe + 源起点 + 目标周围多半径/朝向
  ├─ B. 几何过滤 filter_station()：地面支撑 + 关节限位 + 机器人碰撞
  ├─ C. 展开 (站位 × 臂 × 躯干高 × grasp) 组合，全部标 not_tested
  │
  ├─ D. 调度（空间覆盖优先：同一配置先扫遍所有站位）
  │      for each row:  run_station_attempt(...)
  │          ├─ 初始化：place_base（只改 base qpos，非 base 完全不变）
  │          ├─ dry planner：只用于诊断，模拟器用完即关，不执行
  │          │     无解 → status=planning_no_solution（空轨迹、无视频）
  │          ├─ 真实执行：新开 Simulation → begin()
  │          │     torso_adjust → pregrasp → approach → close → lift → hold
  │          │     每个物理 tick 采样 PickMonitor（力/支撑/漂移/碰撞）
  │          ├─ evaluate_pick()：双指力>0 + 抬升≥5cm + 无支撑保持≥2s
  │          │     逐项违约 → failure；证据缺失 → infrastructure_error
  │          └─ 渲染交付视频（实际 qpos 回放，无插值）
  │
  ├─ E. refinements()：在“实测成功点附近且有冲突”处做有界局部加密
  ├─ F. case1_verdict()：源起点已测困难 + 别处有严格成功 → status=pass
  ├─ G. 审计全部 attempt（audit_station_attempt）；任一出错则整体无效
  ├─ H. 追加 feedback（不改原 build），导出 REPORT/HTML/PNG/SVG
  └─ summary.json 的 data_collection_complete = 同时有成功 + 失败 + case pass + 审计通过
```

三层结论务必分清（这是阶段三的核心设计）：

```
geometry  : valid / geometry_filtered / not_tested     （能不能站在那）
planning  : success / no_solution / infrastructure_error / not_tested  （能否规划出路径）
execution : success / failure / not_executed / incomplete / infrastructure_error （真的动了吗、成没成）
```

## 11. 一句话总结工程的设计哲学

> **“能证的就给证据，不能证的就说未知，绝不为了好看伪造成功。”**
> 你会在几乎每个模块里反复看到这个模式：状态字段是有限枚举、失败证据必须保留、
> 下游只能追加不能覆盖、每一个数字都能追溯到原始 attempt。

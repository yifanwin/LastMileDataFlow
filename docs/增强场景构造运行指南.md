## 1. 环境与 GPU


## 2. 配置

配置文件：`configs/scene_datasets/val103_val104_countertop_targets_v3.json`。
路径相对配置文件目录解析；复制或移动配置时检查路径。

| 配置项 | 设置/用途 |
|---|---|
| `schema_version` / `rule_version` | `scene-dataset-recipe-v1` / `scene-cases-v3` |
| `dataset_dir` / `asset_library` | ProcTHOR val场景目录 / THOR障碍物资产目录 |
| `robot_config` | `rby1_position_head320.json`；机器人XML路径、控制频率等在该文件中 |
| `houses` | 两场景：`["val103","val104"]`；单场景：`["val103"]`；全量：显式列出本地完整XML/metadata对应的所有val house |
| `targets` | 自动选择：`{}`；单目标：`{"val103":["Cup_30"]}`；也支持精确instance_id、task_id，仅限制pick |
| `input_snapshots` | 原始场景缓存映射；`{}`表示从原始XML构造；不能填增强后的快照 |
| `max_pick_targets_per_house` / `max_open_targets_per_house` | `-1`：不设数量上下限，纳入所有合格目标；正整数：固定目标配额 |
| `cases` | `["Case1","Case2","Case3"]`；严格只构造单pick时用`["Case1","Case2"]` |
| `variants_per_case` | 每个pick每个增强case的变体数，通常5；最小包填1；Case3每个open仅1样本 |
| `pick_target_types` | cup、mug、wine bottle、atomizer、salt shaker、pepper shaker、soap dispenser |
| `case1_support_types` | CounterTop、Table、DiningTable、CoffeeTable、SideTable、Desk |
| `case1_added_surface_count` / `case2_added_surface_count` | `[5,8]` / `[10,20]`，均指新增支撑面物品数量；Case1另新增1把地面Chair |
| `case1_surface_categories` / `case2_surface_categories` | 允许新增的障碍物类别，与pick目标白名单不同 |
| `min_substantial` | Case2大/高障碍物最低数量，默认2 |
| `allow_surface_capacity_shortfall` / `capacity_probe_budget` | `true` / `20000`；只有合法放置候选域穷举确认容量不足才允许低于最小新增数 |
| `min_prefilter_points` / `min_final_points` | `5` / `5`：静态预筛、最终合格站位门槛 |
| `station_selection` / `max_final_stations` | `coverage` / `20`；也可用`all_valid`保留全部合格站位 |
| `min_target_separation_m` | 正配额pick默认0.75m；不限配额时仅分散排序，不因距离删除合格目标 |
| `station_config` | 站位半径、间距、图像尺寸、目标像素门槛等；默认320×240、目标至少24像素 |
| `seed` / `assets_per_category` | 随机种子 / 每类检索资产数量，默认20261012 / 6 |
| `max_candidates` / `max_physical_trials` / `variant_timeout_s` | 单变体候选预算 / 物理布局尝试数 / 时间预算，默认2400 / 12 / 1800秒 |
| `settle` / `views` | 静置参数 / 构造前后图像参数，媒体默认640×480 |

运行前选择配置文件：

```bash
CONFIG=configs/scene_datasets/val103_val104_countertop_targets_v3.json
# 最小val103/Cup_30，两case各1个：
# CONFIG=configs/scene_datasets/val103_cup30_minimal_v3.json
```

## 3. 发现 → 资格检查 → 构建

- **发现**：读取原场景，筛选符合目标类型、支撑条件及静态站位门槛的候选，保存原始基线。命令行打印每场景原始任务数、静态通过数、选中pick/open数量，以及各Case预计样本数和总数；资格检查后更新预估，最终数量以构造与物理审计为准。
- **资格检查**：实际初始化站位并检查目标可见性；Case1还检查Chair放置候选区域，淘汰不合格目标。
- **构建**：为合格目标生成增强变体、静置并检查物理合法性和最终站位；open不增强。最后自动物理审计，封存样本与目录README。

```bash
RUN="scene-v3-$(date +%Y%m%d-%H%M%S)-$$"
STATIC="outputs/diagnostics/$RUN-static.json"
QUALIFIED="outputs/diagnostics/$RUN-qualified.json"
DATASET="outputs/scene_datasets/$RUN"
bin/lastmile-dataflow discover-scene-datasets \
  --config "$CONFIG" --output "$STATIC" \
  2>&1 | tee "outputs/logs/$RUN-discover.log"
bin/lastmile-dataflow qualify-scene-datasets \
  --discovery "$STATIC" --output "$QUALIFIED" \
  2>&1 | tee "outputs/logs/$RUN-qualify.log"
bin/lastmile-dataflow build-scene-datasets \
  --config "$CONFIG" --discovery "$QUALIFIED" \
  --output-dir outputs --dataset-id "$RUN" \
  --gpu-ids "${GPUS[@]}" --workers "$WORKERS" \
  2>&1 | tee "outputs/logs/$RUN-build.log"
# 改配置后重新发现/检查；正配额允许缺目标时加 --allow-partial-targets。
```

## 4. 审计与目录交付

```bash
bin/lastmile-dataflow audit-scene-datasets "$DATASET" --physical \
  --output "outputs/diagnostics/$RUN-recheck-$(date +%Y%m%d-%H%M%S).json"
cat "$DATASET/manifest.json" # 完整交付须sealed；partial保留缺口
cat "$DATASET/timing.json"
cat "$DATASET/README.md"
ls "$DATASET" # 直接交付目录，不压缩；保留构造diagnostics供物理审计
```

# 增强场景构造运行指南

本指南统一说明 **scene_datasets 的配置、构造、审计与目录交付**。当前规则是 `scene-cases-v3`；支持全量 house 清单、指定单场景、指定单场景单 pick 目标。所有命令从本 worktree 根目录执行。

**当前真实验收范围仅 val103 / Cup_30 的 Case1、Case2 各一个样本。** 全量命令是运行方法，不表示已完成全量验收。原五阶段管线不属于本入口。

## 1. 交付范围与规则

- `scene_datasets` 保存场景、任务、编辑记录、真实图像、物理检查与冻结站位；不包含策略执行轨迹。
- 场景快照与站位包绑定机器人、传感器及物理控制配置，与 cuRobo、MolmoBot 或其它规划/策略无关。
- 下游执行 datasets、benchmarks 引用 `scene_dataset_id / sample_id / robot_sensor_config_id`；不改写封存输入，不静默重采样。
- **Case1**：pick；仅台面/桌子支撑。新增1把地面 Chair，正常新增5–8件目标支撑面物品。
- **Case2**：pick；正常新增10–20件支撑面物品，至少两件实测尺寸达标的大/高物体。
- **Case3**：open；不增强，每个合格 open 目标交付1个原场景样本；不乘以 `variants_per_case`。
- 以上数量指**新增数量**，不含目标与原有物体。
- 容量不足时可少于最小新增数，但必须证明当前声明的候选资产/点/角度离散域无合法追加姿态，静置后再次检查。预算/超时耗尽不是容量证明，也不是连续空间上的数学证明。Chair、Case2大/高物体、碰撞/支撑、最终至少5个合格站位等条件不豁免。
- pick 目标白名单：cup、mug、wine bottle、atomizer、salt shaker、pepper shaker、soap dispenser。它是用户假定高成功率范围，不是策略实测结论。`SprayBottle→atomizer`、`SoapBottle→soap dispenser`；generic Bottle、SoapBar 不自动算合格。

详细契约见 [scene-datasets-v1.md](datas/scene-datasets-v1.md)。

`val103_val104.json` 是此前 v2 配方，`configs/case_edits/procedural_obstacles_*.json` 是历史单目标诊断入口；不要用于新 v3 数量规则。

### 3.2 路径解析

- `dataset_dir / asset_library / robot_config / input_snapshots` 相对**配方文件目录**解析；`model_path` 相对**机器人配置文件目录**解析。
- 同目录生成新配方可保留原相对路径。移动配方文件时必须重新检查路径，不能仅复制到别的目录。
- 当前模板的 `input_snapshots` 引用本机旧的**原始场景**缓存。跨机器/全量生成应清空 `{}`，或逐项配置可信缓存。
- 缓存必须是未增强原场景，并且来源 XML/metadata、机器人物理配置与当前输入相同；不匹配会拒绝加载。不能用增强样本充当原始基线。
- CLI 没有 scene_datasets 专用 `--houses` / `--targets` 快捷参数；场景/目标筛选写在 JSON 配方中。

### 3.3 创建所需范围的配方

下面一次生成三个**独立配方**，不会启动构造、不会覆盖已有文件。先检查模板 `dataset_dir / asset_library / robot_config` 适配本机。

```bash
CFG_TAG="$(date +%Y%m%d-%H%M%S)-$$"
export CFG_TAG
PYTHONPATH=src "$DATAFLOW_PYTHON" - <<'PY'
import copy,json,os,re
from pathlib import Path
base=Path('configs/scene_datasets')
template=json.loads((base/'val103_val104_countertop_targets_v3.json').read_text())
tag=os.environ['CFG_TAG']
def save(name,config):
    path=base/f'{name}-{tag}.json'
    with path.open('x') as stream:
        json.dump(config,stream,ensure_ascii=False,indent=2)
        stream.write('\n')
    print(path)
# 单场景：自动选最多3个分散 pick + 1 open。
single=copy.deepcopy(template)
single.update(houses=['val103'],targets={},input_snapshots={})
save('val103-auto-v3',single)
# 单场景单目标：只构造该 pick 的两个 case，各5变体，配额10。
target=copy.deepcopy(single)
target.update(targets={'val103':['Cup_30']},max_pick_targets_per_house=1,
              cases=['Case1','Case2'],variants_per_case=5)
save('val103-cup30-v3',target)
# 全量：枚举本地 val XML+metadata 的实际可用 house，不写死1000或10000。
full=copy.deepcopy(template)
folder=(base/full['dataset_dir']).resolve()
houses=[]
for metadata in folder.glob('val_*_metadata.json'):
    match=re.fullmatch(r'val_(\d+)_metadata\.json',metadata.name)
    if match and (folder/f'val_{match[1]}.xml').is_file():
        houses.append(int(match[1]))
if not houses:
    raise SystemExit(f'没有完整 val XML/metadata 输入：{folder}')
full.update(houses=sorted(set(houses)),targets={},input_snapshots={})
save('val-all-v3',full)
print('全量实际 house 数：',len(full['houses']))
PY
```

按需要选一个配方，**不要一次启动三个范围**：

```bash
# 全量（所有本地可用 val house；每 house 仍是有限目标采样，不是全部物体）
CONFIG="configs/scene_datasets/val-all-v3-$CFG_TAG.json"
SCOPE=val-all-v3
# 指定单场景：改用下两行
# CONFIG="configs/scene_datasets/val103-auto-v3-$CFG_TAG.json"
# SCOPE=val103-auto-v3
# 指定单场景单目标、两个 case 各5变体：改用下两行
# CONFIG="configs/scene_datasets/val103-cup30-v3-$CFG_TAG.json"
# SCOPE=val103-cup30-v3
# 单目标最小2样本：直接使用已真实验收的配方
# CONFIG=configs/scene_datasets/val103_cup30_minimal_v3.json
# SCOPE=val103-cup30-minimal-v3
export CONFIG
```

换 house：同时修改 `houses` 与 `targets` 的键；例如 `houses:["val104"]`。支持103、`val103`、`val_103`三种 house 表示。
`targets` 只限制 **pick**，可使用 asset_id、精确 instance_id 或 task_id。asset_id 可能匹配多个实例；要求唯一对象时使用 instance_id。它不取消其它硬规则，不保证目标一定合格。
只要包含 Case3，仍会独立选择 open；所以“严格只要单个 pick”必须使用 `cases:["Case1","Case2"]`。

### 3.4 配方字段与默认值

默认值以当前 [SceneDatasetRecipe](../src/lastmile_dataflow/construction/scene_dataset_config.py) 为准。**类的默认 rule_version 仍为v2；新配方必须显式写 v3，不能省略。**

| 字段 | 默认/要求 | 含义 |
|---|---|---|
| `schema_version / rule_version` | recipe-v1 / 新任务显式 scene-cases-v3 | 配方与构造规则版本 |
| `dataset_dir / asset_library / robot_config` | 必填 | 原场景、编辑资产、机器人配置路径 |
| `houses` | 必填、非空、唯一 | 显式范围；没有隐式全量扫描 |
| `targets / input_snapshots / categories` | `{}` / `{}` / `[]` | pick选择器、原场景缓存、原始任务category额外限制（影响pick与open） |
| `pick_target_types` | v3显式七类白名单或其非空子集 | 语义目标筛选；不是障碍物类别 |
| `case1_support_types` | CounterTop、Table、DiningTable、CoffeeTable、SideTable、Desk | 必须来自允许集合；不含Bed、Shelf、Dresser、Stand |
| `cases` | Case1、Case2、Case3 | 不同任务操作对应不同 case |
| `variants_per_case` | 5 | 每个pick每个增强case的变体数；不影响Case3 |
| `max_pick_targets_per_house / max_open_targets_per_house` | 3 / 1 | 不只是上限，也是构建的期望配额；不能设0，去掉相应case表示不需要该任务 |
| `min_target_separation_m` | 0.75 m | pick目标分散选择：优先不同房间/支撑，再最大化间距 |
| `min_prefilter_points / min_final_points` | 5 / 5 | 静态预筛与实际可见站位门槛 |
| `station_selection / max_final_stations` | coverage / 20 | 从合格站位覆盖选取；all_valid表示保留全部合格点 |
| `station_config` | `{}` | 站位几何、传感器图像尺寸与可见性配置，见下表 |
| `case1_added_surface_count / case2_added_surface_count` | [5,8] / [10,20] | 可缩窄区间，不能超出版本允许范围；不含Chair |
| `allow_surface_capacity_shortfall / capacity_probe_budget` | false / 20000 | v3模板显式true；容量探测预算，未穷举不能提前成功 |
| `assets_per_category` | 6 | 每种编辑资产类别检索数量；容量域依赖实际检索池 |
| `case1_surface_categories` | Bowl、Cup、Mug、Bottle、Plate | Case1允许新增的支撑面障碍物类别 |
| `case2_surface_categories` | Bowl、Cup、Mug、Bottle、SaltShaker、Kettle、CoffeeMachine、Vase | Case2障碍物类别；不受pick七类限制 |
| `min_substantial` | 2 | Case2实测大/高物体数最低要求 |
| `seed` | 20261012 | 选择与构造可追溯随机种子 |
| `max_candidates / max_physical_trials / variant_timeout_s` | 2400 / 12 / 1800 s | 单变体搜索、物理布局尝试与时间预算；不是降低验收标准的开关 |
| `settle` | require_source_stability:false | 构造静置参数；物理验收仍包含源物体等时长对照 |
| `views` | width:640、height:480 | 配对构造前后媒体图像尺寸，不等于站位相机尺寸 |

`station_config` 默认值：

| 字段 | 默认 |
|---|---|
| `radius_m / spacing_m` | 0.7928056080178096 / 0.1108796040001314 m |
| `width / height / min_target_pixels` | 320 / 240 / 24像素 |
| `map_resolution_m / navigation_margin_m` | 0.05 / 0.02 m |
| `operations` | [pick,open]；应覆盖请求case对应操作 |
| `gripper_width_m` | 0.10 m |
| `open_fraction / open_hinge_rad / open_slide_m` | 0.3 / π/6 rad / 0.10 m |

`station_config.seed` 会被配方顶层 seed 覆盖。更改机器人、相机分辨率、站位几何或物理控制配置会改变包的绑定，必须重新构建/资格检查，不能与旧包混用。
当前 `rby1_position_head320.json` 的 `model_path` 指向外部机器人XML，控制 profile position-v1、20Hz、physics_dt=0.004s，声明 head/wrist三相机。320×240由站位配置默认提供，不是文件名自动生效。

## 4. 统一运行：发现 → 实际资格检查 → 构造 → 审计

### 4.1 配置与路径预检（不构造）

```bash
PYTHONPATH=src "$DATAFLOW_PYTHON" - <<'PY'
import os
from pathlib import Path
from lastmile_dataflow.construction.scene_dataset_config import load_scene_recipe,load_scene_robot
recipe=load_scene_recipe(os.environ['CONFIG'])
robot=load_scene_robot(recipe.robot_config)
for name,value in [('dataset_dir',recipe.dataset_dir),('asset_library',recipe.asset_library),
                   ('robot_config',recipe.robot_config),('model_path',robot.model_path)]:
    if not Path(value).exists():
        raise SystemExit(f'缺少 {name}: {value}')
for house in recipe.houses:
    for suffix in ('.xml','_metadata.json'):
        path=Path(recipe.dataset_dir)/f'val_{house}{suffix}'
        if not path.is_file(): raise SystemExit(f'缺少原始场景：{path}')
print('rule:',recipe.rule_version,'houses:',len(recipe.houses),'cases:',recipe.cases)
print('pick selectors:',recipe.targets,'station geometry:',recipe.geometry)
PY
```

### 4.2 创建唯一运行标识并发现目标

```bash
RUN="scene-$SCOPE-$(date +%Y%m%d-%H%M%S)-$$"
STATIC="outputs/diagnostics/$RUN-static.json"
QUALIFIED="outputs/diagnostics/$RUN-qualified.json"
DATASET="outputs/scene_datasets/$RUN"
bin/lastmile-dataflow discover-scene-datasets \
  --config "$CONFIG" --output "$STATIC" \
  2>&1 | tee "outputs/logs/$RUN-discover.log"
```

此步冻结原始基线到 `$RUN-static-baselines/val_<house>/scene`，做语义、支撑与静态站位预筛。静态可行数采用达到门槛即停止的下界，不能当作完整可见站位数。

全量前先检查每 house 是否有初选目标：

```bash
"$DATAFLOW_PYTHON" - "$STATIC" <<'PY'
import json,sys
plan=json.load(open(sys.argv[1]))
for row in plan['houses']:
    print('val',row['house'],'eligible pick/open',row['eligible_pick'],row['eligible_open'],
          'selected pick/open',row['selected_pick'],row['selected_open'])
empty=[r['house'] for r in plan['houses']
       if not any(s['house']==r['house'] for s in plan['selected'])]
if empty:
    raise SystemExit(f'无初选目标的house：{empty}；不能直接进入当前 qualify 入口')
PY
```

**当前限制**：qualify 对每个house取一个已选目标作为基线入口；该house完全无初选目标时会报错。全量配置不能保证每house有合格目标。需保留发现/排除证据，给可运行子集生成新配置并重新发现，记录未覆盖house；不要将子集包装成全量完成。建议先单场景 smoke，再按显式 house 分片运行；当前没有自动全量分片/聚合命令。

### 4.3 实际目标资格检查（不可跳过）

```bash
bin/lastmile-dataflow qualify-scene-datasets \
  --discovery "$STATIC" --output "$QUALIFIED" \
  2>&1 | tee "outputs/logs/$RUN-qualify.log"
```

资格检查执行独立站位初始化、真实相机目标可见性；不合格初选可被其它静态合格且空间分散的候选替换。Case1还要求存在实测近地面Chair候选点。没有足够目标时保留缺口，不放宽物理/语义规则。
检查 `$QUALIFIED` 的 houses、selected、qualification、exclusions 后再构建；不要修改冻结发现JSON凑配额。

### 4.4 并行构造与最终封存

```bash
bin/lastmile-dataflow build-scene-datasets \
  --config "$CONFIG" --discovery "$QUALIFIED" \
  --output-dir outputs --dataset-id "$RUN" \
  --gpu-ids "${GPUS[@]}" --workers "$WORKERS" \
  2>&1 | tee "outputs/logs/$RUN-build.log"
```

`--output-dir outputs` 指的是统一输出根，不是 `outputs/scene_datasets`，否则会多嵌套一层。
完整资格配额：每 house 的样本数 = `pick配额 × variants_per_case × 已请求pick case数 + open配额（请求Case3时）`。默认31/house；单目标Case1+Case2各5为10；最小各1为2。
实际构造可能因物理/可见性/唯一布局预算不足而少于配额。构建末尾自动做物理审计：`sealed` 才是完整通过；`partial` 有显式 missing_samples，不能当作完整交付。CLI 对非sealed退出码为1，即使已留下一些合格样本。

如果明确批准只交付当前合格目标子集，可在构造命令增加 `--allow-partial-targets`。它只放行目标配额缺口，保留原 expected_samples，不降低样本硬规则；不是“全量成功”开关，也不能解决完全无目标house的 qualify 入口限制。

### 4.5 只读复查

```bash
# 身份、校验和、包绑定/站位及媒体检查
bin/lastmile-dataflow audit-scene-datasets "$DATASET" \
  --output "outputs/diagnostics/$RUN-recheck.json"
# 额外重载冻结模型、支撑/碰撞/case与源物体对照检查
bin/lastmile-dataflow audit-scene-datasets "$DATASET" --physical \
  --output "outputs/diagnostics/$RUN-physical-recheck.json"
```

物理审计不运行策略，不证明导航/抓取。普通默认审计需要增强配置所在构造诊断目录；含容量证书的样本还需原基线与候选资产来穷举重放，交付/备份时不能忽略这些依赖。

```bash
bin/lastmile-dataflow audit-scene-datasets \
  outputs/scene_datasets/scene-val103-cup30-minimal-v3-20261012-r2 \
  --physical \
  --audit-inputs outputs/scene_datasets/releases/scene-val103-cup30-minimal-v3-20261012-r2-companion/audit_inputs \
  --output "outputs/diagnostics/cup30-portable-recheck-$(date +%Y%m%d-%H%M%S)-$$.json"

当前没有自动通用 companion 导出CLI；不要将该最小包 companion 套到别的 dataset。容量证书完整重放的迁移依赖还未统一打包。

## 5. 目录交付、状态与构造时间

└── logs/<run>*.log                 唯一运行日志入口
```

- 以 `manifest.status` 判断 sealed / partial / audit_failed；progress是构建过程检查点，可能仍标running，不能覆盖manifest结论。
- 发现/资格检查JSON保存时间与耗时。根 timing 保存 discovery_wall_s、并行 wall_s、unit_wall_sum_s 和各单元时间；样本 construction/timing 保存变体、静置、对照、媒体、站位耗时。
- 并行 wall_s 不包含构建末尾审计/报告/打包，不等于单元时间之和；变体耗时不包含共享基线和资产检索。续跑会产生新的本次调用墙钟，不是跨所有调用的累计总耗时。
- sealed场景/状态/索引/检查结果只读；下游结果写新目录。本次最小包README为封存后追加说明，未改写原封存文件；后续新构建README自动纳入校验。

## 6. 失败、停止与有限续跑

| 现象 | 处理 |
|---|---|
| 路径/缓存身份不匹配 | 检查配方相对路径、原始输入摘要及机器人配置；不能修改旧摘要绕过检查 |
| 目标不在白名单/支撑不合格/站位不足/Chair无候选区域 | 保留排除记录；改目标/house并创建新配置、新run，不降低规则 |
| 容量probe预算耗尽 | 结论是不确定；可新run增加预算，不允许伪装容量已满 |
| EGL/NVML错误 | 检查运行权限、驱动与空闲GPU；不是样本物理失败 |
| FileExistsError | 新run/新发现输出；不得覆盖旧结果 |
| 缺目标配额 | 获批准后partial交付，或新范围重跑；记录缺口 |
| 物理审计失败 | 保留失败证据；不得改标签封存 |

前台 Ctrl+C 让构建父进程清理worker。停止后检查有无该 dataset 的父进程/单元进程；不要用不限定run的 `pkill` 杀其它任务。

```bash
ps -eo pid,args | grep -E 'build-scene-datasets|scene-dataset-unit' | grep -v grep || true
```

`--resume` **不是任意中断恢复**。必须保持相同配置路径与内容、资格发现输入、dataset-id、output-dir与partial选项。它复用有 result.json 的单元；存在已开始却没有result的诊断单元，会要求新dataset-id，以保留证据。失败result也不会自动重做。已sealed且审计通过的相同输入直接返回原目录。

```bash
# 仅在满足上面条件时运行；不是保证任意中断可恢复。
bin/lastmile-dataflow build-scene-datasets \
  --config "$CONFIG" --discovery "$QUALIFIED" \
  --output-dir outputs --dataset-id "$RUN" \
  --gpu-ids "${GPUS[@]}" --workers "$WORKERS" --resume \
  2>&1 | tee "outputs/logs/$RUN-resume-$(date +%Y%m%d-%H%M%S).log"
```

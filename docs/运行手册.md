# 运行手册

先完成 [安装与数据准备](setup.md)。从仓库根目录使用 `.venv/bin/lastmile-dataflow`；以下每次运行都要换新的 run 名称或输出目录。
GPU 按实时利用率和空闲显存选择，不使用固定服务器卡号。

## 0. 配置本机公共路径

首次运行时复制并修改：

```bash
cp configs/local.example.json configs/local.json
```

本机配置示例：

```json
{
  "assets_dir": "/home/wenyifan/wenyifan/MoMaTrajGen/molmospaces_data/assets",
  "output_dir": "outputs"
}
```

五个命令默认读取仓库中的 `configs/local.json`；该文件不提交到 Git。
配置路径相对仓库根目录，也可填绝对路径。显式 `--assets-dir` / `--output-dir` 优先；CLI 路径仍相对调用目录。

## 1. 构建场景库

```bash
GPU=<chosen-index>
.venv/bin/lastmile-dataflow build-scenes \
  --config configs/scene_datasets/val103_cup30_minimal_v3.json \
  --run-id small --gpu "$GPU"
```

输出为 `outputs/scene_datasets/small`。配置里的路径必须先按本机数据位置调整。
命令内部依次发现任务、筛选有效站位、构建并保存场景。pick 使用障碍物增强；open 保存对应任务场景。

场景增强保留数量范围、碰撞、支撑、静置、源场景影响与最终站位检查。放不下就记 rejected，不降低数量下限。
独立增强研究可调用 `workflows.obstacle_augmentation.augment_obstacles()`；不另建重复 CLI。
场景资格通过不等于机器人任务成功，站位几何过滤也不是逐点实测。

## 2. 逐点标定

```bash
.venv/bin/lastmile-dataflow evaluate-stations \
  --dataset outputs/scene_datasets/small \
  --config configs/execution/curobo_v2.json \
  --output-dir outputs/station_evaluations/small \
  --run-id curobo_v2_001 --gpu "$GPU"
```

- 输出 run 为 `outputs/station_evaluations/small/curobo_v2_001`，包含原始 `trials.jsonl`、rollout 和展示热图，不执行连续恢复采集。
- 每场景仅输出一张带站位号的 `figures/<scene-id>/success_heatmap_stations.svg`；数值热图与参数仍保存在 `success_heatmap.npz`、`heatmap.json`，
- 用 `--samples <scene-id> ...` 选择场景；`--max-trials <n>` 限制每场景标定预算。不完整的标定不能用于正式配对。
- 图像默认保留；`--record-video`、`--record-depth`、`--record-physics` 按需开启额外记录。

### 使用 MolmoBot 标定

将逐点命令的执行配置换为 `configs/execution/molmobot.json`，并准备 `configs/policies/molmobot.json` 指向的本地权重。
输入场景必须使用匹配的 **native motor 控制、相机与初始化站位**；不能把 position 场景直接交给策略，也不能只换 backend 字段。
运行前核对保存的机器人配置；native 转换入口为 `runtime.construction.benchmark_scene.native_scene()`，转换后需检查站位初始化与可见性。

pick 默认连续夹爪，open 默认二值夹爪；这是实际控制语义，不是两个任务共用同一动作解释。改变控制或相机配置后重新标定。
模型只接收观测和任务，不把成功率图提供给策略。

## 3. lastmile-datasets 生成

### 3.1 生成引用型数据集

```bash
.venv/bin/lastmile-dataflow collect-lastmile \
  --dataset outputs/scene_datasets/small \
  --config configs/execution/curobo_v2.json \
  --calibration outputs/station_evaluations/small/curobo_v2_001 \
  --output-dir outputs/lastmile_datasets/small \
  --run-id lastmile --gpu "$GPU"
```

- `--calibration` 指向具体标定 run，而非父目录；物理执行配置和 profile 必须匹配，选点阈值和展示参数可独立调整。省略时在当前 run 内标定一次。
- `rate <= lastmile_low` 的全部 S0 与 `rate >= lastmile_high` 的全部 S1 全组合配对。距离、`start_count` 和 `max_s1_candidates` 不截断配对；远目标和无路径 pair 均保留。
- 每个 pair 新建独立 attempt，A* 导航到 S1 后操作，不中途重置或传送。当前连续执行仅支持 cuRobo。
- `pair_index.jsonl` 保存完整计划和真实结果；`train_index.jsonl` 包含两类成功且记录完整的轨迹：所有站位的已有成功标定操作（`s1_direct_operation`）与新成功连续执行（`s0_to_s1_continuous`）。前者没有导航字段，不重新执行。
- 引用型结果仍依赖原标定目录；无 S0 时也可以包含已有成功操作。无路径、失败、未知和不完整记录不进入训练视图。

### 3.2 独立物化：复制为自包含数据集

```bash
.venv/bin/lastmile-dataflow collect-lastmile \
  --materialize-from outputs/lastmile_datasets/small/lastmile \
  --output-dir outputs/lastmile_datasets/small \
  --run-id lastmile_materialized
```

此步骤只做 CPU 文件处理，无需 `--gpu`、资产或模型；不重跑标定、规划或采集。必须使用新输出目录。
训练索引引用的两类成功轨迹、必要 RGB/已启用的深度、录制和控制元数据被复制到内部 `rollouts/`。
同一来源 attempt 只复制一次；`source` 保留历史来源，`rollout_path` 使用内部相对路径。完整 pair 结果保留，未入训练集的失败轨迹不复制。
缺少必需文件时抛出错误并留下 `incomplete` 汇总，不静默删样本。物化完成后可整体复制目录，不依赖原标定或采集 run。

### 3.3 读取训练 batch

有成功样本时，从物化目录读取一个真实控制间隔：

```bash
.venv/bin/python - <<'PY'
from lastmile_dataflow.data.export.lastmile_dataset import load_training_batch
batch = load_training_batch("outputs/lastmile_datasets/small/lastmile_materialized", [0], steps=1)
print(batch["state22"].shape, batch["actions"].shape)
print({camera: rgb.shape for camera, rgb in batch["images"].items()})
PY
```

读取器返回等长 NumPy 窗口：22D state、原始 20D actions、phases、时间、相机观测和任务信息；不补帧、不 padding。`start` / `steps` 不得超过实际动作长度。
这是原始控制格式，不是完整 MolmoBot 上游训练格式；非原生夹爪动作转换仍需显式标定。成功 batch 读取不证明模型训练效果或仿真重放可用。

## 4. 困难 S0 benchmark

```bash
.venv/bin/lastmile-dataflow build-bench \
  --dataset <existing-scene-dataset> --calibration <existing-curobo-calibration> \
  --config configs/benchmark/v0.1.json --output <new-bench-dir>

.venv/bin/lastmile-dataflow evaluate-bench \
  --benchmark <bench-dir> --output <new-evaluation-dir> \
  --policy-config configs/policies/molmobot.json --gpu "$GPU"
```

构建直接读取已有 cuRobo 标定，允许标定过程中底盘移动；成功率归属 trial 的初始站位。沿用原标定次数，不重跑标定、不转换构建场景，不要求 GPU 或策略配置。
低率起点 ≤20%，同对象同任务高率站位 ≥60%；保留有合法整机保守导航路径的全部 S0。区域半径、yaw 容差及抽样参数见 [benchmark 配置](../configs/benchmark/README.md)。
`episodes.jsonl` 是执行计划；`oracle.json` 保存隐藏区域、路径和难度；`summary.json` 说明数量及排除原因。空 benchmark 保留负结果，不运行评测；未标定 smoke 不再作为正式构建入口。
评测目前只支持 RBY-1/MolmoBot，必要的 native 转换在评测初始化阶段进行。Panda 可构建 bench，尚无对应 VLA 接口，评测记 `unsupported_policy`，不伪造 rollout 或任务失败。
详细步骤见 [benchmark 指南](../reports/benchmark/docs/运行指南.md)。

## 5. 如何理解结果

- 导航到达、操作成功、记录完整分别给结论；程序退出码 0 不代表任务成功。
- pick 判定需要真实双指承力、抬升、无支撑保持及滑移约束；open 根据实际关节进展与接触保持判定。
- 初始化、仿真、记录和共享模型/GPU 错误不当作普通任务失败；共享故障后停止当前批次。
- 未完成试验不补入成功率分母；benchmark 同时报告覆盖率与完整计划集合的成功率，unknown 存在时不提供完整成功率。
- 实际执行开始后不传送、重置或恢复快照；独立试验创建新的仿真与 attempt。

文件布局和控制维度见 [数据格式](data-format.md)，显式真实验证入口见 [测试说明](../tests/README.md)。

# 运行手册

先完成 [安装与数据准备](setup.md)。从仓库根目录使用 `.venv/bin/lastmile-dataflow`；以下每次运行都要换新的 run 名称或输出目录。
GPU 按实时利用率和空闲显存选择，不使用固定服务器卡号。

## 0. 配置本机公共路径

首次运行时复制并修改：

```bash
cp configs/local.example.json configs/local.json
```

本机配置示例（数据放在大数据盘，不使用仓库内 `data/`）：

```json
{
  "assets_dir": "/data1/molmospaces_data/assets",
  "output_dir": "/data1/molmospaces_data/outputs"
}
```

五个命令默认读取仓库中的 `configs/local.json`；该文件不提交到 Git。
配置路径相对仓库根目录，也可填绝对路径。显式 `--assets-dir` / `--output-dir` 优先；CLI 路径仍相对调用目录。

## 1. 构建场景库

```bash
GPU=<chosen-index>
.venv/bin/lastmile-dataflow build-scenes \
  --config configs/task_modes/panda_omron_task_modes.json \
  --run-id small --gpu "$GPU"
```

输出为 `outputs/scene_datasets/small`。配置里的路径必须先按本机数据位置调整。
先按 [task_modes 配置说明](../configs/task_modes/README.md) 生成离线索引并调整数据路径、houses 和目标数。当前公开构建仅接受 v2 Panda RoboCasa 配方，旧 Case JSON 已退出。需要并行时加 `--build-workers 2`；GPU 可传多个编号。

每个任务共用一次停车、静置和几何准备，遍历八类候选模式。放不下、无对照或代理不满足则记 rejected；Articulated 对 Pick 记 skipped。输出最多 20 个真实初始化合法姿态，含同 XY 的 yaw 对照。

accepted 只表示候选构建通过。最终困难模式需要三次原始 trial、S0/S1 和诊断证据；诊断与下游多标签已接通，完整真实标定仍待验证，不能将 proposal_intent 当最终类别。

## 2. 底盘可达质量图

`evaluate-stations` 只构建静态的 SE(2) 底盘可达质量图，不执行物理试抓：目标物体固定，底盘、升降和夹爪锁定，每个 `(站位, grasp)` 用 cuRobo 求七关节手臂 IK（32 seeds，全部返回），MuJoCo 复核 FK 与接触，再对每个有效构型计算扩展可操作度并取最大值。需求与方案见 [base-map 需求](../reports/base-map/requirement/01-base-irm.md) 和 [实施方案](../reports/base-map/plan/01-base-map-implementation.md)。

```bash
.venv/bin/lastmile-dataflow evaluate-stations \
  --recipe configs/scene_datasets/panda_omron_val103_cup30_base_map.json \
  --config configs/execution/panda_omron_base_map.json \
  --output-dir outputs/experiments/<unit>/runs --run-id full --gpu <空闲 GPU>
```

- `--recipe` 读取 `base-map-scene-v1` 场景文件（源场景 XML、metadata、目标 asset/object id、参考站位、升降与夹爪）；`--dataset` 读取已有场景库快照，只用其场景和 pick 目标，不复用其站位。首版只验收 Panda-Omron。
- 采样：以物体碰撞包围盒中心为原点的 10 cm 网格，覆盖每个 grasp 的臂展圆；每个位置朝向物体 ±60°、每 15° 一个，共 9 个朝向。`region_m` 可裁剪试跑区域，默认全范围。
- 过滤：无地面、底盘（车体、立柱、link0）与环境碰撞、肩枢轴到 TCP 超出臂展上界的查询不做 IK，不计入 IK 有效率分母。
- 热启动只取已完成行的邻点有效解，占 32 seeds 中最多 8 个；同一行内的站位不互相提供初值，结果与评分进程完成顺序无关。
- 评分在 CPU 多进程（`scoring_workers`，或 `--scoring-workers` 覆盖）中进行；GPU 只做 IK。本命令不渲染，不需要 EGL。
- 输出 `<run>/<scene-id>/`：`scene.json`（grasp、网格、几何常量）、`candidates-NNNN.npz`（每个查询的 32 个候选及原因）、`map.npz`、`summary.json`。计算命令不出图。字段见 [数据格式](data-format.md#底盘可达质量图-run)。
- 出图是第二个命令，只读已保存的数组，不求 IK、不评分、不需要 GPU：

  ```bash
  .venv/bin/lastmile-dataflow evaluate-stations --plot-from outputs/experiments/<unit>/runs/full \
    --output-dir outputs/experiments/<unit>/analysis --run-id full-figures
  ```

  每个场景得到逐 grasp 的站位质量图 `base-quality-g{k}.png`（同一位置各有效朝向质量的平均值）、朝向箭头图 `heading-quality-g{k}.png`（每个有效朝向一支箭头，颜色为该朝向质量）、IK 有效率图、grasp 预览和离线 `base-quality.html`。加 `--render-examples --gpu <n>` 另渲染高/中/低质量构型，需要可用的 EGL（pro5000 见附录）。
- 质量只来自扩展可操作度；IK 有效率单独保存，不进分数、颜色或排序。质量图不是抓取成功率，不能当成物理标定交给 `build-bench`。

### 逐点物理标定（collect-lastmile 内置）

物理试抓只在 `collect-lastmile` 中运行：未传 `--calibration` 时先对场景库的全部站位逐点标定，写 `trials.jsonl`，再生成并执行 S0×S1 计划；传入已有标定 run（旧的 `evaluate-stations` run 或此前的 `collect-lastmile` run）时直接复用。`--max-trials`、`--station-workers`、`--cpu-workers`、`--preparation-workers`、`--recording-mode`、`--no-planner-reuse` 等标定参数都在 `collect-lastmile` 上。连续采集与内置标定只支持 cuRobo；MolmoBot / π0.5 不再有逐点标定入口，策略评测走 `evaluate-bench`。

默认一个进程；同站位、同手臂、相同冻结初态的闭爪前 planner 默认复用。每个 trial 仍新建仿真、使用原 seed 并重新规划。共享 GPU/模型故障停止新 trial 和新站位派发，已在执行的 trial 自然收尾；不完整的标定不能用于正式配对。逐物理步判定和接触统计保持 4 ms；关闭 `--record-physics` 时省去完整接触文本与 JSON 序列化，仍保留任务事实和最多 32 条接触示例。

## 3. lastmile-datasets 生成

本轮任务模式交付按用户要求止于完整标定；本节及 benchmark 步骤保留供后续使用，暂不继续执行。

### 3.1 生成引用型数据集

```bash
.venv/bin/lastmile-dataflow collect-lastmile \
  --dataset outputs/scene_datasets/small \
  --config configs/task_modes/panda_omron_calibration.json \
  --calibration outputs/station_evaluations/small/curobo_v2_001 \
  --output-dir outputs/lastmile_datasets/small \
  --run-id lastmile --gpu "$GPU"
```

- `--calibration` 指向具体标定 run；执行配置和 profile 必须匹配。模式采集只选 train，复用原 mode_settings 和 diagnosis.jsonl；省略时在当前 run 内标定并诊断一次。
- 模式数据按诊断中每标签同 tier 的 qualifying_s1_ids 配对；同一 S0/S1 合并标签，只执行一次，Visibility-only 可独立入链。普通非模式数据沿用 lastmile_low / lastmile_high 全组合。距离和候选数不截断配对，无路径 pair 保留。
- 每个 pair 新建独立 attempt，A* 导航到 S1 后操作，不中途重置或传送。当前连续执行仅支持 cuRobo。
- 采样默认 1 m / 0.25 m；操作范围使用 execution 的 `radius_m`。导航使用完整房间地面，可绕出采样圆；用于连续采集或 benchmark 的场景配方设 `local_task_models=false`，删除过物体的局部快照需重新构建。
- 导航统一搜索站位连接和房间 XY/yaw 状态，执行器跟踪明确朝向。`navigation_margin_m=0.02` 仅为软净空目标，低于该值不再排除；`navigation_clearance_weight=2.0` 控制惩罚，`navigation_max_penetration_m=0.005` 独立控制严重碰撞判停。规划原因读 `navigation_planning` 或 benchmark summary 的 `navigation_diagnostics`。
- `pair_index.jsonl` 保存完整计划和真实结果；`train_index.jsonl` 包含两类成功且记录完整的轨迹：所有站位的已有成功标定操作（`s1_direct_operation`）与新成功连续执行（`s0_to_s1_continuous`）。前者没有导航字段，不重新执行。
- 引用型结果仍依赖原标定目录；无 S0 时也可以包含已有成功操作。数值成功轨迹需 replay_complete，按每个实测边界生成 observations/ 相机观测后入训练视图，不新增物理步或改写原 trial。失败、未知和不完整记录不进入训练视图。

### 3.2 独立物化：复制为自包含数据集

```bash
.venv/bin/lastmile-dataflow collect-lastmile \
  --materialize-from outputs/lastmile_datasets/small/lastmile \
  --output-dir outputs/lastmile_datasets/small \
  --run-id lastmile_materialized
```

此步骤只做 CPU 文件处理，无需 `--gpu`、资产或模型；不重跑标定、规划或采集。必须使用新输出目录。
训练索引引用的两类成功轨迹、必要 RGB/已启用的深度、录制和控制元数据被复制到内部 `rollouts/`。
同一来源 attempt 只复制一次；`source` 保留历史来源，`rollout_path` 使用内部相对路径。完整 pair 结果保留，未入训练集的失败轨迹不复制。
缺少必需文件时抛出错误并留下 `incomplete` 汇总，不静默删样本。物化完成后可整体复制目录，不依赖原标定或采集 run。

### 3.3 读取训练 batch

有成功样本时，从物化目录读取一个真实控制间隔：

```bash
.venv/bin/python - <<'PY'
from lastmile_dataflow.data.export.lastmile_dataset import load_training_batch
batch = load_training_batch("outputs/lastmile_datasets/small/lastmile_materialized", [0], steps=1)
print(batch["state"].shape, batch["actions"].shape)  # Panda RoboCasa
print({camera: rgb.shape for camera, rgb in batch["images"].items()})
PY
```

读取器按本体布局返回等长 NumPy 窗口：Panda RoboCasa 为 `state`（16D）与 12D actions，RBY-1 为 `state22`（22D）与 20D actions；另含 phases、时间、相机观测和任务信息。不补帧、不 padding。`start` / `steps` 不得超过实际动作长度。
这是原始控制格式，不是完整 MolmoBot 上游训练格式；非原生夹爪动作转换仍需显式标定。成功 batch 读取不证明模型训练效果或仿真重放可用。

## 4. 困难 S0 benchmark

```bash
.venv/bin/lastmile-dataflow build-bench \
  --dataset <existing-scene-dataset> --calibration <existing-curobo-calibration> \
  --config configs/benchmark/v0.1.json --output <new-bench-dir>

.venv/bin/lastmile-dataflow evaluate-bench \
  --benchmark <bench-dir> --output <new-evaluation-dir> \
  --policy-config configs/policies/molmobot.json --gpu "$GPU"
```

构建直接读取已有 cuRobo 标定，允许标定过程中底盘移动；成功率归属 trial 的初始站位。沿用原标定次数，不重跑标定、不转换构建场景，不要求 GPU 或策略配置。
模式数据只选 val 并消费已保存标签：一个 S0 一个 episode，恢复区域仅使用该起点各标签合格 S1 的并集。标签和 S1 只存私有 oracle，不发给策略。普通非模式数据沿用 ≤20% 起点、≥60% 恢复站位。保留合法导航路径。区域半径、yaw 容差及抽样参数见 [benchmark 配置](../configs/benchmark/README.md)。
`episodes.jsonl` 是执行计划；`oracle.json` 保存隐藏区域、路径和难度；`summary.json` 说明数量及排除原因。空 benchmark 保留负结果，不运行评测；未标定 smoke 不再作为正式构建入口。
模式统计总体按唯一 episode 计数，标签组允许重叠；同时报告完整计划成功率、coverage、unknown 与基础设施错误。
Panda RoboCasa 评测使用 `--policy-config configs/policies/pi05_panda_omron.json`，需先准备 π0.5 环境和权重。RBY-1/MolmoBot 的 native 转换在评测初始化阶段进行。策略与本体不匹配记 unsupported_policy，不伪造 rollout 或任务失败；新模式链的真实策略结果尚未验证。
构建后打开 `<bench-dir>/visualization/<episode_id>.png` 查看静态地图；评测后打开 `<evaluation-dir>/visualization/<episode_id>.png` 查看实际轨迹、结果和 head / 第三人称最终帧。两个完整 MP4 保存在 rollout 的 `videos/` 中。评测不回写构建目录。

详细步骤见 [benchmark 指南](../reports/benchmark/docs/运行指南.md)。

## 5. 如何理解结果

- 导航到达、操作成功、记录完整分别给结论；程序退出码 0 不代表任务成功。
- pick 判定需要真实双指承力、抬升、无支撑保持及滑移约束；open 根据实际关节进展与接触保持判定。
- 初始化、仿真、记录和共享模型/GPU 错误不当作普通任务失败；共享故障后停止当前批次。
- 未完成试验不补入成功率分母；benchmark 同时报告覆盖率与完整计划集合的成功率，unknown 存在时不提供完整成功率。
- 实际执行开始后不传送、重置或恢复快照；独立试验创建新的仿真与 attempt。

文件布局和控制维度见 [数据格式](data-format.md)，显式真实验证入口见 [测试说明](../tests/README.md)。

## 附录：pro5000本机差异（无系统 EGL）

- **系统缺 libglvnd/libegl**：本机已有 `/data1/wenyifan/opt/lib`，运行前设置：

  ```bash
  export LD_LIBRARY_PATH=/data1/wenyifan/opt/lib
  export MUJOCO_GL=egl MUJOCO_EGL_DEVICE_ID=<空闲 GPU 编号>
  export __EGL_VENDOR_LIBRARY_FILENAMES=/usr/share/glvnd/egl_vendor.d/10_nvidia.json
  ```

  `MUJOCO_EGL_DEVICE_ID` 是 EGL 设备索引，不等于物理 GPU 编号；缺 `__EGL_VENDOR_LIBRARY_FILENAMES` 时渲染会返回全黑图像。

- PyPI 镜像已写入 `~/.config/pip/pip.conf` 和 `~/.config/uv/uv.toml`（阿里云）。

## Panda 数值标定与离线回放

双池与回放入口已接通；正式 Panda 实验在软件回归后按执行计划运行。Panda 执行配置已设每点 3 次，内置标定默认不保存在线 RGB；其后的连续采集保留视觉采集。

构建进程数使用 `build-scenes --build-workers 4`，支持 1–12；首次与最终配方分别为 `configs/scene_datasets/panda_omron_val103.json`、`configs/scene_datasets/panda_omron_val100.json`。最终配方固定 val0–val99、三类 Case；使用 `--allow-partial-targets` 保留无合格目标的来源。

已有数值 run 的指定 rollout 可离线生成视频，输出 run-id 使用新值。以下从本 worktree 根目录运行；GPU 按实时占用选择：

```bash
export LD_LIBRARY_PATH=/data1/wenyifan/opt/lib:${LD_LIBRARY_PATH:-}
MUJOCO_GL=egl .venv/bin/lastmile-dataflow collect-lastmile \
  --replay-from outputs/my-run \
  --rollouts r000000 r000001 --replay-camera front_camera \
  --output-dir outputs --run-id my-replay --gpu 0
```

相机别名从 rollout 的 `recording.json` 读取。输出在 `outputs/replays/my-replay/`。无实际执行步的 trial 不生成执行视频，缺少固定模型或完整状态时先修复源记录问题；不重跑任务补视频或改写成败。

三相机 + 俯视底盘轨迹使用 `--replay-layout grid`，不需要 `--replay-camera`：

```bash
MUJOCO_GL=egl .venv/bin/lastmile-dataflow collect-lastmile \
  --replay-from outputs/my-run \
  --rollouts r000000 --replay-layout grid \
  --output-dir outputs --run-id my-grid --gpu 0
```

输出 `replays/my-grid/r000000/grid.mp4`：左上/右上为左右目，左下为腕部，右下为以 S1 为中心的俯视面板（目标 T、站位 S1、底盘足迹与实走轨迹）。标定轨迹是 S1 直接操作，没有 S0→S1 的 A* 路径；俯视只画实测底盘轨迹。`video.json` 保存帧索引、播放时间和相机列表。

### Panda 双池资源

Panda 的 `shared_station_preparation=true` 启用公共准备与全局标定双池。所选 GPU 各运行一个常驻规划进程，CPU trial 数独立配置，最多 60；旧 `--station-workers` 保留给其他执行配置。

```bash
# 从实时空闲卡中选择 --gpu 列表；以下示例选 0、1。
export LD_LIBRARY_PATH=/data1/wenyifan/opt/lib:/data1/wenyifan/opt/cuda-12.8/lib64:${LD_LIBRARY_PATH:-}
export CUDA_HOME=/data1/wenyifan/opt/cuda-12.8
MUJOCO_GL=egl .venv/bin/lastmile-dataflow build-scenes \
  --config configs/scene_datasets/panda_omron_val103.json \
  --output-dir outputs --run-id panda-stage1-build --build-workers 4 --gpu 0

MUJOCO_GL=egl .venv/bin/lastmile-dataflow collect-lastmile \
  --dataset outputs/scene_datasets/panda-stage1-build \
  --assets-dir /data1/wenyifan/lmdf/molmospaces_data/assets \
  --config configs/execution/panda_omron_curobo.json \
  --output-dir outputs --run-id panda-stage1-collection \
  --gpu 0 1 --cpu-workers 60 --preparation-workers 12 --recording-mode numerical
```

正式全量不传 `--max-trials`。`numerical` 关闭在线 RGB、深度和视频，保留完整实测状态和回放引用；`visual` 沿用在线观测记录，显式 `--record-video` 或 `--record-depth` 也会选择 visual。数值标定成功不自动加入视觉训练索引。

`collect-lastmile` 的内置 Panda 标定使用同一双池和资源参数；其后连续采集仍按原执行链记录视觉观测。300 s 为每 trial 的规划调用与物理执行活跃预算，首次 batch 整次耗时计入每个 trial，排队和保存另计。`summary.json.calibration` 保存计划/记录数量、准备失败、资源峰值、规划活跃时间与总时间；原始结果仍只有 `trials.jsonl`。

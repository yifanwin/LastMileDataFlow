## 4. 失败归因

### 4.1 `torso_feedback_limit`（25/41，主因）

**观测事实**（逐条读 `physics.jsonl.gz` 汇总）：

- 25/25 **全部为实测高度低于下限**：首次越界时 `torso_measured_h ∈ [-0.00308, -0.00301]`，下限为 `0.0`；
- 越界幅度中位数 **0.00302**，最大值 **0.00308**，`FEEDBACK_TOLERANCE_RAD = 0.003`——即**超出阈值 2×10⁻⁵ ~ 8×10⁻⁵ rad**；
- 全过程 h 最低 **-0.00308**，从未出现真正的失控下坠；
- 发生阶段：**15 条在 `navigation`**（其中 3 条第 8 步、11 条第 9 步就触发，几乎一启动即死），**10 条在 `arrival`**；另有 10 条走到 134~698 步才触发；
- 触发时**尚未进入抓取规划**（`planning.json` 为空）。

**代码定位**（`runtime/no_edit_execution.py:107-115`）：

```python
h_actual = float(self.sim.robot.group('torso')[1])
margin = torso_feedback_margin(h_actual, self.sim.robot.config.torso_limits)
if margin > FEEDBACK_TOLERANCE_RAD:
    failures.append('torso_feedback_limit')     # → 硬停止本 attempt
```

`torso_feedback_margin` 定义为 `max(0, lo-value, value-hi)`，下限 `lo = 0.0`，所以任何负向过冲直接等价于 margin，**零容差**。

**关键对照**：同一 run 内，105 次站点 trial 走了 `arm_tick` / `mobile_tick`（躯干命令写成 `clip(measured_h + h_gap/scale, …)`，对实测值闭环修正），**0 次**触发该原因；41 次 rollout 走 `navigate()`，其中躯干命令是 `neutral_action()` 给出的 `a[19] = ctrl[current]`（**开环保持**，全程不再修正，见 `no_edit_execution.py:402`），25 次触发。

**结论**：这是 **rollout 导航路径的躯干开环控制**问题——位置环在重力下产生约 −0.003 rad 的稳态下偏，恰好等于并略微超过阈值，而检查是零容差、一票否决。它既不在失败分类上与「真实失控」区分，也与 `torso_error_policy='record_only'` 的协议声明矛盾。**这是本 run 从「有 63 次成功抓取」变成「0 条保留」的直接原因。**

### 4.2 `constrained_planning_failure`（15/41）

- 30 条诊断（含 retry）**全部**为 `status = "Goalset planning returned None."`，`feasible` 全 `False`；
- **30/30 都是 `native_plan_grasp = True`**——即抓取候选本身可规划，失败只发生在 goalset 段；
- 主导约束项（solver_trace 首帧 max 的中位数）：`scene_collision` 512.4、`cspace` 358.8、`target_collision` 109.0；
- 代码自带标注 `finite_budget_not_impossibility: true`；
- 到达精度无问题：这些 rollout 终点 base 与 goal base 的位置误差均值 **0.0003 m**、最大 0.0008 m，yaw 误差 ≈ 0。也就是说**导航本身成功**，失败纯粹来自「在目标站位上以 holonomic base + 单自由度躯干为变量做无碰撞规划，5 次 native attempt 内没解」。

按前文口径，**不能**把这 15 条读成「物理不可达」；它们是「冻结预算内无解」。

## 6. 效度边界与未验证项

- 仅 **1 个场景**（val_103）、**1 个任务**（Cup_30 pick）、**1 个 seed**，不能外推任何成功率结论。
- `dataset_index.jsonl` 为空，本 run **未产出任何可训练片段**；60 % 的 trial 成功率**不等于**管线成功率，两者分母语义不同（trial = 单站点固定抓取；rollout = 起点→目标连续转移）。
- `torso_feedback_limit` 的机制定位基于「站点 trial 0 次 vs rollout 25 次」的路径对照与 `navigate()` 开环命令的代码证据，**尚需一次定向复现**（例如把 `FEEDBACK_TOLERANCE_RAD` 或下限留白调大、或让 `navigate()` 也走闭环躯干命令）来确证。
- `constrained_planning_failure` 是冻结预算内的结论，**不等于**物理不可达；`torso_heights=[0,0.369,0.738]` 与 holonomic base 规划空间是否覆盖该抓取姿态，未做单独的 IK 可达性扫描。

## 实施结果

工作目录为 `.worktrees/base-map`，保留原有修改。沙箱内不暴露 CUDA，沙箱外实际可用；只读查询发现 GPU 4–7 空闲，用户明确批准使用 GPU 4 做真实验收与通过后的全图。未修改 main 或其他进程。

本轮直接优化原链路，未增加 CLI 或平行执行器：

1. 同一 yaw 的各 grasp 候选按最多 8 个 lane 合批，每 lane 仍为一个显式初值、一个 seed。最后一批才 padding；逻辑尝试数不包括 padding。
2. 每条轨迹独立提交现有 CPU 池；GPU 求后续 batch 时前批可验证/评分。全部结果在下一 yaw 前收齐，热启动仍只来自已完成查询。
3. 同一 worker 同一 yaw 不重复初始化机器人，精确构型质量缓存跨 grasp 复用；目标相关硬间隙独立检查。换 yaw 清空缓存；`warm_start_seeds=0` 同时禁用 IK 和轨迹历史初值。
4. 完全相同的同 grasp、同 yaw 时间多项式共用 CPU 任务，保留各候选身份、原始尝试数和排名；不同路径或时间参数不合并。
5. spawn 前限制 BLAS/OpenMP 为每 worker 一线程，避免进程数与 BLAS 线程相乘。
6. 硬检查仅更新位置运动学、Jacobian 数据和碰撞，不调用无关动力学/约束求解；自碰撞包围球批量预筛，避免逐对重复计算。保留完整硬碰撞集合、接触窗口和所有离散分辨率。
7. 逐区间验证，发现碰撞后不计算后续区间；无效轨迹不评分。地图不启用未被结果消费的逐约束 SolverTrace 同步诊断。
8. 汇总记录 GPU batch 数、实际/padding lane 数、CPU 等待墙钟、复用轨迹数，以及规划与验证/评分 CPU 时间；共享 batch 时间按 lane 分配到查询，不重复累计。

未削减 32 IK seeds、4 代表、每代表 2 初值、32 评分点、前 4 保留预算或 5 ms / 0.01 rad / 近障 2 mm 的验证精度。SVD 已是 64 分区批量计算，本轮实测瓶颈在几何验证，没有增加 GPU SVD 或多 GPU 调度。

## 真实接口修复

真实运行暴露并修复：

- NumPy yaw 排序索引导致随机 seed 变为 NumPy 整数，原生 seed 初始化拒绝；固定遍历索引为 Python int。
- `seed_traj` 实际要求 `[batch, 1, horizon, joints]`，原方案的三维形状判断错误；每 lane 一个 seed 的预算不变。
- 原生 line search 会扩展问题数；目标和接触窗口按 `goal.idxs_link_pose` 映射，避免把 8 个目标与 32 个搜索 lane 错配。
- 原生 B-spline 最后有一个静止 padding 区间；接近软目标在该区间前归零，避免终态已静止时仍要求非零接近深度。
- 已通过硬检查的数值级接触可能使软评分返回 None。轨迹评分按接触惩罚的零质量极限记录 0；独立硬规则不放宽。评分采样发现硬碰撞则拒绝候选，原因 `collision_at_score`，不标基础设施 incomplete。

## 后续数值定位与小样本结果

此前将 None 记为接触零质量的修复仍不足以解释所有零分。定向定位发现 MuJoCo 3.5 的 GJK 存在假零距离：同一分离网格对 `distmax=0.5` 返回 0，但 `distmax=0.03` 返回上界 0.03，witness 端点不重合；实际还涉及 box-mesh 和 cylinder-mesh。与[上游已确认问题 #3383](https://github.com/google-deepmind/mujoco/issues/3383)一致。

共享 `scenes.geometry.geom_distance` 在原生返回 0 且 witness 不重合时，通过保守支撑投影确认分离，再采用 witness 长度并按查询上界截断；没有分离证据则保持原值。该规则依据[上游 GJK 提前退出修复](https://github.com/google-deepmind/mujoco/commit/35342f4)，没有全局忽略零距离、关闭碰撞或更换 MuJoCo 版本。评分与轨迹验证共用这一处理。增加一个实际触发该缺陷的确定性凸网格回归，距离由错误 0 恢复为 0.0605068 m。

## no_valid_trajectory 的具体原因（最终记录细分）

该状态表示初态和 IK 筛选后已经进入轨迹优化，但该查询的所有候选均未通过独立验证。低质量或有效零分不会触发此状态。2,016 个进入轨迹优化的查询中，1,665 个为该状态（82.59%），另外 351 个有有效轨迹。

仅统计这 1,665 个查询，共 12,846 条失败候选：

| 首个失败原因 | 候选数 | 占该子集 |
|---|---:|---:|
| terminal_pose | 7,529 | 58.61% |
| collision | 3,203 | 24.93% |
| approach | 1,949 | 15.17% |
| joint_limit | 165 | 1.28% |

终态要求位置误差 ≤5 mm、姿态误差 ≤0.05 rad。terminal_pose 中 7,521 条位置超限，5,752 条姿态超限，两者重叠 5,744 条；位置误差中位数 15.10 mm、90 分位 27.51 mm，姿态误差中位数 0.07495 rad。它们的原生成功标志全部为 False。输入 IK 代表通过不等于优化后的终态仍通过；这批轨迹相对 q_seed 的归一化终态变化中位数为 0.05367。这里可确认求解终态未达要求，尚不能仅凭记录把原因全部归结为某个代价权重。

approach 要求识别最终连续接近走廊：横向 ≤0.01 m、姿态 ≤0.10 rad、轴向累计回退 ≤0.002 m，并达到独立最小轴向推进 0.01 m。0.10 m 仅为优化软目标。1,949 条 approach 失败中有 1,221 条原生成功，说明原生 success 不包含本项目完整的最终接近验收。当前失败摘要未保存真实接近长度或触发走廊截断的分量，不能用 dataclass 默认 approach_length=0 推断实际推进为零。

1,543 个查询同时包含多种候选失败，仅 70 个全为 terminal_pose、47 个全为 collision、5 个全为 approach。因此灰格的统一状态掩盖了候选层面的混合原因。1,573 个查询已经尝试满 8 条，其余为 2/4/6 条；主要问题并非没有发起优化。

碰撞摘要只保留首个失败时刻，没有保存 geom pair；现有记录不能继续区分具体环境部件、自碰撞或夹爪外壳。进一步定位需对少量失败候选记录碰撞对及接近失败分量。以上为逐候选的首个失败，后续未执行检查可能还有其他问题；不代表已经找到每条失败的唯一物理根因。

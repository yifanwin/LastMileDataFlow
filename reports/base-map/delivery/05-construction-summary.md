## 2. 已构建的处理链路

固定站位与 yaw / 七关节初态 → 初态检查 → 每 grasp 32-seed IK → 按归一化距离选择最多 4 个代表 → 每代表两个初值、最多 8 次轨迹尝试 → Pose-goal 优化 → 独立整轨迹验证 → 所有有效候选评分 → 按完整轨迹瓶颈保留最多 4 条 → 保存记录与地图。

| 模块 | 当前实现与作用 |
|---|---|
| 配置与入口 | 复用 `evaluate-stations`，没有新增公开 CLI；预算、接近、验证和采样参数进入 `BaseMapConfig` |
| `planning/trajectory_quality.py` | 代表选择、终态区域聚类、扰动/历史初值、实际关节曲线、16→32 点自适应评分、主辅瓶颈、排名 |
| `planning/curobo/` | 每显式初值一个 lane，Pose-goal 不把 IK 代表锁成硬关节终态；接近软代价、真实有效曲线解码 |
| `planning/trajectory_validation.py` | 起点、位置/速度/加速度、MuJoCo 几何、终态与接近段检查；硬碰撞和软评分排除分离 |
| `workflows/station_map.py` | 逐 yaw 独立求解、同 yaw 跨 grasp 合批、CPU 验证评分、历史缓存、分块记录和统计 |
| `station_map_plot.py` / `quality_map.py` | 主分图、有效 yaw 均值、R_plan、主辅分及瓶颈阶段、指定查询/候选的 TCP 采样路径展示 |

当前参数：IK 去重距离 0.05，32 seeds / 4 代表 / 每代表 2 初值 / 最多保留 4；接近软目标 0.10 m，独立最小有效长度已落为 0.01 m；检查分辨率为 5 ms、0.01 rad、近障/接近区几何运动尺度 2 mm；评分初始 16、最多 32 点；辅助分排除前 10% 归一化弧长。方案中“最小有效长度待定”已被实现首值补齐，仍需实际样本标定。

主分 `quality_full` 是唯一质量排名依据；辅助分不参与排名。同分再比较归一化路径长度与候选编号。无有效轨迹与有效零分分别记录。新结果使用 `base-trajectory-quality-map-v1`，旧静态结果维持历史含义。

候选 NPZ 保存查询摘要、验证原因、初值来源、实际终态/区域、双分数与瓶颈，以及最多 4 条获选轨迹的 time/q/v/a。R_plan 在最终保留前计算；图中位置均值不对应某条真实轨迹，预览需绑定具体 yaw 与候选。

## 3. 真实实验进展：已有有效轨迹

以下数据直接读取 `outputs/experiments/trajectory-perf-r06-20261106/` 的 summary、输入配置和候选 NPZ；不是由旧交付报告推断。

小区域为 dx∈[-0.1,0]、dy∈[0.6,0.8]，0.1 m 网格，共 **6 个 xy × 3 个 yaw（−60°/−45°/−30°）× 5 grasp = 90 个查询**。summary 中 `stations=18` 表示带朝向的站位，不能误读为 18 个 xy。

| 指标 | 热启动 broad | 冷启动 cold |
|---|---:|---:|
| 接近权重 | 10 | 10 |
| 历史 seed 预算 | 8（包含在 32 内） | 0 |
| 完成查询 | 90 | 90 |
| IK seeds / 有效 IK | 2880 / 518 | 2880 / 486 |
| 实际轨迹尝试 / 完成 | 290 / 290 | 288 / 288 |
| 有效候选 / 保留 | 9 / 9 | 4 / 4 |
| 有效查询 | 9 | 4 |
| 有有效 grasp 的 SE(2) 站位 | 8 | 3 |
| R_plan | 3.10% | 1.39% |
| 墙钟 | 195.00 s | 189.56 s |
| 原保存主分范围 | [0,0] | [0,0] |

两组查询均完整，53 个查询 IK 无解；热启动另外 28 个查询无有效轨迹，冷启动为 33 个。有效候选覆盖 grasp 2 和 4。热启动实际使用 145 个线性、92 个扰动、53 个历史初值；冷启动为 144 个线性和 144 个扰动初值，历史分支确实被关闭。

这是同搜索上限的小样本对照，实际尝试数因代表数量不同而略有差异。可支持“本样本热启动有效候选更多”，不能支持“普遍更快”或已证明全图覆盖提高；热启动墙钟反而略长。

失败原因按独立验证的首个失败统计：

| 原因 | 热启动 | 冷启动 |
|---|---:|---:|
| terminal_pose | 147 | 151 |
| collision | 81 | 86 |
| approach | 51 | 46 |
| joint_limit | 2 | 1 |
| valid | 9 | 4 |

终态误差是当前最大失败类别，随后是碰撞和接近。下一步应从这些真实失败样本定位，不宜直接增加预算或放宽验收。

## 4. 零分问题与密采样：局部已修复，整批结果未更新

r06 原始 broad/cold 虽有有效轨迹，保存的主辅分却全为 0。`zero-score-detail.log` 等诊断记录了大查询距离下 `mj_geomDistance` 返回 0、而近距离查询及几何分离证据不同的情况。当前源码新增共享 `geom_distance()`，在确认几何存在分离平面时处理该异常，供评分及验证调用。这是已有实际错误的修复，不是通过放宽碰撞许可得到正分。

`analysis/dense-check.json` 与 `logs/dense-check-final2.log` 记录了三条已保存曲线的重新验证、修复后 32 点评分及 128 点加密结果：

| query / candidate | 原主分 | 修复后 32 点 | 128 点 | 瓶颈阶段 |
|---|---:|---:|---:|---|
| 19 / 5 | 0 | 0.0030488675 | 0.0030488675 | transit |
| 32 / 4 | 0 | 0.0000521832 | 0.0000521832 | transit |
| 34 / 1 | 0 | 0.0036413036 | 0.0036413036 | transit |

三条曲线均重新通过模型验证，128 个评分点的硬检查也均通过；本样本主分与辅助分相同。加密前后三条的分数及相对顺序没有变化，但它们来自不同查询，不构成同查询多候选排名稳定性的完整证明，也不证明连续最低值已找到。

**这些重算数值只在诊断结果中。原 broad/cold 的 summary、map 和候选摘要仍保存旧零分，不能将其直接作为最终质量图或据此解释站位优劣。** 三条复核也不等于全部 9 条热启动、4 条冷启动曲线已按最终修复复验。

默认配置的 `approach_weight` 仍为 1，得到上述正例的小区域实验使用 10。二者需明确区分；不能说默认参数已取得相同结果。

## 5. 性能和软件验证

已实施同 yaw 跨 grasp 合批、GPU 与逐轨迹 CPU 检查重叠、同 yaw 构型缓存、完全重复曲线复用、worker 单线程 BLAS、位置运动学更新及碰撞包围球预筛。没有削减搜索预算、评分点数或验证分辨率。

已有对照：相同 48 条候选、均无有效轨迹的串行/并发调度墙钟为 262.201 / 54.106 s，约 4.85 倍；相同 1653 状态的验证器 profile 为 10.147 / 4.522 s，约 2.24 倍。这些是不同口径的局部结果，不能相乘，也不能当全图或有评分负载时的加速比。

最新读取到的全套日志 `/tmp/base-map-final-all-tests.log`：**437 项，435 通过、2 跳过，36.495 s**，结束于 11:16。后续 `/tmp/base-map-distance-tests.log`：44 项通过，位于约 11:24。源码和测试在这些日志之后仍有修改时间更新，因此不能把这些既有日志称为当前最终文件版本的完整验收。

本轮是只读分析和文档整理，没有重跑测试、GPU 规划、物理 stepping 或抓取。既有测试覆盖代表/排名、内部碰撞、接近、曲线极值、预算、跨 yaw、记录及调度等软件语义；模型验证仍不等于控制跟踪或抓取成功。

1. 收敛当前距离查询修复，记录一个明确源码版本，对该版本完成相关测试与必要全套回归。

4. 通过小规模验收后再运行 val103/Cup_30 全图，交付主分/R_plan 图、少量获选路径预览和耗时汇总。

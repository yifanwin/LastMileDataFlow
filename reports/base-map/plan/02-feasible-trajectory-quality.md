## 1. 交付范围与主流程

工作区固定为 `/data1/wenyifan/lmdf/LastMileDataFlow/.worktrees/base-map`；main 只读并保持干净。直接扩展现有 `evaluate-stations` 质量图链路，不新增 CLI、平行执行器或静态/轨迹两套运行模式。

首版保持 Panda-Omron、固定底盘和升降、七关节手臂、既有 10 cm 网格/9 朝向/最多 5 grasp、场景物体不动。每条轨迹从固定初始七关节到 grasp，包含接近，不包含闭爪、抬升、撤离和实际执行。

流程为：

1. 一次加载场景、grasp 世界位姿、机器人模型、碰撞几何、限位和评分模型。
2. 按固定 xy/yaw 顺序处理查询；更新底盘坐标变换、局部目标和碰撞世界，检查该朝向初态。
3. 各 grasp 独立执行 32-seed IK；检查终态，按归一化距离 0.05 选最多 4 个代表。
4. 每代表建立两条初值，最多 8 条；同 grasp 同目标，Pose-goal 允许终态关节变化。
5. 执行 TrajOpt，取出每条候选的完整结果与实际终态。
6. 对最终有时间参数的轨迹做独立验证；记录失败阶段/原因和尝试数。
7. 全部有效候选进行 16→32 点评分，得到完整主分、过渡后辅助分和瓶颈位置。
8. 按实际终态统计构型区域；按主分排序保留前 4，以第 1 条更新该朝向/grasp 质量。
9. 写入结果、更新有界热启动缓存，最后按既有有效朝向平均生成各 grasp 的地图。

主质量、规划有效比例、辅助质量、终态多样性分别记录；不相乘，不新增综合权重。

### 2.2 本机 cuRobo 0.8.0 的只读接口证据

本工作区没有独立 `.venv`。本轮只读检查主仓库 `.venv/lib/python3.11/site-packages/curobo`，包元数据为 0.8.0，没有用其 editable 环境运行工作区代码。

`curobo/trajectory_optimizer.py` 导出 `TrajectoryOptimizer`，底层 `_src/solver/solver_trajopt.py::solve_pose` 提供 `seed_config`、`seed_traj`、`num_seeds`、`return_seeds`、`goal_state`、`use_implicit_goal`；`TrajOptSolverResult` 有逐候选 `interpolated_trajectory`、`interpolated_last_tstep`、终态误差及 seed 排名信息。`return_seeds` 大于 `num_seeds` 会自动扩大 seeds，不能误用而超预算。

该版本 `solve_pose` 与 `solve_joint` 对 `use_implicit_goal` 的注释不一致；`manager_goal.py` 还存在只在启用时写目标标志的路径。故 P0 必须验证实际末端自由度与 solver 复用状态，不能仅按函数名或注释认定 Pose-goal。首版采用固定 Pose-goal solver，避免在同一对象上切换 Joint-goal 留下目标状态。

**多候选首选实现：每条逻辑初值独占一个 batch lane，lane 内 `num_seeds=return_seeds=1`。** 每个 grasp 最多 8 个 lane，同一站位下各 grasp 可合批，也可顺序分批；每 lane 的 `seed_traj` 使用该接口明确支持的 `[batch, action_horizon, dof]` 形状。这样不用假定 API 接受未核验的四维多初值张量，并保留独立的候选归属。批量 padding 不进入统计，内部不得再展开新 seeds。

只有实测确认全 seed 输入形状与返回映射后，才考虑“一 grasp 一 lane、8 seeds”的等价优化；它不是首版前提。直接调用现有 motion 的 TrajOpt solver，复用相同机器人、场景与约束，不绕回可能只返回一条解的 `plan_grasp`。

## 5. 朝向更新与热启动

### 5.1 查询与缓存边界

查询键为 `(scene_id, target_id, ix, iy, yaw_index, grasp_id)`。q₀ 是共同七关节数值，但每个 yaw 的初态世界几何不同，逐次检查。不合法记为 initial_state_invalid，不替换起点；保留独立失败计数，0 次轨迹尝试对应空 R_plan。世界 grasp 用 `inv(T_world_base) @ T_world_grasp` 转到底盘系；固定场景几何已上传一次，`bind_station` 更新表达。

同一时间一套 planner 只服务一个绑定站位；该站位的 GPU 求解完成后才能改变底盘变换。CPU 任务包含自己的 base pose、目标和轨迹，在各 worker 的独立 MuJoCo 状态上计算，不依赖随后被重绑的 GPU 上下文。

复用边界：机器人模型、关节限位、自碰撞模型、世界 grasp、q₀/开度可共享；IK 与轨迹只能作初值；旧碰撞通过标记、轨迹质量、环境间隙和瓶颈位置不能复制到新 yaw。跨 yaw 共享 Jacobian/环境惩罚的最终组合值也不成立。

### 5.2 确定性热启动

固定 xy 行优先、yaw 从 −60° 至 +60° 遍历。只取已完成的同场景/目标/grasp 查询：同 xy 相邻 yaw 优先，其次现有空间邻域。按 yaw 差、xy 距离、来源查询编号排序；每个查询的 CPU 检查和评分完成后再提交热启动缓存，先实现确定性，再评估流水线性能。

IK：最多 8 个历史实际终态作为 32 seeds 的一部分，其余保留原生/随机初值。重新 IK 后才可成为新代表。

TrajOpt：每个新代表始终保留一条关节插值初值；第二条优先采用最近历史轨迹，按当前 solver horizon 重采样并平滑修正起终点到当前 q₀/q_seed；无历史轨迹则采用扰动初值。历史轨迹只是新初值，允许与新环境碰撞，优化后重新验证。一个历史来源不复制给所有代表，按新代表到来源实际终态的距离分配，剩余代表使用扰动。记录 `seed_kind`、来源查询/候选和新代表编号。

缓存只保留当前/邻近网格行和 yaw 邻域，离开邻域即淘汰；不保存全图求解器状态或派生索引。原生优化中途状态不跨目标复用，仅复用显式 q/轨迹初值。

## 6. Pose-goal、末段接近与实际终态

q_seed 是初值终点，不是 Pose-goal 的硬关节目标；q₀ 固定，grasp TCP 终态固定。P0 需确认 solver 没有隐式锁住 q_seed；若不支持所需语义，先修正适配层，不静默改成 Joint-goal。

采用 grasp TCP 正向接近轴（目前转换保留 TCP z 轴，实施时核对本体定义），设目标为 pg，轴为 a：`d(q)=a·(pg−p(q))`，横向偏差为 `(I−aaᵀ)(p(q)−pg)`。软目标是从 d≈0.1 推进到 d≈0，硬验收不要求走满 0.1 m。

验证从轨迹末端向前识别满足方向、横向和姿态要求的最终连续接近末段，记录其真实弧长/时间起点；从该点到终态全段检查横向偏差、姿态和轴向回退。不能只标记最后 20% 就算接近通过，不能通过短暂经过名义 pregrasp 点后大幅绕行蒙混。记录该段实际轴向推进长度，与独立的最小有效接近长度比较。短于 0.1 m 不直接拒绝；最小有效长度的具体首值尚待确定，不能拿软目标充当硬下限，也不因单条失败临时改变配置。

逐候选保存 `q_seed`、`q_final`、`distance_seed_final`、FK 终态误差。实际有效终态使用归一化距离 0.05 的确定性直径受限聚类：候选编号递增，必须与某簇每个成员都在阈值内才入该簇。记录簇数、簇成员、最大簇占比与输入代表到簇的映射。

所有有效候选聚类在最终前 4 筛选之前完成；没有有效解时记录 0 簇、空占比。失败轨迹若有实际终态也保存以便诊断，但不混入有效终态覆盖。聚类只是阈值区域统计，不能称为机器人所有 IK 拓扑分支。相同终态可以有不同路径，评分后仍可能同时入选。

## 7. 严格轨迹验证与计数

### 7.1 验证流程

使用最终输出的关节轨迹、关节顺序、时间步长和实际有效长度，不将 B-spline action/control points 误当可执行 q(t)。统一保留 solver 所定义的曲线/插值，后续评分与保存采用同一条轨迹；任何重采样或重定时若改变几何需重验。

验证顺序：起点一致/时间有效 → 关节范围、速度/加速度与连续性 → MuJoCo 全程 FK、环境/自碰撞 → 必要接触规则 → grasp 终态与接近末段。记录首个失败原因和位置即可，不穷举全部错误。原生成功标志保留作对照；凡有可用最终轨迹都执行独立检查，最终有效性由上述条件决定。缺少轨迹是一次未找到解；基础设施异常则查询 incomplete。

对每个输出时间区间插值细分，至少达到第 4 节步长，近障/接近区域进一步加密；不能只检查原生结点、TCP 位移或 32 个评分点。关节运动导数按实际轨迹表达检查，不靠稀疏差分宣称速度/加速度通过。若输出含非平滑拼接，先用现有时间参数化生成一致轨迹再验，不能省略连接处。

用户已接受科研首版：采用明确分辨率的整段离散几何复核，连续碰撞证明不作为交付前提；不在没有证据时称连续无碰撞证明。选择一条结点间碰撞反例验证检查能拒绝。通过表示模型与检查协议下可执行，不宣称真实闭爪或跟踪成功。

### 7.2 接触和评分分离

将既有目标/手指几何角色读取复用，但为轨迹加上阶段和接触窗口。准确的夹持面 geom 名称在 P0 从机器人模型确认后写配置；若现有几何无法区分夹持面和外壳，先修正角色映射，不扩大豁免。

正常地面支撑沿用既有许可；目标必要接触限于最后接触窗口和指定夹持面，容差只用于微小接触数值误差，不允许穿越目标。其余接触按严格规则拒绝。既有 `robot_contacts` 的 −1/−2 mm 初始化穿透规则不能作为本 validator 的默认。

用于加密的最小间隙从完整非许可碰撞对获得；评分函数对目标/支撑面的软排除只影响 m(q)，不缩小验证或加密碰撞集合。

### 7.3 R_plan

每条实际提交优化的初值是一次逻辑尝试。保存 `n_attempted`、`n_completed`、`n_valid`、`n_retained`；batch padding、优化迭代和 dt finetune 不新增尝试。物理约束失败属于 completed；基础设施失败造成 incomplete。

- 完整查询且 n_attempted>0：`r_plan=n_valid/n_attempted`。
- 0 次尝试：空值加过滤/初态/IK 原因。
- 查询 incomplete：正式比例为空，保留现有计数和错误。
- 重复终态/路径不从分子分母去掉；比例计算于前 4 筛选之前。
- 汇总对完整查询求和再相除，记录不完整查询数量。

正常情况下 4 代表产生 8 次尝试；若只有 1 代表则为 2。为保证可比性，结果保留实际代表数和预算配置，不能把不同分母的比例解释为相同覆盖能力。

## 8. 双瓶颈评分、位置与阶段

令 L 为固定范围归一化的总关节弧长，u=s/L。先取 16 个等弧长点（含两端），再加入 u=0.10 和实际接近边界，重复点不增加预算；新增边界最多占 2 点，包含在最多 32 点中。

加密对区间计算第 4 节的六项触发程度，将质量差/运动量除阈值、间隙与限位用阈值除实际值，取最大程度作优先级；只要超过 1 即触发。同程度按弧长位置处理，优先项加入弧长中点。无触发时选最长区间。复用验证阶段的 FK/距离/区间运动记录，避免为加密重复进行整轨迹检查；m(q) 只在选中的最多 32 个构型上计算。

每轮保留旧点与分数：

\[
Q_{full}=\min_{s\in S}m(q(s)),\qquad
Q_{post}=\min_{s\in S,\ s\ge0.10L}m(q(s)).
\]

辅助分不重新优化轨迹、不使用另一套独立采样预算，不改变最终排名。辅助区间包含截断边界，所以二者可核对 `Q_post≥Q_full`；主分瓶颈在起点且后段较好时，辅助分用于说明差异。L=0 时辅助分为空。

瓶颈记录包含 q、TCP 世界位姿、t、s、u、样本编号及阶段。优先显示 `approach`，否则 u<0.10 为 `initial_transition`，其余为 `transit`；另存过渡/接近两个布尔标记和 `is_terminal`，允许两个阶段重叠。主分/辅助分各记录最早的最低点和每轮最低值。

按主分降序、完全同分按路径长度升序、再按候选编号保留最多 4 条。辅助分和终态簇不作为隐含二级质量指标；4 条可以来自同一实际终态区域。每 grasp 最坏 8×32=256 次 m(q) 评估，边界点包含其中。

单查询最坏 32 次 IK seed 优化、8 次轨迹优化、8 条全程验证、256 个质量构型评估。验证点数可远大于 32，不能按静态 IK 耗时线性外推全图时间。首版维持单 GPU 和现有 CPU 进程池，按阶段计时后再优化，不提前建多 GPU 调度平台。

## 性能优化建议（尚未实施）

优先保留 32 IK seeds、4 代表、8 轨迹、32 评分点和验证精度，优化重复计算和调度。旧静态图耗时不能直接预测轨迹版瓶颈，首个小规模样本分别记录 IK、TrajOpt、验证、距离/Jacobian、SVD、传输、等待和总墙钟时间；不把重叠 CPU 累计时间与 GPU 时间直接相加。

1. **删除被替代的终态评分。** 当前 `_score` 对全部收敛 IK 做 Extended Manipulability；新代表按归一化距离选取，只保留 IK 终态几何/位姿检查，不再为 32 个 seeds 计算用于旧排名的可操作度。IK 热启动也按几何覆盖选取，避免隐式保留这笔开销。
2. **同站位合批。** 同 yaw 的多个 grasp 共享碰撞世界，将最多 5×8 个逻辑初值分成适配显存的 batch；保持每初值独立 lane 和候选身份。不同 yaw 不直接塞进同一单世界 batch。求解器、机器人和上传几何持久复用，减少每候选初始化/传输/同步。
3. **CPU 任务按轨迹分发。** 独立 worker 持有 MuJoCo 模型，一条轨迹的验证与评分在同一 worker 完成；无效轨迹立即结束，不做质量评分。不按每个采样点发进程任务。相同状态的 FK、距离与 Jacobian 尽量共用，但软评分几何集合和硬碰撞集合仍分别解释。
4. **小范围精确复用。** 同一 yaw/场景/q₀/开度下，初始合法性和初始质量只算一次；同 yaw 完全相同轨迹可复用计算，候选尝试数仍分别统计。不以近似构型缓存替代实际质量，不跨 yaw 复制环境相关结果。对大量场景几何可先用保守包围体剔除不可能接近的对象，再精确测距，不能因粗筛漏掉障碍。
5. **平衡流水线和热启动。** 当前实现先提交整行站位，再回收 CPU 结果更新缓存，因此本行前面 yaw 的已求解结果没有及时成为后续 yaw 的热启动。新方案固定来源与回收边界；若必须使用直接前一 yaw 的最终结果，该依赖需要等待，不能同时承诺无等待流水线。先在空间独立小块之间重叠 GPU 规划与 CPU 验证，块内保持确定性热启动依赖。是否优于简单顺序查询，以小样本墙钟时间和覆盖数比较，不凭 GPU 利用率判断。
6. **测量后再扩大并行。** 保持现有 CPU 池，避免 NumPy/BLAS 每 worker 再开大量线程；SVD 当前已按 64 分区批量计算，只有计时显示其占比显著才考虑跨采样点批量化或 GPU 化。多 GPU 可按固定空间块分配，各块持久 solver 和有限 CPU 配额；明确块间热启动边界，不能假设与单 GPU 全图遍历得到相同结果。

保存前 4 条完整轨迹，其余候选摘要分块写出，避免逐点日志和大量小文件。不要为提速提前按长度/终态分剪掉候选、按时间替代弧长评分、降低验证精度，或在预算内已有一条成功时跳过其余候选。基于当前最低分的提前终止虽能给出主分上界，但会改变完整候选评分/辅助诊断口径，首版不采用。

本轮只检查现有耗时报告、评分函数和调度流程并补充建议，未运行性能实验，未承诺加速倍数；未修改算法及 main。

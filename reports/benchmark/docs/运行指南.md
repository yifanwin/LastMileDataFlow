从当前 worktree 根目录运行，使用该 worktree 的 `.venv`。依赖安装见仓库 `scripts/install.sh`。

## 1. 从已有标定构建

```bash
.venv/bin/lastmile-dataflow build-bench \
  --dataset <existing-scene-datasets> \
  --calibration <existing-curobo-calibration-run> \
  --config configs/benchmark/v0.1.json \
  --output outputs/benchmarks/<new-run>
```

`--calibration` 指向含 `trials.jsonl` 和 `config.json` 的具体 run。来源数据集必须对应同一份 scene-datasets。标定允许底盘移动，沿用来源试验数；不需要重新标定、策略配置或 GPU。

查看构建结果：

```bash
.venv/bin/python -m json.tool outputs/benchmarks/<run>/summary.json
```

`episodes.jsonl` 一行一个合格 S0；`scene-files/` 保存来源物理快照；`oracle.json` 是评测器内部的高率区域、路径和难度证据，不能发送给策略。初始化不合法、无高率站位、无路径或标定不完整的样本在 summary 中说明；没有合格样本就保留空 benchmark。

## 2. 策略评测

先确认模型权重、tokenizer、GPU 驱动和策略所支持的机器人：

```bash
nvidia-smi
.venv/bin/lastmile-dataflow evaluate-bench \
  --benchmark outputs/benchmarks/<run> \
  --policy-config configs/policies/molmobot.json \
  --output outputs/benchmark_evaluations/<new-run> \
  --gpu <chosen-index>
```

当前 MolmoBot 仅支持 RBY-1。Panda 的构建已可用，对该策略的评测输出 `unsupported_policy`，不生成执行轨迹。RBY-1 必要的 native 控制转换在评测初始化时进行，并记录实际配置；来源 cuRobo 标定保持原协议。

评测输出 `results.jsonl`、`summary.json` 和真实 `rollouts/`。Task Success 是主结果；Recovery Success 只是进入隐藏区域近似的诊断。完整率不足时正式 TSR/Macro 为 null；先查看 coverage、错误和未执行数量。Full policy 不调用 oracle 路径。

## 3. 生成与查看图片

新 `build-bench` 自动生成 `<benchmark>/visualization/<episode_id>.png` 和 `summary.png`，只包含静态构建信息与私有 oracle。新 `evaluate-bench` 在自己的 `visualization/` 下生成同名图片，展示本次实际轨迹、结果和双视角最终帧截图；不会向 benchmark 回写评测信息。不生成 HTML 或 JavaScript。

已有产物可以单独导出图片：

```bash
.venv/bin/python -m lastmile_dataflow.data.visualization.benchmark \
  --benchmark outputs/benchmarks/all-existing-v0.1/rby1-current
.venv/bin/python -m lastmile_dataflow.data.visualization.benchmark \
  --evaluation outputs/benchmark_evaluations/rby1-full-v0.1
```

直接打开 PNG：

- [RBY-1 benchmark 图片](../../../outputs/benchmarks/all-existing-v0.1/rby1-current/visualization/e000000.png)
- [Panda benchmark 图片](../../../outputs/benchmarks/all-existing-v0.1/panda-current/visualization/e000000.png)
- [RBY-1 评测组合图片](../../../outputs/benchmark_evaluations/rby1-full-v0.1/visualization/e000000.png)

Benchmark 图片展示 S0、高成功率站位与朝向、Recovery Region、最短恢复路径和难度。评测图片读取 benchmark 原始 JSON，叠加完整实际轨迹，标出中间和最终位置，右侧展示最终结果及相同记录时刻的两个视频截图。评测图片生成不依赖 benchmark 是否已导出图片。

地图底图是障碍物膨胀后的保守导航自由空间。绿色是 Recovery Region 的离散 XY 投影；进入区域仍需满足 yaw 容差。最短路径为紫色虚线，实际轨迹为蓝色实线。静态图片不提供播放或拖动，完整回放直接打开 rollout 中的两个 MP4。

## 4. 视频记录与已有数据补做

后续评测默认保存 `rollouts/<episode_id>/videos/head.mp4`、`third_person.mp4` 和 `trajectory.npz`；不默认保存相机逐帧 PNG。策略仍使用原有 head 与双腕输入。视频是原始相机 RGB，head 未应用策略的鱼眼预处理。

`recording.json` 的 `videos` 字段保存路径、帧数、帧率、每帧实际相对仿真时间和来源。视频按控制记录频率编码，页面按对应帧显示真实时间，末尾可能有不足一个周期的物理步。

已有完整状态与 head 图片的评测可以补做视频：

```bash
nvidia-smi
MUJOCO_GL=egl .venv/bin/python \
  -m lastmile_dataflow.data.visualization.benchmark_replay \
  outputs/benchmark_evaluations/<existing-run> --gpu <chosen-index>
```

目标 `videos/head.mp4` 和 `third_person.mp4` 已存在时不覆盖。补做读取原始 head PNG，将轨迹中的 qpos/qvel/ctrl 和冻结场景用于第三人称渲染；不调用策略，不推进物理，不改写轨迹和结果。第三人称视频标记 `recorded_state_reconstruction`。补做后自动生成评测组合 PNG；已有 PNG 保留。

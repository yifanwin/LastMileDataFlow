## 1. 目标与研究问题

基于已有 **scene-datasets + cuRobo 逐站位实测标定**，快速构建首版可解释、可闭环的 last-mile mobile manipulation benchmark，名称为 **lastmile-bench**。

**按用户 2026-10-17 澄清：标定允许开放底盘，优先直接复用已有结果。本文成功率统一指“参考执行器从该站位初始化，在已有标定协议下完成任务的实测成功率”；不要求固定底盘，不以重做标定作为构建前置。**

研究问题：**机器人已经到达目标附近，但当前站位无法可靠完成操作时，策略能否通过自主底盘调整解除失败条件，并最终完成任务？**

“可解释”要求每个 episode 都能说明：S0 为什么困难、对象为什么可操作、恢复机会是否可达，以及该样本的移动难度。“可闭环”要求策略从 S0 接收观测、执行动作、继续接收反馈，直到成功或结束预算，并由仿真中的实际任务状态判定结果。

本文是目标需求，不代表现有代码已实现或真实评测已通过。“首版”指本项目首次交付，不据此宣称学术首创。

## 2. 范围与边界

v0.1 必须覆盖：

- 从已有合法站位和逐站位实测结果筛选困难 S0。
- 在同一场景、同一对象、同一任务内建立高成功率证据及 recovery region approximation。
- 验证从 S0 到恢复区域的合法底盘路径，导出 `episodes.jsonl`。
- Full policy 从 S0 自主闭环执行，记录任务、恢复、底盘运动和难度指标。
- 按 Task、Case、Failure Pattern / family 汇总，并给出明确分组口径的 Macro Average。

本轮优先最小实现：复用现有 `build-bench` / `evaluate-bench` 入口和执行、记录链路，不新建平行管线。本文只整理需求，不执行构建、标定或策略评测。

v0.1 不要求：连续空间的成功概率精确建模、最优恢复策略、固定 S1 到达任务、训练数据物化、完整新模型训练或一次性补齐大量 failure family。`lastmile-datasets` 的 S0×S1 示教配对规则不因本需求改变。

## 3. 任务、初始状态与目标

| 概念 | 定义 | 约束 |
|---|---|---|
| Task | `Pick` 或 `Open`，只描述做什么 | 不把移动方向、固定恢复站位或失败原因写成 Task 类型 |
| Target | 场景中的具体操作对象；Open 还需定位关节 | 同类对象不能互相替代 |
| Initial State / S0 | scene-datasets 中的合法站位及可恢复的完整初始状态，参考执行器从该站位启动的任务实测率低 | 保留底盘 XY、yaw、机器人关节、对象与场景状态 |
| Goal | 最终 Pick 成功或 Open 成功 | 不要求到达某个固定 S1，不将进入恢复区域写成任务成功条件 |
| S1 / 高率站位 | 构建期证明对象可操作、构造恢复区域的标定站位 | 可有多个；不作为策略输入或指定终点 |
| Episode | 一个确定任务、对象、S0 和初始化条件下的独立评测实例 | 不按 S0×S1 生成多个相同起点的评测实例 |

Pick / Open 的物理成功判据复用项目对应任务的判定器，并记录协议与阈值。Pick 应由实际抓取、抬升及保持证据判定；Open 应由目标关节进度及保持证据判定。具体距离、角度和时长沿用任务协议，不能由策略自行报告成功。标定和 Full policy 均可在各自约定的活动范围内移动底盘。

“已经到附近”的范围沿用 scene-datasets 的目标局部采样域，并保存其定义；不增加一个未经约定的固定 S0→S1 距离门槛。

## 4. 输入与标定证据

### 4.1 必需输入

1. scene-datasets：场景引用、对象与任务标识、合法候选站位、初始化状态、导航所需几何信息。
2. cuRobo 标定：原始 trial 结果、站位绑定、试验次数、成功判定、执行配置及必要 rollout 引用。
3. 构建配置：低/高成功率阈值、区域近似参数、局部候选域、导航参数及确定性抽样 seed。
4. 评测配置：机器人与控制接口、策略观测/动作接口、任务判定协议、执行预算。

### 4.2 “从站位启动的标定成功率”的含义

站位 q 的实测成功率为 `p_hat(q) = 成功 trial 数 / 有效 trial 数`，只从原始记录计算，不能从平滑热图读取。

- 每次 trial 从对应站位初始化，随后允许既有 cuRobo 协议规定的底盘与机械臂联合运动；保留底盘模式、局部活动范围、躯干使用和重试预算。
- 正常执行得到的操作失败、规划无解、任务预算超时可计为失败；初始化、仿真、记录或共享服务错误保持未知，不充当失败样本。
- 用于正式筛选的站位须完成配置规定的有效试验数；同时保存成功数和总数，不能只存一个百分比。不完整标定不支撑该站位的资格判定。
- 已有允许底盘移动的标定属于有效输入，直接按原始 trial 计数复用，不因开放底盘而重新标定；试验数沿用该批标定的既定计划，不强制补到新设次数。
- 低/高率只说明参考执行器 cuRobo 在该协议下的表现，不保证任意待测策略在这些站位上的成功率相同。

`station_id` 绑定 trial 的初始站位。成功 trial 中后续移动到的底盘位置是执行轨迹，不替换该站位身份，也不自动成为新的高率标定站位。低率 S0 表示“参考执行器即使可做既定范围内的底盘调整，从这里启动仍难以成功”，不据此声称“固定底盘不可操作”或“任何移动策略都无解”。

标定须绑定其来源场景、对象、任务、机器人、初始对象状态和实际执行协议。构建优先保留来源快照与控制配置，不为适配某个待测策略而先改变场景、机器人或重做标定。cuRobo 是构建参考执行器，待测策略及其控制接口可以不同；差异在评测配置中明确记录，既有标定率始终解释为来源参考协议下的证据。策略适配另行验证实际执行接口，不把已有标定率宣传为新策略的成功率保证。

## 5. Episode 有效性筛选

| 条件 | v0.1 规则 | 不满足时 |
|---|---|---|
| S0 合法且困难 | 来自 scene-datasets 的合法站位，`p_hat(S0) ≤ 0.20` | 排除并记录原因 |
| 对象可操作 | 同一 `scene_id + object_id + task_id` 下至少有一个合法站位满足 `p_hat(q) ≥ 0.60` | 排除该任务下缺少恢复证据的 S0 |
| Recovery 可达 | S0 到至少一个高成功率恢复区域存在合法底盘路径 | 排除无解 S0 |

阈值含等号。`0.20 / 0.60` 为 v0.1 标准值；若实验修改，须在配置和结果中标明为其他筛选设置。不得沿用旧实现的 `0.80` 高率阈值而仍标为本需求版本。

具体要求：

- 分组必须绑定具体对象；若现有 `task_id` 已唯一绑定对象，可以复用，不额外构造重复身份体系。
- 起点与高率站位使用相同初始场景、对象状态和参考标定协议，不能把不同底盘活动范围或执行预算的结果混成同一张成功率图。
- 导航合法性考虑机器人底盘/导航姿态的实际占用、碰撞、地面支撑及控制可行性；站位之间的欧氏距离近，不等于存在合法路径。
- 高率区域与 S0 不必位于固定半径内；局部搜索域须明确记录，不能把旧的 1 m 邻近规则当成 benchmark 定义。
- 每个符合条件的 S0 形成候选 episode。若规模需要抽样，显式记录候选数、保留数、抽样方法和 seed，不静默只保留最低率的一个起点。
- 无合格 S0、无高率站位、无合法路径是有效构建负结果。空 benchmark 如实输出数量和原因，不退回未标定 smoke。

## 6. Recovery Region

### 6.1 概念与 v0.1 近似

概念上，Recovery Region 是从其中启动时，参考执行器在既定标定协议下完成任务的概率显著高于 S0 的连续底盘位姿区域。执行可以包含底盘调整；该区域不等同于固定底盘即可完成操作的区域。v0.1 用离散高率初始站位及其局部邻域近似：

```text
H = {q | q 为合法标定站位，p_hat(q) ≥ 0.60}
R_approx = (所有 q ∈ H 的局部邻域的并集) ∩ 导航自由空间
```

- 局部邻域扩张半径是构建配置，不写死在 benchmark 定义中；导航地图分辨率和机器人占用处理同样保存。
- 底盘朝向影响可操作性。区域成员判定须包含 yaw，或明确记录并复用候选站位的朝向规则；不能把同一 XY 上所有朝向都默认为高率。
- 高率站位是实测证据；邻域是几何近似，不能声称扩张后的每一点都实测达到 60%。恢复诊断应标明基于 approximation。
- 扩张不得穿过障碍物把另一侧未验证空间当作同一局部恢复机会；路径终点须具有对应高率站位的合法局部连接。
- 若扩张把已知低率 S0 覆盖进去，须调整邻域/成员判定并说明，不能让 episode 在初始时刻自动被算作恢复。具体处理方式在方案阶段确定。

构建期为每个 S0 确定其可达的恢复子集 `R_reach`。只要至少存在一个合法可达恢复机会，episode 可通过路径筛选；不要求所有高率站位都可达，也不指定策略必须选择其中哪一个。

### 6.2 信息可见性

| 信息 | 策略可见性 | 用途 |
|---|---|---|
| 任务指令、正常传感观测、约定的机器人状态 | 可见 | 策略闭环控制 |
| S0 初始状态 | 由环境初始化，按正常接口可观测 | 起始条件 |
| S1 / 高率站位、标定成功率、恢复区域、oracle 路径 | 完全隐藏 | 构建与评分内部使用 |
| Path Length、Recovery Ratio、Detour Factor、Failure Pattern 标签 | 不进入策略输入 | 评测后分析与汇总 |

保存策略所需 episode 信息与评测器内部 oracle 证据的清楚边界。oracle 信息不得通过指令、候选终点、在线奖励、规划提示或可读取的辅助文件进入待测策略。具体内部文件名由方案确定，不另复制一套原始 trial。

## 7. 难度指标

难度在构建期计算，与待测策略的实际行驶结果分开。

| 指标 | 定义 | 记录要求 |
|---|---|---|
| Path Length | S0 到 `R_reach` 的最短合法导航路径的平移长度 | 单位 m；以现有导航离散化下的 A* 最短路径近似，并记录分辨率 |
| Recovery Ratio | 局部候选站位中属于 `R_approx` 的比例 | 保存分子、分母和局部候选域定义 |
| Detour Factor | Path Length / S0 到同一 `R_reach` 的最小欧氏距离 | 无量纲；分母使用区域而非随意选定的 S1 中心 |

Recovery Ratio 采用离散站位占比，不宣称连续面积占比。局部候选集合 `C(S0)` 为明确局部范围内的合法候选站位；半径或其他范围规则、朝向采样、站位间距须随配置固定。计算为 `|C(S0) ∩ R_approx| / |C(S0)|`，不能用全场景不同密度的采样混算，也不能仅在高率站位之间计算比例。

Path Length 与 Detour Factor 的距离均取底盘 XY 平面长度，路径本身仍须满足朝向与运动约束。纯转向恢复可有零平移长度，需通过 yaw 运动指标解释；欧氏距离为零时 Detour Factor 标为不适用，不人为填成 1 或无穷大。

v0.1 记录连续指标即可，不强制预设 easy / medium / hard 分箱。

## 8. 闭环执行与评分

### 8.1 执行规则

- Full policy 从 S0 开始，自主决定何时、如何调整底盘并完成操作，可交错移动与操作。
- 每个 episode 独立初始化；执行开始后不传送、不恢复到 S1、不重置对象，也不拼接导航与标定轨迹。
- 所有策略使用一致的任务定义、观测/动作约定和执行预算。记录控制步数、仿真时间、墙钟时间及结束原因；具体上限在评测配置中冻结。
- 任务成功立即按协议确认；未在预算内完成为任务失败/超时。策略不必先尝试一次失败操作，也不必按预设阶段行进。

### 8.2 指标与结果含义

| 指标 | 口径 | 地位 |
|---|---|---|
| Task Success Rate / TSR | 最终 Pick / Open 的实际任务成功比例 | 主指标 |
| Recovery Success | 执行中通过有效底盘运动进入隐藏恢复区域近似 | 诊断指标，不替代任务成功 |
| Base Path Length | 实际底盘 XY 轨迹相邻点距离之和 | 行为记录，区别于构建期最短路径 |
| Final Displacement | 最终底盘 XY 与 S0 的距离 | 行为记录 |
| Base Yaw Motion | 累积转角及最终相对转角 | 解释纯转向和朝向调整 |
| Effective Adjustment | 平移或旋转超过配置容差 | 排除控制抖动；容差随评测记录 |
| Per-case SR | 按 Case、Failure Pattern / family、Task 分组的任务成功率 | 分项解释 |
| Macro Average | 先计算各组内部 SR，再对组等权平均 | 减少组规模不均的影响 |

Recovery Success 不能只看最终位置，也不能仅凭“发生过底盘位移”判断；须由实际位姿序列验证移动后进入区域，并记录首次进入时刻。进入时采用区域朝向规则和统一容差，不把仿真抖动算作恢复。它只证明进入构建近似区域，不单独证明底盘运动造成任务成功率提升。

以下结果都需保留：任务成功但未进入近似区域、进入区域后任务失败、未移动却任务成功、移动后仍失败。低率不等于零成功率，区域近似也可能漏掉其他可操作位置；这些情况均不得篡改 TSR 或强制判为无效。

后续可选比较同一批 episode 的 **Full policy** 与 **固定底盘 policy**，使用相同任务与预算，解释移动带来的差异。它属于评测消融，不改变已有标定，也不是首版 bench 构建、运行或验收的前置任务。

### 8.3 统计分母与 Macro Average

- 每次评测明确计划 episode 总数，并记录已执行数、有效任务结论数和覆盖率。
- 有效任务结论为成功、失败或正常执行预算超时。基础设施错误、未知和未执行保持独立状态，不冒充任务失败。
- 全量任务结论齐全时，`TSR = 成功数 / 计划 episode 数`；否则正式全量 TSR 标为未知，另报有效子集 TSR 及覆盖率。
- 每组先计算 `SR_g = 组内成功数 / 组内 episode 数`，再计算 `Macro = Σ SR_g / 非空组数`。组内结果不完整时标明覆盖率，不用已完成子集冒充正式组分数。
- 分别报告 `macro_by_case`、`macro_by_failure_family`、`macro_by_task`，不把三种不同分组的数字混为一个未说明的 Macro。推荐以 `macro_by_case` 作为首版主 Macro，最终分组单位在评测前冻结。
- 分组集合随 benchmark 固定，不能评测后删除零成功组或未知组来抬高 Macro。原始总体 TSR 同时保留。

Case 是预定义场景/任务条件分组；Failure Pattern / family 是对 S0 困难原因的解释标签。标签须来自场景构造与标定证据，不根据待测策略本次失败倒推；证据不足时允许 `unknown`，不强行归因。首版标签表与单标签/多标签汇总规则待方案确定。

## 9. 数据流与最小产物

```text
已有 scene-datasets + cuRobo 逐站位标定（允许底盘移动）
  → 同 scene + object + task 汇总原始 trial
  → 筛选合法且从该站位启动的标定成功率 ≤ 20% 的 S0
  → 查找成功率 ≥ 60% 的合法站位
  → 构造 recovery region approximation
  → 验证 S0 到恢复区域的合法路径
  → 排除初始化非法 / 缺少高率证据 / 无路径样本
  → 计算难度并写 episodes.jsonl，另保存内部 oracle 证据引用
  → Full policy 从 S0 闭环执行
  → 保存任务结果、恢复诊断、真实底盘运动
  → 按 Task / Case / Failure Pattern 汇总 TSR 与 Macro
```

| 产物 | 最小内容 |
|---|---|
| `episodes.jsonl` | episode ID、场景与任务/对象引用、S0 初始化、seed、必要预算引用；一行一个 episode |
| 构建配置与内部 oracle 证据 | 标定来源引用、低/高率计数、区域定义、可达路径证据、三个难度指标、分组标签；不暴露给策略 |
| 构建摘要 | 各筛选阶段数量、保留数量和排除原因；不要求额外逐项审计附件 |
| `results.jsonl` | 一次评测中每个 episode 的任务结论、状态/结束原因、恢复诊断、底盘指标、真实 rollout 引用 |
| `summary.json` | 总体 TSR、覆盖率、分项 SR、各明确口径的 Macro、错误/未知数量 |

每阶段维护必要主记录，原始场景、标定 trial 和 rollout 复用引用，不为同一事实建立重复索引。构建配置改变时创建新 benchmark 输出；不改写原始输入或既有实验结果。

## 10. 验收标准

| 编号 | 可检查的结果 |
|---|---|
| A1 | 每个正式 episode 均有合法 S0、原始计数支持的 `≤20%` 证据、同对象同任务的 `≥60%` 证据及合法可达路径 |
| A2 | S1、恢复区域、oracle 路径与难度标签不进入策略输入；目标中没有固定 S1 要求 |
| A3 | 三个难度指标按一致配置计算；零欧氏距离等实际不适用情形有明确表达 |
| A4 | 策略真实地从 S0 闭环执行，底盘运动与操作来自同一次连续 rollout |
| A5 | 最终任务成功与恢复诊断独立；底盘路径、位移、朝向和有效调整可由真实轨迹核对 |
| A6 | 汇总包含总体、Task、Case、Failure family、明确分组的 Macro 及覆盖率，未知结果不伪装成失败 |
| A7 | 首版发布的任务家族各有至少一个满足筛选条件的真实 episode，并完成至少一个完整评测批次；未覆盖的任务不宣称已验收 |
| A8 | 验证材料至少包含一条从合法困难 S0 自主调整并最终操作成功的真实闭环记录，证明恢复执行链可用；正式评测仍保留全部成败结果 |

A8 是恢复链路的演示验收，不要求某个待测策略的所有 episode 成功，也不预设正式 TSR 的最低值。软件测试、未标定 smoke 或仅存在输出文件，均不能代替 A1–A8 的真实构建与执行证据。

## 11. 现有实现差异与待确定参数

已核对的现有实现差异：

- 现有 `select_starts` 默认低率 20%、高率 80%、附近 1 m；本需求改为高率 60%，并以可导航恢复区域为证据。
- 现有选择器未验证恢复路径、未构造 region、未计算上述难度指标；当前汇总尚无恢复诊断与 family Macro。
- 现有 benchmark 的 native/MolmoBot 标定绑定需与“cuRobo 构建参考、Full policy 独立评测”的职责对齐。
- 通用 cuRobo 配置默认允许底盘联合运动，本需求接受并复用该类标定；实现应保留其实际活动范围和预算，不增加固定底盘筛选条件。
- 当前仓库 README 记录 PandaOmron 的连续 cuRobo 链路已有真实成功，但其 VLA/benchmark 尚未接入；首版机器人及策略组合须明确，不以该连续采集成功替代 benchmark 验收。

下列参数在实施方案/配置中确定，不阻碍本文固定核心定义：

| 待确定项 | 要求或建议 |
|---|---|
| 首版机器人、策略与真实覆盖范围 | 明确采用的机器人、Full policy，以及 Pick / Open 各自对象数、场景数和 episode 目标规模 |
| 每站位有效试验数 | 沿用已有标定计划并保存计数；新增标定可采用现有默认 5 次，但不强制已有结果重跑；实测率不等于真实概率保证 |
| 区域扩张半径、yaw 规则、低率冲突处理 | 作为 approximation 配置；不得用未约定的默认值隐式决定诊断结果 |
| 局部候选域及导航设置 | 固定候选域、站位间距、地图分辨率、导航姿态和碰撞余量 |
| 执行预算、有效调整容差 | 所有策略保持一致；纯转向调整可以计入 |
| Case / Failure family 标签与主 Macro 单位 | 预先定义，推荐主 Macro 按 case，其他分组分别报告 |
| 固定底盘对照 | 后续可选评测消融；不属于标定要求或首版必须交付项 |

下一阶段优先打通“复用已有场景与标定 → 有效 episode → 自主恢复闭环 → 可解释汇总”，再扩充数量与失败类型。

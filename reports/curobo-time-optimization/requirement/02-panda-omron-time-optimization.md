# PandaOmron 实验主体与构建、标定加速需求

- 状态：active
- 日期：2026-10-24
- 替代：旧 RBY-1 20×5 口径，以及本文件此前“先跑 Panda 基线、逐项优化再实验”的安排
- 关联：[当前状况](../info/01-current-status.md)、[实施方案](../plan/01-panda-omron-time-optimization.md)、[数据集生成需求](../../build-lastmile-datasets/requirement/01-lastmile-datasets.md)

**目的：得到 PandaOmron 各初始站位的 cuRobo 实际执行成功率。** 每站位固定 3 次不同 seed 的独立 trial；加速以流程重组、公共准备复用、批量规划和并行执行为主。先完成本轮全部加速实现及必要软件检查，再统一运行全量实验；不先跑 Panda 基线、预实验或逐项性能对比。CUDA Graph 不纳入本轮。

## 1. 结果含义与实验范围

- 主体为 PandaOmron，保留已有 RBY-1 实现和结果。研究局部初始点完成任务的难度，不要求跨房间执行；首阶段为 pick，最终扩展到三个 Case 对应的 pick/open。
- 站位范围保持 `R=L`、间距 `Δ=B/4`；检查全部候选的物理合法性后，覆盖保留最多 20 点。合法点不足 20 时全部保留；可见性只记录，不作为资格门槛。
- 每个任务使用一个固定局部模型，覆盖全部站位和允许的机器人运动区域，保留目标、完整支撑、有关碰撞与视觉结构。局部模型生成新初态和新标定，不套用旧整屋标签。
- 本轮两阶段默认使用 `position-v1`，保留对应的控制、相机与物理配置；`robocasa-v1` 保留但不安排为本轮第二套主实验。
- 允许修改发现、资格检查、准备、规划、执行调度和记录的组织方式。保持的是实测成功率的含义，不要求复制旧版的调用顺序、文件生成时机或逐条轨迹。

### 已确认的两阶段实验范围

| 阶段 | 输入与任务 | 执行范围 | 结论与时长要求 |
|---|---|---|---|
| 初步正式全量 | `val103 / Cup_30 / Case2`，每任务 1 个变体 | 全部最终合法站位，最多 20 点，每点 3 次；全部加速实现及软件回归完成后统一运行 | 结果限定于该任务范围；保存各阶段与资源池实测耗时，不先抽点预跑 |
| 最终全量 | 固定清单的 100 个 val 来源场景，启用 Case1、Case2、Case3；每任务/Case 1 个变体，Case3 沿用每个 open 目标保存一次的语义 | 按各来源场景实际合格目标生成 Case；每个 accepted 派生场景的全部最终站位各 3 次 | 启动前给出构建、标定及按需视频的时长预估；报告三类 Case 的覆盖、缺项和原始结果 |

100 指输入 val 来源场景数，不等于 100 个 accepted 派生场景，也不保证每个来源都有三类合格任务。名单、目标选择数量与规则在最终运行前写入有效配方；最终 pick/open 目标按各自资格发现，不把 `Cup_30` 选择器推广到所有房屋。无合格目标、构建 rejected 和未完成分别保留，不通过替换来源或补造任务凑齐产出数。

初态采用每站位真实静置后的共享状态，三次 trial 独立创建；采用下文的 300 s 活跃规划/物理执行软预算。这些默认值已由用户接受，后续按本协议实施。

## 2. 每站位 3 次与有效成功率

计划量为 `N×3`，`N≤20`，满 20 点为 60 次。seed 按稳定站位索引定义，不随 worker、batch slot 或完成顺序改变：

```text
seed = config.seed + station_index * 3 + trial
trial = 0, 1, 2
```

三次试验可共用只读模型、同一份准备初态、候选几何和规划资源；各有独立 Simulation/MjData、规划随机流、真实执行与结果。一次规划结果或任务失败不能复制成三次结果，内部 IK/TrajOpt seeds 也不能计作物理 trial。

成功率读取原始有效 trial：`successes / evaluable_trials`。完整站位应有 3 个有效结果；基础设施错误、仿真/记录错误和未知保持原分类，缺项即标定不完整，不补失败或隐式追加直到成功。

| 原始有效结果 | 实测率 | 解释 |
|---|---:|---|
| 0/3、1/3 | 0、1/3 | 低率集合，作为困难初始点候选 |
| 2/3 | 2/3 | 中间组，不进入低率或高率集合 |
| 3/3 | 1 | 高率集合，作为恢复目标点候选 |

低阈值确定为 `lastmile_low=1/3`，高阈值确定为 `lastmile_high=1.0`，比较均含等号。完整 3 次标定中，0/3、1/3 进入低率集合，仅 3/3 进入高率集合，2/3 保留为中间组。JSON 中低阈值写为 `0.3333333333333333`，不截成 `0.33` 而排除 1/3。仅完成 1 次且成功的结果不能冒充 3/3；不完整标定仍不参与正式配对。

有限样本不代表精确成功概率。搜索先显式保持 32 IK seeds、4 TrajOpt seeds、最多 16 个候选和原生重试预算；流程重排不靠静默减预算获取收益。

相对旧 RBY 5 次协议，计划数少 40%；相对调整前 Panda 的 2 次协议则多 50%。旧结果不改写为新 3 次结果。准备初态、随机流组织或预算计时改变后，记录新协议，不能声称与旧版逐 trial 完全等价。

## 3. 可修改的加速流程

| 环节 | 本轮要求 |
|---|---|
| 场景构建 | 任务元数据和几何只解析一次；复用同模型的候选检查；物理筛选后再对最终点记录可见性；增强仍保留真实静置和必要校验 |
| 公共准备 | 同站位准备并真实静置一次，形成明确的操作初态；三次独立 trial 从这份状态创建，不各自重复相同静置 |
| 规划 | 缓存机器人/静态世界/候选；同站位闭爪前按 3 个独立 seed 批量规划，闭爪后按各自实测状态继续规划 |
| 调度 | 站位队列、多 worker、常驻资源；共享任务与独立试验状态分开，父进程唯一写主 trial 记录 |
| 记录 | 成功率标定默认不逐帧渲染 RGB/深度或编码视频；保存 cuRobo 规划轨迹、真实执行状态、场景与相机信息，支持事后离线生成视频 |

公共准备发生在操作试验开始前，记录实际准备后底盘位姿、目标/场景状态和控制状态。若准备中初始点失效，保留准备错误，不复制成三次操作失败。已有开始执行的 Simulation 不恢复、不重置、不传送；共享准备状态只能用于创建新的试验实例。

任务成败仍来自真实物理执行与完整判定，物理步长、任务证据频率、支撑/碰撞和局部运动约束沿用所属 profile。必要的共享故障停批和批量失败隔离保留。

### 离线视频复现必须可用

关闭在线渲染只省掉当场图像生成，不能省掉回放所需数据。所有实际执行的 trial（成功、失败、超时均包括）至少保留：

- cuRobo 各规划段的关节名、参考坐标系、目标关节序列、时间间隔、阶段和对应 trial，包含闭爪后规划；批量输出按 trial 归属保存。
- 初始帧及每个实际控制步后的整场景状态与时间戳，覆盖机器人、目标物和其他动态物体；保存完整积分状态及必要控制信息，不能只存机器人计划关节角。
- 固定场景模型、可读取的 mesh/texture 资产引用、MuJoCo 版本、站位准备初态，以及所选相机的名称/位姿/内参、尺寸和播放时序。模型每场景保存一次，trial 引用，不为每条轨迹复制资产。

离线使用独立渲染数据逐帧恢复实测状态，执行 `mj_forward` 后输出所选相机视频；不重新规划或物理积分，不触碰已经开始的在线 Simulation，不改变原成功率。规划轨迹另外用于查看计划和执行偏差；只按计划关节角生成的动画须标明规划来源，不能当作物体抓取后的真实执行视频。

视频数据可回放是标定交付条件，数值结果就绪时所需资料必须已写完；视频本身按需在标定结束后生成，单列耗时。无实际执行步的 trial 保留初态和规划结果，不补造执行视频。现有 E01 未满足逐像素一致标准，本轮需实现并验收运动、物体状态、相机和时序正确的视频回放；不把该要求直接宣称为训练图像逐像素还原已通过。

成功率交付不再以成功训练图像全部就绪为前提。视觉示教采集或离线观测导出仍需按用途检查模态和渲染结果；纯数值标定结果不得自动标成视觉训练数据已齐全，也不通过视频回放补造新试验标签。

## 4. 统一全量实验与验收

本轮实现范围固定为：构建去重与局部模型、同站位公共准备、规划静态资源复用、同站位批量规划、站位并行，以及支持离线视频复现的成功率专用记录。全部实现覆盖 Case1/Case2 的 pick 与 Case3 的 open，包括开门过程中的世界更新、阶段查询和记录。先完成全部改动与软件回归，再跑初步正式全量，之后完成最终 100 个 val 场景的提前估时，再开展最终全量；每个 accepted 场景覆盖全部最终站位及各 3 次 trial。实际视频回放验收使用对应正式运行产生的轨迹，不新增前置 Panda 预实验。

最终全量的估时先使用初步阶段实测规划/执行/构建耗时和 100 个来源场景的任务清单，报告正常与保守情景、G/CPU 并发、构建与标定及按需视频时间。Case1、Case3 未测的成本显式列出假设；不能只把单个 Case2 墙钟乘 100。最终场景库构建后，按 accepted 派生场景和最终站位数更新标定预计时长，随后再启动该阶段标定。估算不增加额外抽点 rollout。

| 阶段 | 目标 | 必须报告 |
|---|---|---|
| build-scenes | 降低重复解析、采样、编译及失败搜索成本 | 总墙钟、accepted/rejected、候选/验证次数、每 accepted 场景成本 |
| cuRobo 标定 | 单场景满 20×3 的成功率结果及视频回放资料就绪 ≤30 min，作为待验证工程目标 | 原始 trial、各点分子/分母、录制/回放资料完整性、任务结果、总墙钟和分项 |
| 全量实验 | 所选场景均有明确构建状态，accepted 场景均有完整执行覆盖或真实中断原因 | 构建与标定分别计时及总时间、资源配置、场景/站位覆盖和缺失原因 |

资源加载、公共准备、队列等待和收尾计入实际总墙钟。新协议将 300 s 软超时用于每 trial 的活跃规划与物理执行，公共准备、排队、结果写入另计；批量调用整次耗时计入每个参与 trial，不按 batch 大小摊薄。搜索次数、仿真时长和原始墙钟分别记录，不能因 I/O 或排队位置不同悄悄改变失败定义。没有新旧配对基线时报告新流程绝对耗时，不编造加速倍数。

## 5. 本次文档边界

本次仅将用户确认的两阶段范围、`position-v1` 默认值和最终运行前估时要求同步到文档，不执行实施计划、软件回归或 Panda 实验，不修改代码、运行配置或既有结果。读取到的两份 Panda 执行 JSON 已含每点 3 次及 1/3、1.0 阈值；流程能力的完成状态仍以实际实施验收为准。CUDA Graph、GPU 物理后端迁移和本轮额外异步图像系统不列入实现范围。

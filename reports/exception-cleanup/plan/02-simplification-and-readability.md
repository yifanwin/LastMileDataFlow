## 目标与范围

继续在 `.worktrees/exception-cleanup`、`refactor/exception-cleanup` 分支实施，保留上一轮已有改动。按调用链整理当前维护的六个源码领域、共用入口和相关测试；不移动目录，不修改历史归档、外部资产和既有实验数据。

目标是实际减少重复判断、状态维护、资源包装和阅读负担。可读性改进贯穿每批修改，不单独做全仓排版。允许代码行数增加，不给异常关键字、上下文工具或函数长度设置数量指标。

## 实施规则

- 一个约定在真实输入边界检查一次；内部按明确约定直接使用。删除检查前先看生产调用方，不能把测试中缺少字段的临时对象当成生产接口必须兼容的格式。
- 删除没有调用方的内部代码、可以证明重复的分支和无意义的默认值；保留真实可选字段和后端差异。没有读者的诊断字段也不直接据此删除，仍需遵守现有输出格式。
- 资源的创建、使用和释放应容易定位；一个资源有明确的主要释放位置。必要的异常路径收尾用简短 `finally` 表达，不为消除语法另建管理器、装饰器或上下文协议。
- 原生支持上下文的文件、连接、读写器直接使用 `with`。`closing` 和 `ExitStack` 只在能明显简化实际生命周期时保留，不能批量替换或批量恢复旧写法。
- 短变量仅限含义明确的局部数学运算。模型、状态、关节索引和数据地址使用有含义的名字；分号、多层三元表达式和嵌套构造调用展开成顺序步骤。
- 仅在一段代码具有独立职责或消除实际重复时提取函数；不创建只转发参数、改名或返回一个字典的包装。

## 第一步：删除明确的冗余逻辑

先处理叶子模块和执行器中容易确认的重复，不同时重做生命周期。

| 位置 | 具体动作 |
|---|---|
| `runtime/execution/lifecycle.py` | 删除当前没有调用方的 `episode_phase()`；检查重复读取当前 scope、反复复制结果字典和重复设置相同标记的逻辑 |
| `runtime/execution/vla.py` | 在核对循环所有出口后，删除与 `for/else` 重复的 `unfinished → policy_step_budget_exhausted` 兜底；统一重复计算的初始监测信息等局部值 |
| `scenes/stations/sampling.py` 及相关配置调用方 | 对已由配置对象保证存在的字段直接访问；保留实际可选参数，不为单测临时对象维持无必要的 `getattr` 默认值 |
| 其余加载、控制和结果处理模块 | 清理同一调用链上的重复校验、重复转换和无恢复意义的异常包装；真实负结果仍按现有业务分支表达 |

每次删除都应能说明对应约定由哪里建立。对不能确认是否必要的物理检查，先保留，避免把本轮扩大为协议和算法重设计。

## 第二步：简化资源生命周期

先确定所有者，再选写法。优先处理上轮加入的多层资源包装，不新增平行清理链路。

| 资源 / 模块 | 预定处理 |
|---|---|
| `sample_stations` 的 renderer 与逐候选 probe | renderer 由采样函数释放；probe 在本次候选结束时释放。优先撤掉单个可选 renderer 使用的 `ExitStack`，保持逐候选收尾清楚、及时，不积攒全部 probe |
| `collection.py`、`station_dataset.py` 的单个场景 Simulation | 拆开长构造表达式，使场景创建和处理可直接阅读；无收益的 `closing` 改为局部、简短的收尾，不再叠加资源登记 |
| `lastmilebench.py` 的 parent / native Simulation | 明确原始场景与派生场景的所有权；π0.5 路径只释放同一个实例一次。优先使用直观的局部收尾，减少 `enter_context(closing(...))` 嵌套 |
| `benchmark_replay.py` 的 Simulation 与两个固定视频 writer | writer 使用已有原生上下文；Simulation 在本次重建结束时释放。避免用通用资源栈表达固定的两个输出 |
| `edit_views.py` 的 renderer 与模型 FOV | 将模型原始值、渲染器创建、状态恢复写清楚。重点简化匿名恢复回调；若部分创建失败和共享模型恢复用局部 `ExitStack` 更清楚，可保留该局部用途 |
| `scene_preview.py` 的可选前后场景，以及其他现存 `closing` | 按相同标准检查；确有收益的原生 `with` 或局部资源工具保留，不机械追求清零 |

已有 episode 隔离层继续负责 attempt 中登记的 Simulation、记录器和执行日志；工作流自己的基线场景不交给 attempt 释放。正常流程中如果必须提前刷新或关闭文件，保留该时序；否则合并重复收尾。

## 第三步：整理执行隔离与记录器

这一批涉及真实结果语义，在前两批稳定后单独处理。

- 把 episode 执行、错误分类、记录收尾、资源释放、结果合并按顺序写清楚。保留一个通用故障分类边界，不再增加新的异常适配层。
- 将 `cleanup()` 中记录器的特殊处理与普通资源循环区分清楚，减少循环内对同一个对象身份的重复判断；不扩展成通用资源类型系统。
- 结果在必要位置更新一次，减少整份字典反复重建；保留现有主记录字段、未知结果与错误证据。
- 检查记录器的 `finalizing`、`finished`、`result` 分别承担的职责。它们当前区分“写入已开始”和“写入已成功”，不能直接当作重复布尔量删除；只有能够用更少状态完整表达时才合并。
- 保持最终写入失败后不重试同一条轨迹、中断继续传播、部分物理步保留、单个资源关闭失败后仍处理其他资源、共享故障停批。

## 第四步：把密集代码整理成人可读的流程

优先修改 `runtime/construction/state.py`、`runtime/execution/curobo.py`、`vla.py` 和本轮实际触及的资源管理函数，再检查其余六个领域中的同类写法。

- `state.py` 按关节、执行器、body、等式约束和全局状态分段；将 `m0/m1/d0/d1` 改为 `old_model/new_model/old_data/new_data` 等含义明确的名字。数组宽度与地址拆开赋值，不改状态迁移算法和按名称匹配规则。
- 两个执行器清楚呈现“准备 → 导航 → 操作/策略循环 → 判定 → 保存结果”。展开多层状态选择和密集字典，局部变量表达实际含义；保留后端之间真正不同的行为，不新建统一执行器。
- 将渲染器、快照和 writer 的长嵌套创建表达式拆开。注释解释物理约束、动作语义与必要时序，删除重复叙述代码或夸大防御必要性的注释。
- 对配置、策略客户端、规划与导出中的相同问题按生产调用链处理，不批量格式化引入的推理核心，不顺带修改模型算法。

## 1. 修复目标与范围

修复合法 S0/S1 被整机外接圆膨胀栅格屏蔽的问题。推荐采用 **真实几何局部连接 + 现有 A* 全局绕行**，train 和 benchmark 共用规划结果，执行器消费规划给出的完整 XY/yaw 路线。

本轮方案不重新标定、不改模式标签和 S1 优先级，不增加 CLI。已有 run 保留；实施已完成并使用原标定构建新 run，实际改动、367 项软件回归及四条物理导航结果见[修复交付](../delivery/07-navigation-geometry-fix.md)。本文以下保留方案与验收口径，结果以交付报告为准。

用户后续已明确撤销本文的 20 mm 硬门槛，改为“实际到达且无严重碰撞，20 mm 仅用于软代价选路”，见[净空软目标需求](../requirement/02-navigation-soft-clearance.md)。本文保留为上一轮实现方案；新需求的实现与验证见[软净空交付](../delivery/08-navigation-soft-clearance.md)。

不采用缩小机器人半径、删除桌子障碍或强制把起点格置 free 的办法。保守栅格仍适合开放空间的快速搜索，问题在于不能用它否定真实几何合法的近桌站位。

## 2. 共用局部几何检查

在 `planning/navigation.py` 增加一个小型共用模块，负责位姿边检查和路径拼接；网格算法保留在 `planning/astar.py`。

输入为源初始化、实际 base/yaw、目标姿态和现有导航配置。源手臂、升降、夹爪在导航时保持不变；终点必须在该保持姿态下合法，并与引用的 S1 初始化协议一致。若不一致，明确记录，不通过初始化重设关节来补齐。

几何查询使用独立的准备态 Simulation/MjData，复用原模型和物体状态；可复用现有 `clone_preparation`。只调用初始化和 forward，不积分，不修改执行中的实例，也不修改共享模型的碰撞参数。

每条候选边明确给出起止 `[x, y, yaw]`，XY 线性插值、yaw 采用最短角连续表示；检查间隔先沿用复核中的 **≤1 cm、≤1°**。检查地面支撑、实际整机碰撞及环境净空；需要的距离查询复用仓库已有 `mj_geomDistance` 用法，只检查邻近且碰撞规则允许的机器人—环境 geom 对，排除已有允许的轮/底盘—地面接触。

**保留 `navigation_margin_m=0.02` 的含义，不把“没有接触”当成“有 2 cm 余量”。** 已有合法端点若不满足余量，记录 `endpoint_clearance_below_margin`，不自动降低阈值。上轮七条路线的 363 个位姿尚未测量此项，所以不能预先承诺新 benchmark 一定得到七个 episode。

检查返回是否通过、首个阻塞位姿和测得的最小环境净空，复用主记录保存必要结果，不建立逐位姿审计清单。有限采样属于工程近似，动态执行仍须单独验收。

## 3. 路线生成

按同一保持关节姿态处理一组配对，利用每任务最多 20 个已有合法站位：

1. 将实际站位 `[x, y, yaw]` 作为节点；按真实几何检查站位间直连边，结果在本次规划中复用。
2. 在通过检查的边上做最短路搜索。这样 Cup 的六条直连路线和 `S0042 → S0041 → S0044` 都能作为候选，无须硬编码 station ID。
3. 对局部图仍未连通的配对，将站位通过真实几何检查的短连接接入原保守自由栅格，再用现有全房间 A* 绕行。短连接包含明确朝向；候选连接按距离排序，并受局部范围与查询预算限制。预算不足或未找到连接不称为真实场景无路。
4. 拼接后再按执行采用的 XY/yaw 规则检查整条候选路径，包含端点连接、旋转和最终到达段。输出路径平移长度及 yaw 行程。

这不是对连续配置空间最短路的保证；难度中的路径长度明确表示该离散候选图找到的参考路线长度。没有找到路线时保留负结果，不补造轨迹。

路径以 `poses: [[x, y, yaw], ...]` 为执行依据；绘图所需 `xy` 从它直接投影，不另算第二条路线。train 的配对和 benchmark 的 oracle 使用同一返回结构。

## 4. 同步修改执行与恢复区域

### 4.1 执行器

修改 `runtime/execution/navigation.py`，逐点跟踪规划的显式 XY/yaw，删除按 `index / (len(points)-1)` 重建 yaw 的处理。速度、单步限幅和到达容差保留。

规划器与执行器共用导航角度差函数，不为此更改操作规划的关节角语义。最终对齐也必须属于检查过的路线；实际状态偏离参考时记录跟踪误差，不重置、不传送。

导航阶段利用已有物理子步回调记录实际接触。发生明确环境穿透时按现有初始化几何阈值终止当前导航，写 `navigation_collision`；不改变操作阶段已有的接触记录协议。它不能保证碰撞前停车，作用是避免发生碰撞后仍将导航报为成功。

### 4.2 benchmark 恢复区域

修改 `data/evaluation/recovery.py`：合法实测 S1 作为精确锚点保留，不能再因公共保守栅格的 `free=false` 被直接删除。

保留现有恢复半径、yaw 容差、最近实测站位裁剪和标签合格 S1 集合。在每个锚点周围的小范围内，预计算按真实几何、锚点保持姿态与朝向检查通过的局部位姿单元及到锚点连接；与原保守自由区域相接。只在这些局部有效单元内扩展恢复区域，不画一个无条件可恢复的圆盘。

`goals`、`contains`、路径难度和 `motion_diagnostics` 读取同一套区域表示。保存到现有 `oracle.json`，包含几何方法与分辨率，不要求离线统计重新运行 MuJoCo。yaw 维度同样要检查，不能仅凭锚点 yaw 合法就推定整个 yaw 容差区间都合法。

精确锚点和局部单元连接到同一个参考图后，才能计算恢复比例和路径长度。不得只修改 episode 筛选、却让后续 `contains` 继续用旧栅格否定相同终点。

## 5. 文件改动与失败原因

| 文件 | 改动 |
|---|---|
| `planning/navigation.py` | 共用真实几何边检查、站位图、到保守栅格的连接和显式位姿路线 |
| `planning/astar.py` | 保留现有栅格搜索；按需提供连接所需的节点/距离接口 |
| `workflows/collection.py` | `_recovery_trials` 使用共用导航结果，保持完整 pair 分母 |
| `workflows/lastmilebench.py` | 使用相同路线与局部恢复区域，拆分筛选原因 |
| `data/evaluation/recovery.py` | 锚点/局部区域表示及统一的恢复判断、难度统计 |
| `runtime/execution/navigation.py` | 跟踪显式 yaw，复用现有物理步与记录链 |
| 当前格式说明及相关测试 | 描述路径、oracle 区域和新增原因；不维护内部旧路径兼容壳 |

失败原因至少分为：

- `initialization_invalid`：实际源/终点初始化非法。
- `endpoint_clearance_below_margin`：实际端点不满足配置净空。
- `recovery_region_empty`：选定 S1 没有合格恢复目标。
- `local_connection_not_found`：有限候选内未找到局部连接。
- `navigation_search_exhausted` / `navigation_search_budget_exhausted`：离散图搜索无解 / 查询预算耗尽。
- `navigation_tracking_timeout` / `navigation_collision`：执行超时 / 实际碰撞。

`conservative_start_blocked` 作为诊断字段保存，不再直接当成最终“无导航路径”。以上均描述本方法和预算内的结果，不声称连续空间不可达。

## 6. 实施顺序与验收

### 第一步：离线规划与执行协议

先实现共用检查器、站位图和显式 yaw，再接 train、benchmark 与恢复区域。测试只覆盖实际问题：合法站位被圆柱屏蔽但真实边合法、直连碰撞而经中间站可达、旋转中碰撞、真实墙体阻断、净空不足、规划 yaw 被原样执行，以及恢复区域保存/重载一致。

先跑相关领域测试，再按仓库要求跑全套离线回归；报告软件验证与真实任务验证的区别。

### 第二步：Cup 原快照复核

复用 Cup r02 原始 trial/诊断，创建新的 benchmark run；不重新标定。

- 原七个 S0 都必须进入真实几何检查，不能在保守栅格入口被直接排除。
- 七条已知候选路线作为回归参照，逐条报告实际净空及去留；S0042 的直接碰撞路线必须被拒绝。
- 同一终点在规划、保存/重载后的恢复判定中结果一致。
- 输出 candidate、eligible、written 和逐原因排除计数；不以“必须七条全收”为通过条件。

### 第三步：实际导航

先选一条满足余量的 Cup 短路线运行独立连续 attempt，再验证需要分段绕行的路线。只验证导航时可在 S1 到达后结束诊断 attempt，不冒充完整采集成功；需要完整示教时继续由现有操作链执行。

验收分别报告：路径几何检查、实际导航到达、跟踪误差/接触、记录完整性、后续操作结果。每次物理试验使用新 Simulation 和 attempt，只有实际导航到达且记录完整才能记导航成功。若跟踪失败，针对实际误差修复，不先调整操作容差。

### 第四步：Train / Open 扩展复核

共用修复通过 Cup 后，复核原 train 的 13 对和 Open 的 7 个候选。先重新规划，确认通过后再运行必要的独立导航试验；已有跟踪超时按新结果定位，不将 Cup 的改进外推成 Train/Open 成功。

## 7. 本次方案编写结果

核对了导航生成、连续执行、恢复区域和统计四处调用。除已知的保守栅格误拒绝外，确认执行器会自行插值 yaw、恢复区域会再次过滤 S1，已将两处纳入同一修复范围。方案已执行；详见[修复交付](../delivery/07-navigation-geometry-fix.md)，不将导航成功升级为完整操作任务成功。

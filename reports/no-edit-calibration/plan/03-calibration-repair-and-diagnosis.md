## 5. N2：先修测量方法，不继续全场景随机采样

本节是已完成工作的设计和问题历史；当前实现与实测结论以交付第 7.3 节为准，旧脚本问题不再作为待修事项。

文件入口：`scripts/experiments/p2_collision_diagnosis.py`。

### 5.1 确定需要改的脚本问题

1. **路径与变换复用**：从 `planning.robots.panda_omron` 的资产/配置入口读取球，不再拼旧路径。主比较使用当前 planner 的 FK 球心和有效半径；CPU 对照从实际 MJCF body 变换获得对应部件的位置，显式计入 torso 和 base yaw/平移。
2. **障碍集合一致**：使用本 query 实际导出的 environment/target/handle geom 集合及范围。当前脚本自设 REACH_M、3D 距离筛选，而生产导出是另一范围下的 XY 筛选；`sim.planning_geometry` 是缓存，不是本 query 的完整成员清单。Open 加载时还需绑定当前 handle。
3. **对应物理部件**：区分底盘 box、固定柱、随 torso 移动的升降柱、link0。比较同一个候选状态、同一障碍 geom，不能将“全体球的最小值”和“不同实体障碍对的最小值”相减来宣称误差。
4. **符号**：现有 `closest_point` 只给表面距离。球心在闭合实体内部时，正的“表面距离减半径”也可能是假阴性。保留该数值时改用明确名称，不能标成可行性真值；碰撞判定优先读实际 cuRobo checker，并与可靠物理窄相位/解析结果比较。
5. **停止不可靠替代**：`mesh_clearance()` 每个 geom 对随机采 4000 点，反复建立查询，又只用 scene 顶点是否落入 robot 内判相交。它既慢，也会漏掉面/边相交及反向包含；不能靠固定 seed 或增加采样数把它变成精确测距。

旧 distances 的 physical 字段继续标为无效；保存原文件，不回写伪造数值。新结果只需一个主 JSON 和必要图，字段表达该值是 signed distance、表面距离、截断界还是 unavailable。

### 5.2 `mj_geomDistance` 返回 0 的优先定位

不要先认定 API 不能用。MuJoCo 3.5.0 [API 文档](https://mujoco.readthedocs.io/en/3.5.0/APIreference/APIfunctions.html#mj-geomdistance)规定该函数返回有符号距离，上限为 distmax，未发现更近结果时返回 distmax；因此应核实调用是否把 0 当作“无限距离”，以及 fromto 是否实际有效。

官方同时明确指出 legacy CCD 的距离可能不准确，native CCD 路径行为不同，见[距离计算说明](https://mujoco.readthedocs.io/en/3.5.0/computation/#geom-distance)。这是排查依据，**尚未证实当前错误由 CCD 设置导致**。

最小定位步骤：

1. 用已知分离/相交的简单 box 对确认距离符号和调用参数，再取一个原来“远处返回 0”的实际 box/cylinder–mesh 对复现。
2. 记录实际 MuJoCo 版本、geom 类型/id、世界位姿、distmax、fromto 和当前模型 CCD flags。区分截断返回值、精确相切、异常的零值，不把所有零都当接触。
3. 若版本与模型配置支持，在独立诊断模型比较当前 CCD 和 native CCD；不修改生产模型选项、不更换正式物理设置。先验证真实原状态的 `mj_forward` 接触对和距离是否一致。
4. 若可靠距离仍不可用，优先取 val103 墙与物理 box 的实际几何做解析/凸体窄相位对照；先检查实际 geom 类型，不能仅因名称为 wall 就假设它是平面。包围体完全分离可证明这一对不相交，但包围体重叠不能证明碰撞。

不求整屋所有 geom 对的精确最小距离。先针对球命中的障碍和其附近可能相交的机器人部件，以保守包围体筛掉明显远离的对，再做窄相位。只检查几个命中对足以解释该局部差异；宣布全机器人无碰撞时，仍需完整的有效接触检查。

### 5.3 三种几何含义不能混为一谈

- MuJoCo 编译后的碰撞表示及接触过滤，是实际仿真使用的物理模型。
- 导出的三角网格与 cuRobo checker，是规划器实际使用的环境表示。
- 视觉 mesh 只是辅助判断导入尺度与外形。

MuJoCo 的凸 mesh 碰撞与原始非凸三角网格可能不同；这类分歧先归为表示差异，不能一律叫球太大。对非闭合 mesh 不强求统一的内部符号，不把表面采样估计标成精确穿透深度。

### 6.1 必须观察实际失败状态

在当前修复版重新请求同一准备态/目标/seed；若原失败已消失，记录为“绑定修复后不再复现”，不要强行把它保留为碰撞故障。

对仍失败的 query，诊断模式仅保存：

- 初始 q；当前 lane 下代表性 IK 候选 q、目标姿态、位置/旋转误差、约束可行性及 seed/goal 索引。
- 轨迹失败时保存实际候选轨迹，并找出约束最强的时间点；不能只检查 t=0 或终点。
- 对 pose 已收敛但不可行的候选，重点检查发生冲突的球、具体障碍和对应物理几何。

通过现有 `curobo/tracing.py::SolverTrace` 定向取证，不保存所有任务所有 seed。新建未 begin 的诊断 sim 恢复各候选状态，不改 live rollout 的 qpos。候选没有被接口返回时，明确 unavailable，不能把实际已执行轨迹当作失败候选替代。

### 6.2 核对原有“最大连杆 cost”统计

`SolverTrace.link_costs()` 当前使用 `value[seed_idx, 0]` 并按 link 求球 cost 之和。需对实际 tensor 维度、seed/lane/goal 对应和第二维含义做一次核对：

- 不能把选出的 seed 集合当作全部 seed；不把不同候选的最小位姿误差与最大碰撞值拼成同一状态。
- 若第二维确为 horizon，则索引 0 不能代表整条轨迹峰值。
- 多球 link 的累计 cost 更容易较大，最大累计项不是“该连杆独立造成无解”的证明；补看球数量、最大单球值及原生 feasible 标记。

本轮只校准代表样本的解释，不先重扫 58k trial 的历史统计。

## 7. N4：有同状态证据后再修改

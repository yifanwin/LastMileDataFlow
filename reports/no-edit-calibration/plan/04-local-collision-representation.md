# 局部 Pick / Open 标定：消除碰撞表示假失败的实现方案

- 状态：draft（实现方案；本轮未修改生产代码、未运行新实验）

- 替代：[03 修复方案](03-calibration-repair-and-diagnosis.md)中尚未实施的局部碰撞表示工作顺序；保留历史修复结论
- 关联：[局部碰撞需求](../requirement/02-local-collision-representation.md)、[交付报告](../delivery/04-calibration-repair.md)

## 1. 目标与实现决策

**目标：实体具有足够操作间隙时，不因碰撞表示的外扩、错误符号、填平空隙或过期位姿而规划失败。** 以当前 MuJoCo 实际碰撞几何为参照，同时保留真实碰撞约束。性能优化必须在几何正确的候选之间比较。

工作目录为 `.worktrees/no-edit-calibration-val0-99`。沿用已有站位、seed、初始化状态、目标候选和任务预算，不调整采样半径、间距或任务成功判据。

采用以下顺序，逐步增加变量：

1. **先修机器人表示**：固定柱和升降柱优先；随后收紧底盘在小间隙处的外扩。环境保持当前版本，直接解决五个近站位的已知起点误拒绝。
2. **再改环境表示**：物理 box 直接输出带位姿的 cuboid；关键复杂部件保留少量独立封闭几何，正确组合各自查询结果，保留家具结构空隙。
3. **按实测需要引入静态局部 ESDF**：解决复杂背景部件多、独立查询慢的问题。目标、把手及运动部件继续使用精细独立表示。
4. **完成固定样本的规划与真实执行对照**，再决定生产默认配置。CoACD 不作为本轮前置依赖。

不承诺有限球集或有限分辨率栅格在任意小间隙下都零误差。对已知决定成败的间隙，必须收紧表示并验证；仍存在争议的拒绝保留为“表示误差未解决”，不能直接解释成站位物理不可操作，也不能把离线复核通过当作任务成功。

## 2. 基线与归因口径

基线是当前的任务绑定修复、51 个底盘球、逐 geom 凸包后合并成一个环境 mesh。已知它消除了部分假碰撞，但柱体过粗、重叠内部符号和近接触误差仍未解决。交付报告第 13 节的结果作为历史对照，不重做已经完成的完整 P1。

每个争议状态在同一份诊断结果中记录：场景/站位/seed、规划阶段、状态来源、机器人部件、障碍 geom、实体距离、球表示距离、buffer 及实际可行性结论。复用现有诊断 JSON，不另建数据索引。

必须区分三项：

| 项目 | 含义 | 本轮处理 |
|---|---|---|
| 实体占用 | MuJoCo 实际参与碰撞的形状和位姿 | 作为参照，保留真实相交 |
| 表示误差 | 球外扩、离散化、几何填平、SDF 错符号 | 修正，不能自动视作安全需求 |
| 明确的余量 | 当前 2 mm sphere buffer，以及独立的优化 activation 设置 | 首轮保持；分别记录作用，不把 10 mm activation 当作实体厚度或直接等同硬拒绝阈值 |

实际测距达到截断上限时只能给距离下界；无可靠距离的状态保留未知。起点、IK 目标和失败轨迹中段分别比较，不能用 `rejection_geometry` 的最差轨迹状态替代初始状态。

## 3. A：固定柱、升降柱与底盘球

### A1. 几何与坐标对齐

沿用需求文档第 8 节已核实的形状：固定柱为半径 0.12 m、高 0.40 m 的圆柱；升降柱为半径 0.1125 m、高 0.40 m 的圆柱。前者归属 `omron_base`，后者随 `panda_link0` 运动。机械臂底座是另一个 mesh，不与升降柱一起按圆柱处理。

从 model 的 geom 形状/尺寸/局部位姿生成候选，转换到实际规划 link frame。验证初始姿态及升降行程的两端和中间位置，排除把升降柱错绑到固定坐标系的问题。环境端核实桌子 `collision_1/4/5` 的实际形状与变换，核实前只使用 geom 名，不把高度推测写成桌腿/横梁事实。

### A2. 柱体采用可控覆盖，复杂机械臂采用官方拟合

圆柱先尝试按轴向分段的覆盖球：对半径 R、段高 h 的圆柱段，中心置于段中心，半径 `sqrt(R² + (h/2)²)` 可覆盖整个圆柱段。增加段数可以减少侧向外扩，但**不能消除端部约 R 量级的外扩**，因此不能仅凭侧向指标采用这一方案。

如果端面外扩影响桌面/机械臂附近空间，改用端部细分的三维覆盖候选：把圆柱体分成较小区域，使用覆盖各区域的球，优先细化外侧和端部。复用底盘覆盖脚本中的评价和写出逻辑；只在简单覆盖明显冗余时使用候选集合的 ILP 精简，不要求全局最少球数，不手写另一套 MORPHIT。

机械臂底座、臂 link、夹爪或携带物如发现实际拟合问题，使用当前安装版本的官方 `fit_spheres_to_mesh`，优先比较 MORPHIT；VOXEL/SURFACE 作为对照或退化网格的备选。官方覆盖率指标用于筛选，不能单独证明实体完全覆盖；补充关键表面和实体覆盖验证。安装版参数名以现有代码和函数签名为准，不照抄不同版本文档。

所有候选统一比较：

- 最终写入的球是否覆盖实体，包括 YAML 舍入影响；区分构造性覆盖证明和有限采样检查。
- 未加 buffer 的拟合外扩与加 buffer 后的最终外扩；圆柱同时检查径向和上下端面，不能只看世界轴包围盒。
- 球数、同一查询耗时、已知争议状态是否被正确接受，以及真实相交是否仍被拒绝。

不统一缩半径，不删除柱体球。柱体修改先独立对照；没有证据的臂 link 暂不重拟合。球数变化时同步 `PARTS` 的分组，仍保留简单的数量检查。

### A3. 底盘继续收紧，51 球不是最终精度标准

S0008、S0012 的底盘到桌下部件仍有约 1.4–1.6 cm 间隙。现有约 3.6 cm 外扩足以误拒绝这些状态，不能仅以“保守设计”结束排查。

复用 `n4_chassis_spheres.py` 生成更紧的覆盖候选，分别控制侧面和顶面外扩。以这些真实间隙减去显式 buffer 后的剩余空间确定候选精度，先在诊断中筛选，不预先锁定某个球数。优先减少无用内部重复和不影响覆盖的冗余，再比较细化的成本。

生成的是适用于该机器人构型的统一球模型，不按站位或目标桌子临时删除/缩小球。若球数增长使 Open 不可接受，保留这个明确的精度/性能瓶颈，再评估更局部的覆盖布局；环境 ESDF 无法消除机器人球本身的外扩。

**A 完成条件**：五个近站位的起点不再因已确认的柱体外扩被拒；底盘小间隙拒绝有同状态的独立结论。起点若仍不可行，列明剩余真实碰撞或尚未解决的表示误差。目标 IK 和最终任务成功另行记录，不要求五站全部成功才算柱体修复有效。

## 4. B：结构化局部环境

### B1. 共享导出，按真实形状选择表示

在 `collision_world.py` 保留唯一的 geom 选择逻辑，分开“选择物理部件、取得局部几何和位姿、生成 cuRobo 表示”。诊断与生产继续共用输入，避免各写一份场景筛选规则。

| 物理部件 | 首选表示 | 必须保留 |
|---|---|---|
| 原生 box 桌面、方腿、横梁、门板、柜框部件 | cuRobo cuboid，尺寸为物理半尺寸的两倍，位姿按真实 geom 转换 | 厚度、旋转、部件之间空隙 |
| 圆腿、圆柱等曲面 primitive | 已支持且语义一致的解析表示；否则足够精细的封闭曲面网格 | 圆形截面，测量多边形离散误差 |
| 目标、桌面邻物、把手、椅子复杂部件 | 少量独立物理凸包/封闭 mesh | 抓取间隙、真实占用、部件归属 |
| 复杂静态背景 | 先用于独立几何正确性对照，再按 C 阶段考虑局部 ESDF | 可能影响完整动作的障碍 |

原生 box 可直接转换，不需要三角化再拼接。mesh 只有在与实际凸包的误差已核对、且不会堵住关键间隙时才替换成盒子；不依家具名字自动整件盒化。已经由多个物理 geom 组成的桌椅直接利用现有结构，不做全资产库语义分割。

如果物理侧单个凸包已经填平 L 形内角，planner 必须保持相同占用。本轮不只在规划侧用 CoACD 挖出空隙；确需改变该资产时另做物理与规划同步的派生场景实验。

### B2. 查询组合与成本控制

关键 cuboid 与独立 mesh 使用 cuRobo 对各障碍的查询组合，避免将相交凸包直接拼接后依赖单一 mesh 的内部判定。用重叠实体内部点和外部间隙点验证实际可行性语义；不能只验证表面距离。

先用一张桌子、邻近椅子和目标邻物完成结构化原型。独立 mesh 全环境方案已有 6–11 倍耗时证据，不重做上千 mesh 的生产接入。若精确结构化后局部仍有大量 mesh，直接进入 C 阶段，不能为了减少数量又合并成符号有歧义的大 mesh。

过渡实验可以保留旧背景表示作为对照，但不能把它宣称为已完成的环境符号修复。最终候选中所有与本次运动相关的几何均须有可靠表示。

### B3. 局部范围、动态更新和接触语义

- 范围覆盖机器人全身、携带物和门/抽屉的规划运动空间及查询邻域。先沿用现有范围，只在确实不能覆盖动作时扩展；这与站位采样半径无关。
- Open 的动态集合按实际运动 body 子树确定，不能只更新把手。门板、门上附属物等随实际关节状态更新；固定门框留在环境里。
- 每次规划请求前刷新测量到的动态位姿。若一段轨迹内门角会明显变化，沿用现有分段重规划语义，并核对该段扫掠与物理执行；不能宣称一次起点位姿更新覆盖整段开门运动。
- 保持 environment、target、handle 的对象归属、接触掩码和 checker 引用关系。抓取后目标从静态障碍中移除并作为携带物参与后续检查，不能重复占用或丢失占用。
- 支撑面始终保留。目标与支撑面的合法接触、手指与目标/把手的合法接触按任务阶段表达，不全局忽略目标或桌子。

**B 完成条件**：规则部件不再承担 mesh 查询成本；关键空隙保持物理尺寸；重叠内部不被判为空地；门运动后旧位置释放、新位置被正确占用；现有目标绑定和接触语义不退化。

## 5. C：复杂静态背景的局部 ESDF（条件实施）

只有 B 的正确表示确实受独立几何数量限制时，才将复杂静态背景替换为一张局部 ESDF。近接触关键结构仍优先用精确 cuboid/mesh，避免为了统一后端而把桌边和把手一起粗化。

实施步骤：

1. 复用独立封闭物理几何构建占用并集，通过本地 cuRobo 0.8.0 的 `Mapper/MapperCfg` 和 `VoxelGrid` 做小原型。不能从现有合并 mesh 的错误符号烘焙 ESDF。
2. 首个原型固定一个任务、一个稳定地图坐标系。先量建图、更新、查询开销，再考虑同场景多站位复用；不建立跨任务通用地图服务。
3. 1 cm 只作规模/性能试验，5 mm 作误差对照，不把二者预先设成接触区域的合格精度。分别设置输入距离场和 ESDF 分辨率，测量真实表面误差、薄障碍是否丢失及窄缝是否闭合。
4. 验证重叠深内部、截断带、地图边缘和球查询邻域；越界不能默认为自由空间。地图范围不足时扩展后再求解，不把越界当成无碰撞。
5. 静态图不包含会移动的目标/门等部件；少量动态部件按 B3 更新。若其他物体被推动，静态缓存失效并重建，不能继续使用旧占用。
6. 几何、建图参数和静态位姿未变才复用；场景切换清理旧缓存。沿用现有生命周期管理，不引入文件指纹或新的持久化缓存体系。

各障碍有符号距离的最小值能表达并集占用，但重叠内部数值不一定等于并集边界的精确距离。还需核对实际优化所需的距离、梯度和可行性；官方接口可调用不等于本场景已经正确。

**C 采用条件**：没有新增关键间隙误拒绝或真实碰撞漏判；把构建和更新计入后，实际成本优于对应的独立几何候选；长 Open 不因新表示新增预算超时。否则保留 B 的结构化候选并进一步缩小有证据的复杂背景范围，不强行上线 ESDF。

## 7. 验证顺序和样本

### 7.1 先检查几何，再重放冻结查询

1. 比较最终加载球与实体覆盖、外扩和坐标关系；包括柱体升降姿态、底盘侧面/顶面及真实相交对照。
2. 对五站原始起点重放相同查询，再看目标 IK 和轨迹阶段。只改柱体、再改底盘，最后改环境，分别记录哪个约束变化。
3. 对环境验证部件间隙、相交凸包内部、同几何换参考系后的结论，以及 Open 动态刷新。
4. 冻结输入通过后，才对同 seed 创建独立 Simulation 做真实 rollout。运行开始后不恢复快照或传送；离线诊断不冒充执行。

| 样本 | 验证目的 |
|---|---|
| val1 Bowl：S0022、S0011、S0008、S0012、S0010，各原有 3 trial | 主修复集；分开起点、目标 IK 和轨迹约束 |
| 同任务 S0014、S0007 | 邻近成功对照，检查原有可行空间和性能 |
| val10 原失败 lift 查询 | 防止环境符号问题复发；与新 rollout 到达的新状态分开解释 |
| val12、val104 | 原假内部影响大；起点修复后重新诊断目标约束 |
| val107 已有异常 seed | 分别检查实际机械臂接触与几何更换后的规划退化 |
| val108、val105 的已有 Open 样本 | 动态部件、接触关系、长任务预算 |
| 原固定 12 站 | 最终集成回归，复用已有输入与原始 trial，不另挑有利站位 |

已知失败优先复现，之后执行必要对照，不为每次微小调整重复全套。候选确定后才跑固定 12 站的完整对照。

### 7.2 真实碰撞与任务结果

记录真实执行中的禁止接触，并按机器人部件和障碍定位；合法支撑/抓取接触不能混入“撞环境”。优先利用已有物理 stepping 回调采集子步接触，不新增另一套轨迹记录链。若只检查控制帧，结果必须注明不能排除帧间碰撞。

几何正确、规划完成、执行终止、任务成功分别报告。解决起点假碰撞不等于消除所有 IK/轨迹失败；少量 trial 的成功数变化只说明这批样本，不能宣布总体成功率已恢复。

### 7.3 性能比较

每阶段报告球数、cuboid/mesh 数、voxel 数、峰值显存，以及首次构建、刷新、相同查询和整个 trial 的时间。首轮热身与稳态分开；GPU 负载可比，避免把争用当成算法代价。必要时交换 GPU 做复核，不扩大成无必要的性能测试矩阵。

同时比较相同冻结查询与真实任务总耗时。提前误拒绝、少执行步骤或改变重试次数均不能单独解释成查询加速。建图成本计入实际发生的阶段和端到端时间，不从报告中隐去。

性能选择规则：先排除几何不合格的候选，再在合格候选中选总成本低的版本。沿用 300 s 等原有预算；以无新增预算失败、保持长 Open 可完成为基本约束，并明确剩余时间余量。历史 6–11 倍独立 mesh 退化是实测证据；先前对 ESDF 等方案的倍率预估仅是假设，不作为验收结果。

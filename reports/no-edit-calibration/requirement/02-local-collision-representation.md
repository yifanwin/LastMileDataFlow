## 1. 目标

**用户明确目标：不因为碰撞体的误差发生假性失败。** 在机器人围绕目标进行局部 Pick / Open 站位标定时，碰撞表示应保留实际可操作空间，不能因机器人球外扩、环境粗化、错误符号或过期位姿，把物理上可行的状态/轨迹判为不可行。在满足这一目标的前提下控制规划成本。

重点是物理精度与规划性能的取舍，不追求整个房间统一高精度，也不通过降低碰撞约束提高通过率。本轮只梳理需求，不修改实现、物理资产、站位采样、预算或成功判据。

## 2. 局部场景范围

- 机器人：底盘、躯干/固定柱、机械臂、夹爪，以及抓取后携带的目标。
- 目标：Pick 目标物体；Open 目标门/抽屉、把手及对应关节部件。
- 支撑和固定结构：桌面、桌腿、横梁，柜体、门框、冰箱固定部分等。
- 邻近障碍：目标周围桌面上的其他物体、桌边椅子，以及可能影响接近、抬起或开门的其他结构。
- 局部边界按整段操作可能到达的区域确定，覆盖底盘调整、手肘/躯干、携带物运动与门板扫掠；不能仅以目标或 TCP 的距离筛选障碍。

## 3. 按部件和形状选择表示

| 对象/部件 | 要保留的特征 | 表示需求 |
|---|---|---|
| 桌面 | 高度、厚度、边缘和目标支撑位置 | 规则长方体桌面优先考虑 cuboid；圆形或不规则桌面不能无条件套一个大盒 |
| 桌腿、横梁 | 真实截面、方向、位置以及部件之间的空隙 | 方形/长方形部件可分别用带位姿的 cuboid；圆柱形腿保留圆形截面或足够接近的表示，不强制盒化 |
| 椅子 | 椅背、座面、椅腿及其空隙 | 按相关结构拆分，避免整把椅子一个盒子填满底盘/机械臂可经过的空间 |
| Pick 目标及桌面邻物 | 抓取附近外形、相互间隙、遮挡与抬起通路 | 根据实际形状用 primitive 或精细几何；小物体也可能决定成败，不能按体积小直接忽略 |
| 把手 | 手指可进入的孔洞、间隙及接触表面 | 最高优先保留操作相关细节，不用粗包围盒封住抓取空间 |
| 门板、柜门、冰箱门、抽屉 | 厚度、边缘、转轴/滑轨关系及整个运动范围 | 规则板件可用 cuboid，特殊结构另保留；按实际状态更新，不永久当作静态障碍 |
| 固定柜体/门框 | 门或夹爪通过的开口及相邻边界 | 保留开口与独立结构，不能用整件实心盒填平 |
| 机器人与携带物 | 全身和携带物的实际占用 | 表示既不能明显超出实体造成误拒绝，也不能漏掉会接触障碍的部分；与环境表示配套检查 |

“用 cuboid”指形状相符时对部件做低成本表示，不等于给整件家具套包围盒；可以在同一场景混用多种表示。语义上的桌面/桌腿/横梁不必机械等于一个原始 mesh，应由实际几何决定能否合并或拆分。

## 4. 准确性要求

1. 保留决定操作的自由空间：桌下、腿间、椅背旁、把手内侧、门框开口和目标周围间隙。
2. 消除已知的自由空间假内部判定；多个部件组合后也不能把真实内部错误当作外部。消除误拒绝不能以漏掉真实碰撞为代价。
3. 抓取、目标支撑和必要把手接触按任务阶段与对象关系处理；不能把所有接触都禁止，也不能全局忽略目标或支撑面。
4. 以当前仿真实际碰撞几何为参照。若将一个物理实心凸包拆成有空隙的 planner 部件，会造成口径不一致，需在后续方案中明确处理，不能悄悄只改规划侧。
5. 近接触关键部件优先准确；背景允许简化。具体距离阈值、外扩容差和栅格尺寸尚未确定，应按实际间隙与误差选择，不预设整场统一 1 cm 或 5 mm。
6. 区分实体占用、明确要求的安全间隙、几何近似多出来的外扩。不能把既有球/网格的近似外扩自动解释为必须保留的安全距离。“有意保守”不等于满足不假失败的目标；临界站位仍需确认拒绝究竟来自哪一项。
7. 关键失败判定要有足够准确的碰撞依据。粗表示判碰撞、精细物理几何仍有间隙时，不能直接把它归为站位真实不可操作。后续方案可通过收紧表示或对实际争议状态精细复核解决，不预先要求实现通用多层校验系统。

## 5. 性能要求

- 用简单形状表达规则部件，避免为本来规则的 box 付出不必要的复杂网格查询成本。
- 在保留关键空隙的前提下控制部件数，不能把整屋切成大量微小块后让每次查询都遍历全部。
- 同一局部静态场景在多个候选站位和重复求解之间尽量复用几何或距离场；门、抽屉及被拿起物体的变化需及时反映。
- 比较完整规划工作量下的构建、更新、查询与重试成本，关注长 Open 预算；不能把更快误拒绝当成性能改善。
- ESDF、独立 mesh、凸包、cuboid、CoACD 都是实现候选，不是用户已指定的最终后端；本需求允许按部件混合使用。

## 6. 后续方案的验收重点

- 典型几何：桌面/桌腿/横梁、桌边椅子、密集桌面小物体、把手和运动门板。
- 已有真实样本中，实体未接触且间隙足够的状态不再因表示外扩或错误符号被拒；真实相交不应被放行。
- 原有可行操作空间保留；正常支撑/抓取关系与禁止碰撞分别表达，运动障碍无过期占用。
- 同条件比较规划结果与耗时，区分表示误差和 IK/轨迹求解本身的失败；不以笼统成功率增长代替几何正确性检查。
- 采用能满足上述需求的最小实现，避免全库重建资产、全场景统一高分辨率或一次性重写所有碰撞模块。

## 8. 新增直接案例：val1 Bowl 五个近站位

来源：`outputs/experiments/diagnostics/near-stations-val1-bowl-20261028/S*.json`。五站各三条 trial 都是 `planning_no_solution`，没有进入执行。读取日志确认 IK 的起点可行性记录均为 false；有图检查的站位起点为 0/12，S0010 没有 graph_checks，不能把 0/12 PRM 记录泛化为该站也实际运行了图检查。12 是求解内部候选数量，不是 trial 数量。

| 站位 | 已知阻塞及需求 |
|---|---|
| S0022 | 固定柱球明显外扩，目标有可行 IK；作为起点假碰撞的直接修复样本 |
| S0011 | 固定柱/升降柱假碰撞，目标只有少量可行 IK；先消除起点误拒绝，再看剩余约束 |
| S0008、S0012 | 柱体假碰撞与底盘约 1.4–1.6 cm 的小间隙同时存在；两类表示误差分开评估，不能因底盘当前设计外扩约 3.6 cm 就宣布其失败合理 |
| S0010 | 起点碰撞与目标求解困难并存；即使修正碰撞也不承诺所有 trial 成功，须分阶段归因 |

用户给出的初始实体距离与规划球穿透是首要证据。诊断 JSON 中 `rejection_geometry` 记录代表性失败轨迹状态，不一定是初始状态，不能把其中桌腿距离直接替换起点表。例如 S0022 失败候选中出现底盘真实侵入，并不否定其原始起点柱体假碰撞。

读取当前物理状态核实：固定柱是半径 0.12 m、高 0.40 m 的圆柱；升降柱是半径 0.1125 m、高 0.40 m 的圆柱。当前球模型分别为 8 个半径 0.16 m 和 8 个半径 0.15 m 的偏轴球。固定柱位于 `omron_base`，升降柱随 `panda_link0` 运动；`panda_link0` 中另有一个机械臂底座球，对应独立 mesh，不能仅按 link 名把三者混为一体。

本次另在独立、未 begin 的仿真中读取准备状态，沿用既有物理测距核对，完成三站后中止扩展查询以保持本轮需求探索范围：

| S0008 | 7.44 cm | 8.19 cm | 1.63 cm |

## 9. 此轮后续方案必须回答的问题

1. 固定柱、升降柱和机械臂底座各自如何覆盖实体，同时减小无必要外扩；要处理偏轴布局，不能只统一缩半径留下缺口。升降柱需保持随升降高度的正确坐标关系。
2. 51 球底盘在小间隙处的拒绝有多少来自近似外扩，多少来自明确保留的安全距离；当前底盘设计不是不可修改的验收标准。
3. 桌面和下部部件的物理形状、变换是否与 planner 一致。先用同状态证据确定误差来源，不因桌子参与碰撞就直接重做整张桌子或切换后端。
4. 初始状态、目标 IK、轨迹中段、真实执行分别检查。修复完成要求消除由表示误差引起的拒绝，不要求把真实不可达或真实碰撞的站位变成成功。
5. 在上述正确性成立的条件下比较球/部件数、构建更新与查询耗时；不先指定必须用 ESDF、CoACD、ILP 或某个球数。

本次只读取诊断和源码、核实初始实体几何并更新需求，没有改球、碰撞后端、物理资产、预算或成功判据，也没有运行新的 GPU rollout。

## 6. head FOV 约束的影响：同代码对照

本 run 是 head FOV 功能（commit `4838221`）合入后的第一次完整跑。用**同一 worktree、同 seed、同参数、仅 head FOV 开关不同**的 run 做对照：

对照任务的 69 个 lattice 点几何判定完全一致（逐 station 比对，`geometry` 无一处分歧）——因为站位初始化走 MuJoCo，与规划器无关。

### 6.2 任务成功率对照

| 任务 | 未开 FOV（code `f3f5f5f1`） | 开 FOV（code `1cac2c6d`） | 变化 |
|---|---|---|---|
| **SprayBottle** `pick-5a86ecebea93` | 18/45 = **40.0 %**（run `174137`） | **0/45 = 0 %**（本 run） | **归零** |
| **Cup** `pick-bf2b057e9916` | 80/105 = **76.2 %**（run `173735`） | 63/105 = **60.0 %**（本 run / `221404`） | −16.2 pt |

| Fridge 门4 open `f348afd24bb7` | — | 10/55 = 18.2 % | — |

对照有效性的两个前提已核验：**任务 seed 由 `(config.seed, house, task_id, station_id, trial)` 确定性生成**，两 run 同 seed；**valid 站点集合逐点相同**。因此性能差异只能归因于代码（head FOV）。

### 6.3 影响形态

- 开 FOV 后，SprayBottle 的 45 次 trial **全部** `planning_no_solution`，其中 44 条诊断 `constrained_planning_failure`——**不是「变难」，是「做不出来」**；

> 未验证：FOV 约束是「真不可行」还是「求解预算不足」。要区分需要在 goal 站位固定 base、逐抓取候选做自由 IK + FOV 检查的可达性扫描（本 run 未做）。

## 8. 效度边界与未验证项

- 仅 **1 个场景**（val_103）、**1 个 seed**、**1 个 GPU**，不能外推任何成功率结论。
- 「head FOV 导致 SprayBottle 归零」是**跨 run 对照**（不同 code_sha256、不同运行时刻、同 seed 同站点集）。虽已排除 seed 与站点几何两个混淆因素，仍不是同一次运行内的 A/B。
- `constrained_planning_failure` 是**冻结预算内的结论**，代码自标 `finite_budget_not_impossibility`，**不等于**物理不可达；未做 IK 可达性扫描。
- `torso_feedback_limit` 的机制（rollout 特定路径 + 零容差）沿用此前 run 的定位，**本 run 未单独复现**，但失败数与失败位置与该定位一致。
- 4 个 `no_valid_stations` 任务未深挖（是物理不可站位还是采样漏采）。
- `open-85a589b6c418` 有 2 条 rollout 但 `selection.json` 只记到 2 条失败，未追到深层归因。

## 9. 建议的下一步（按优先级）

1. **修 `torso_feedback_limit` 与 `record_only` 语义的冲突**（27/46 rollout 失败指向它）。
   要么让 `navigate()` / `arrival` 走与 `arm_tick` 相同的躯干闭环命令，要么按 `record_only` 把该反馈降级为记录（仅保留真失控如 `|h|>0.05` 的硬停止），要么给下限留与阈值匹配的容差。**这是性价比最高的一项，跨 run 复发。**

2. **对 head FOV 做可达性归因**：在 goal 站位固定 base，逐抓取候选跑自由 IK + FOV 检查，区分「FOV 几何不可行」与「求解预算不足」。SprayBottle 从 40 % → 0 % 是明确的求助信号。

3. **决定数据集口径**：是否接受「目标不在头部视野内的成功示教」。这直接决定 head FOV 该是硬约束、软代价还是仅后验过滤——当前实现是**硬约束**，代价是 18 个 pick 任务清零。

4. **复核站位采样**：49.2 % 的点「无地面支撑」+ 4 个任务 0 站位的现象，值得确认是场景性质还是采样半径/分辨率问题。

5. 把 `attempt_timeout_s=300` 纳入观察——已有 2 条 rollout 撞上该预算。

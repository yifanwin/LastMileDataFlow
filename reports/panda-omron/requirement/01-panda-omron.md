# PandaOmron 迁移：可行性与需求梳理

状态：active  
日期：2026-10-17  
替代：无（原需求文档迁入统一目录）  
关联：[首期实施方案](../plan/01-panda-omron-phase01.md)

首期以固定场景、固定站位的一次真实 pick 闭环为终点。尚未实施迁移。

## 1. 结论

**可行。模型资产已有，基础控制有本地参考实现；主要工作是让 LastMileDataFlow 支持第二种机器人本体。** 不能只增加机器人 JSON 配置：目前配置、控制、规划、相机、成功判定与训练数据都含 RBY-1 专用约定。

**首期完成整机装配、物理控制、相机与 cuRobo V2 的 FK/碰撞对齐，并在固定场景、固定站位完成至少一次真实 pick。** 保留升降机构，运行时固定在初始高度。站位采样、S0/S1、导航和数据工程留待通过后接入。

## 2. 源机器人实际是什么

| 部件 | 本地源码确认的事实 | 对迁移的影响 |
|---|---|---|
| Panda 机械臂 | 单臂，7 个转动关节，原始执行器为 motor | 接位置控制时需配置伺服，不能把关节位置直接写进原始力矩执行器 |
| Panda 平行夹爪 | 两个滑动关节，范围分别为 `[0, 0.04]`、`[-0.04, 0]` m，各有位置执行器 | 可用一个开合量对称驱动；最大关节开口 0.08 m，区别于 RBY-1 的负值开爪约定 |
| Omron 底盘 | `x/y/yaw` 三个平面关节，原始执行器为速度控制 | 源仿真允许横移；沿用它可以复用现有全向底盘规划思路，不等于真实轮式运动学已验证 |
| 升降机构 | 一个滑动关节，行程 **0–0.34 m**，PandaOmron 默认初值 0.2 m | 用户已确认保留，首期固定在初始高度，不开放升降动作 |
| 原始相机 | Panda XML 有 `robotview`、`eye_in_hand`；没有 RBY-1 的头部与双腕相机系统 | 需明确导航/观察相机、腕相机及其安装位姿；第三人称视频相机另算 |

**物理关节、控制命令与训练动作是三个层次，分别定义。** 物理模型保留源关节与执行器；控制先使用 `base_xyyaw / lift / arm_q / gripper_width` 语义字段；训练动作的选取、排序与 flatten 留到数据阶段定义。本期不冻结扁平动作维度。

不应把缺失的左臂或头部补成虚构关节，以便硬套 RBY-1 的 20D 动作和 state22。

源码入口：[组合机器人](../../../../../../robosuite/robosuite/models/robots/compositional.py)、[底盘 XML](../../../../../../robosuite/robosuite/models/assets/bases/omron_mobile_base.xml)、[夹爪 XML](../../../../../../robosuite/robosuite/models/assets/grippers/panda_gripper.xml)、[Panda XML](../../../../../../robosuite/robosuite/models/assets/robots/panda/robot.xml)。

## 3. 已有实现能复用到哪里

相邻 molmospaces 已有 [PandaOmronRobot](../../../../../../molmospaces/molmo_spaces/robots/panda_omron.py)、[关节与夹爪映射](../../../../../../molmospaces/molmo_spaces/robots/robot_views/panda_omron_view.py) 和 [规划资产](../../../../../../molmospaces/molmo_spaces/robots/curobo/panda_omron/panda_omron.yml)。可参考：

- 使用 robosuite 工厂组合 Panda、Omron 与夹爪的方式。
- 底盘、升降和机械臂转成位置伺服的参数，以及与伺服配套的关节摩擦处理。
- 底盘偏航枢轴在 `[-0.21, 0, 0]` 的坐标处理；底盘位姿、导航参考与规划 FK 必须保持一致。
- TCP、手指、URDF、碰撞球与 MuJoCo 关节之间的对应。

这些是迁移参考，不能直接视为 LastMileDataFlow 的验证结果。molmospaces 使用的 cuRobo 接口与本项目 V2 接口不同，旧 YAML 的 `ee_link` 等字段需要转换成当前 `tool_frames` 等配置，并重新验证 FK 与碰撞模型。

建议把必要模型和规划资产整理到本项目配置的 `data_root`，由本项目环境独立加载。整机生成与验收必须经过 robosuite factory；不必引入它的整套任务环境或 molmospaces 评测器。源资产保持只读，复制代码或资产时保留原有来源与许可说明。

## 4. 完整迁移涉及的接入点

下表保留完整迁移的源码探查结果；首期实施整机、薄接口、控制、相机、V2 对齐和固定站位 pick 所需的部分，数据链后接。

| 接入点 | 当前限制 | 最小迁移内容 |
|---|---|---|
| 配置与模型装配 | `RobotConfig` 只接受 `rby1m`；Simulation 直接创建 RBY1Adapter | 显式选择本体；新增 PandaOmron 配置、模型准备与控制适配器 |
| 控制与执行 | 20D 固定切片、双臂循环、RBY-1 夹爪值与六关节躯干联动 | 经薄接口使用语义动作，本体适配器内部处理关节与执行器映射 |
| 场景站位 | 初始化会调整 `head_1`；可见性读取 `head_camera` | Panda 使用实际固定观察相机进行可见性筛选，不模拟不存在的头部自由度 |
| 导航 | A* 可复用；跟踪器保持双臂与 RBY-1 躯干目标 | 换成本体实际保持状态，并按 Omron 几何计算通行范围 |
| cuRobo V2 | 使用 RBY-1 URDF、关节名、双臂 TCP、躯干 mimic 与手指碰撞链 | 提供 Panda 规划描述与关节/坐标转换，复用当前规划和执行流程 |
| 视野约束 | 相机定义绑定 `link_head_2`，且规划器无条件读取该定义 | 按实际相机挂载构造视野模型；只关闭 FOV 开关仍不足以完成接入 |
| 任务判定与快照 | 抓取监视器要求头、闲置臂、六关节躯干；快照保存 `fixed_head` | 仅检查实际存在的部件，保留真实接触、抬升、保持和连续执行语义 |
| 记录与数据集 | recorder 固定 reshape 为 20D；state22、物化、batch 读取绑定 RBY-1 | 保存本体标识、真实动作/状态布局及单位，贯通记录、物化与读取 |
| MolmoBot | 当前配置和输入输出对应 RBY1Multitask 权重、双臂与三相机 | 需要另行确定 Panda 策略权重、输入输出与训练/迁移路线 |

## 5. 语义动作与薄机器人接口

先定义语义动作，再由本体适配器映射到执行器；最后的数据阶段才决定如何 flatten。

| 语义字段 | 含义与单位 | 首期约束 |
|---|---|---|
| `base_xyyaw` | 底盘参考点的平面位姿，位置 m、yaw rad；建议用世界坐标绝对目标 | 支持底盘独立运动验证；固定站位 pick 期间保持底盘位姿 |
| `lift` | 升降轴位置，m，与 RBY-1 躯干联动参数区分 | 保留语义字段与实测值；初始化后目标固定，不开放升降运动 |
| `arm_q` | 按明确关节名顺序给出的机械臂关节位置，rad；支持指定臂 | Panda 使用其单臂，命令目标与实测状态分开 |
| `gripper_width` | 两指总开口宽度，m，定义为两个指关节位置之差 | Panda 由适配器映射为对称双指目标；半开度和 motor 值需显式转换 |

上表的绝对目标约定是建议默认。与已有 RBY-1 增量动作或 motor 夹爪协议的转换须显式留在其适配边界；既有行为保持不变，不假定两种本体控制量同义。

最少抽取以下职责，方法名可在实现时确定：

| 接口职责 | 最小契约 |
|---|---|
| `state` | 返回实际 base、lift、各可用臂与夹爪状态，携带必要的关节顺序、坐标与单位；不虚构头或闲置臂 |
| `hold` | 保持已锁定目标，覆盖首期固定的 lift；不能每步追随反馈漂移重新设定保持基线 |
| `base` | 读取/下发底盘语义位姿，内部处理关节映射和偏航枢轴 |
| `arm+gripper` | 列出可用臂，下发指定臂关节目标和夹爪总开口；提供对应 TCP 和实际手指接触部件映射 |
| `cameras` | 暴露真实相机、用途、挂载与成像参数；共享层据此渲染，不要求 RBY-1 专用相机名 |

本体选择集中在配置/创建入口；共享 stepping、控制调用、规划与 pick 判定依赖接口，避免散落 `if rby1 / elif panda`。只抽两种本体现阶段需要的职责，不建设插件系统或通用机器人框架。Simulation 继续拥有生命周期与物理步，适配器负责状态和控制映射。

## 6. 首期实施范围与验收

首期路径：

```text
robosuite factory 组合整机 PandaOmron
→ MuJoCo stepping
→ base / arm / gripper / lift-hold
→ camera
→ cuRobo V2 TCP/FK 与 collision 对齐
→ 固定场景、固定站位
→ 至少一次真实 pick 闭环
```

- 新增本体配置与薄接口适配，保留 RBY-1。Panda 初始升降高度默认建议为 0.2 m，可在初始化配置中指定。
- 使用项目独立 `.venv`、MuJoCo 3.5.0 与 cuRobo V2 0.8.0。当前项目环境缺失，需要在实施时准备。
- 源模型只读；保留实际关节范围、执行器力限制与碰撞，按需将速度/力矩执行器适配为位置伺服。
- 单独验证底盘平移/转向、臂关节到位、双指开闭及升降保持，实际读取目标与反馈。底盘沿用源模型的平面全向语义。
- 验证整机视角与腕相机画面，明确挂载、光学方向与 FOV；首期不强制引入头部 FOV 优化约束，加载和规划准备也不能依赖不存在的 RBY-1 头部分支。
- 对齐 MuJoCo 碰撞几何与 V2 碰撞球的坐标、尺度、底盘/升降/臂/夹爪覆盖和实际开度，检查自碰撞及机器人与场景碰撞。近似形状可以不同，但要说明明显外扩/遗漏；不能靠删除真实障碍或关闭碰撞通过验收。
- 固定场景、目标物体、初始站位和升降高度，执行接近、闭爪、抬升与保持。pick 的 V2 计划和实际控制均锁定 base/lift；建议先选空间充分、尺寸适配夹爪的杯子。
- 成功判定复用现有真实物理语义：双指承力、目标离开支撑面、抬升至少 5 cm 并连续保持至少 2 s，记录滑移与底盘/升降漂移；不要求不存在的头部或闲置臂。单次成功只证明该固定设置下闭环可行。
- 初始化后执行运动通过真实控制与 stepping 完成，不恢复快照、不传送、不改写 qpos 伪造控制或成功。随机 FK 校验可用独立 scratch data，不改变运行中的仿真。

### 三项硬验收

| 硬验收 | 必须验证的内容 | 必须留下的结果 |
|---|---|---|
| factory 整机 | 用 robosuite factory 组合 Panda、Omron 与夹爪，在项目目标环境中编译并 stepping；后续对齐与 pick 使用该组合来源的模型 | 组合方式、有效配置与整机运行结果；三个 XML 独立编译不能替代 |
| 随机姿态 TCP/FK | 合法关节范围内用固定 seed 取多个随机姿态，覆盖臂变化及底盘平移/偏航；lift 保持本次初值。两侧使用相同关节值、TCP 原点、姿态约定和世界参考系 | 各姿态的位置误差 m、旋转误差 rad 及最大值；不能只比位置或单个初态 |
| Omron pivot | 单独检查源模型局部 `[-0.21, 0, 0]` 枢轴，验证 yaw=0°/90°/180°，同时覆盖非零底盘平移 | 底盘参考点、MJCF 根与 TCP 的世界位姿及残差；固定 pivot 旋转时各点满足同一刚体变换，无额外漂移或重复偏移 |

随机 FK 默认抽样 20 个姿态；用户确认目标为位置 ≤2 mm、旋转 ≤0.005 rad，允许最大值为位置 ≤5 mm、旋转 ≤0.01 rad；超过最大值视为模型/坐标系未对齐。pivot 独立检查保持位置 ≤1 mm、旋转 ≤0.001 rad。pivot 校验应独立于两模型的 FK 对比，避免两侧共享同一坐标错误仍互相吻合。控制跟踪、升降保持及 pivot 的数值容差需在实施验证前明确，不能用肉眼判断代替数值结果。

### 首期交付

机器人与相机配置、factory 整机生成/加载方式、薄接口与 Panda 控制适配、V2 规划描述、可重跑的对齐和固定站位 pick 入口，以及成功演示视频、必要数值结果和 Markdown 实施报告。受影响的 RBY-1 回归需通过。只保留这些验证所需的轻量证据，不提前重构生产 recorder/dataset，也不新增生产 CLI。

## 7. 通过首期后再接入

```text
station sampling → S0/S1 标定 → A* → S0→S1→pick → recorder → dataset/物化
```

后续重建 Panda 自己的站位和标定，不能直接使用 RBY-1 成败图。届时再定义训练动作字段、flatten 顺序和数据元信息，并接入现有共享记录与物化链。open、MolmoBot 与 benchmark 仍为独立后续范围；首期通过不代表现有五个生产命令已全面支持 Panda。

## 1. 目标与现状

将 PandaOmron 从固定站位 pick 接入项目现有 cuRobo 数据生成全流程：机器人自己的站位采样与成功率标定、S0/S1 配对、移动底盘导航、目标附近底盘—机械臂联合规划、连续物理抓取、记录与数据物化。

首期已完成 factory 整机、语义控制接口、相机、MuJoCo/cuRobo FK 与碰撞对齐，固定场景固定站位的真实 pick 已成功并复验。本轮复用这些成果，不重做机器人迁移。本文只梳理需求，不表示下列功能已经实现。

本轮按“导航、站位采样、联合规划都需要”理解用户要求；“整套流程”包括此前明确后接的 recorder 和 dataset。MolmoBot/VLA 策略训练、open 操作与独立 benchmark 暂不纳入。

## 2. 完整运行链路

```text
场景与任务资产
→ PandaOmron 整机及实际相机配置
→ Panda 自己的候选站位与几何/可见性筛选
→ evaluate-stations：逐站位真实 cuRobo 操作试验
→ 基于完整实测成功率得到 S0/S1 与可用配对
→ collect-lastmile：从 S0 开始同一次物理运行
→ A* 全局路径 + 底盘闭环跟踪到 S1
→ cuRobo 目标附近底盘—机械臂联合规划与执行
→ 接近、闭爪、携物抬升、保持与成功判定
→ recorder：连续状态、命令、相机和结果
→ dataset 引用、物化与样本读取
```

站位评估是独立标定试验，可以在每次 attempt 开始前初始化到对应站位；采集中的 S0→S1→pick 必须保持物理连续，不能用标定快照替换到站后的实际状态。

## 3. 导航与联合规划的职责

| 功能 | 必需行为 | 边界 |
|---|---|---|
| 站间导航 | 复用 A* 生成全局 XY 路径；跟踪路径并完成目标 yaw；保持运输臂姿态、夹爪和 lift | 沿用源 Omron 的平面全向模型；本轮不做真实轮系/非完整运动学验证 |
| 目标附近联合规划 | cuRobo V2 同时优化 `base_xyyaw` 与 `arm_q`，执行时同步跟踪 | 使用有边界的局部工作区；不是用局部优化替代跨房间全局导航 |
| 固定底盘规划 | 保留现有固定站位手臂模式，作为对照与诊断 | 规划模式必须进入运行和标定配置，不能混用其成功率 |
| 升降与夹爪 | lift 默认保持初始化高度；夹爪按抓取阶段开合，并在规划碰撞模型中反映实际开度 | 此前未授权开放升降运动，本轮不默认加入升降优化；夹爪不作为自由寻路关节 |

联合规划必须存在实际可执行的底盘运动，而非只把模型中的关节解锁。完成局部移动后的接近、闭爪及抬升阶段，要明确各阶段底盘是否锁定；默认闭爪与抬升保持闭爪前的底盘目标，确需移动时通过显式规划模式定义。

到站后重新读取实际底盘、臂、lift 与夹爪状态，再建立局部规划参考系；不能沿用 S1 离线初始化状态。联合规划边界还应遵守场景通行范围和关节范围。

## 4. 逐模块需求

### 4.1 薄接口与坐标

- 继续使用 `state / hold / base / arm+gripper / cameras`，共享导航、站位和执行代码不新增散落的机器人名称判断。
- 控制语义保持 `base_xyyaw / lift / arm_q / gripper_width`；物理关节数、规划活动变量、控制字段、训练向量分别定义。
- 明确世界坐标底盘参考点、Omron pivot、MJCF 根、URDF 根及局部规划参考系之间的转换，复用并扩展首期已验证的映射。
- 用真实 `arms` 与相机角色替代双臂、head、torso 和固定数组切片假设；不虚构 Panda 的左臂或头部。

### 4.2 站位采样与相机

- 基于 Panda 整机几何、导航保持姿态、底盘足迹和任务位置生成候选站位；Panda 自己生成站位配置，不套用 RBY-1 的站位与成败图。
- 用实际观察相机做目标可见性检查，记录相机名称、挂载和参数；腕相机可用于操作观测，第三人称相机仅用于展示。
- Panda 没有可转头部。站位朝向应根据真实相机安装和任务选择，不调用头部俯仰搜索。
- 站位需要区分几何无效、不可见、可评估但规划失败、执行失败和成功；几何/可见性通过不等于可抓取。
- 导航路径检查需要覆盖保持姿态下整机的障碍接触，不能只因底盘二维栅格可通过就认定整机通过；允许先用保守足迹，暂不增加新导航算法。

### 4.3 S0/S1 标定与配对

- 复用现有逐站位试验和阈值语义：完整实测成功率低于等于低阈值的候选为 S0，高于等于高阈值的候选为 S1；S0 不是任意远处起点，S1 不是人工指定的成功点。
- 标定记录绑定场景任务、机器人、实际相机、初始/保持姿态、规划模式与关键规划配置；变更这些条件后重新标定，不借用固定底盘或 RBY-1 的历史结果。
- 标定中的联合规划必须使用与采集相同的局部活动范围，避免标定时任意移动底盘导致 S0/S1 失去局部站位含义。
- 沿用现有完整性、试验次数与阈值配置；不凭一次成功标记高成功率。没有合格配对时输出实际标定结果，不人为补造配对。
- 对 S0/S1 配对执行路径搜索；保留不可达与规划/执行失败原因，不将失败 attempt 计为成功。

### 4.4 移动底盘与 cuRobo V2

- 导航从实际反馈跟踪世界坐标底盘目标，偏航使用一致的角度差处理；保持锁定的 lift、臂与夹爪目标，不能逐步追随反馈漂移。
- 底盘速度/偏航速度、到达误差、步数上限沿用现有配置入口；Panda 所需差异进入机器人配置，不另设隐藏常数。
- 为 Panda 提供固定底盘与移动底盘的规划描述；活动关节、局部边界、轨迹关节名与实际控制映射一致。
- cuRobo 与 MuJoCo 都保留整机、自碰撞、真实场景及夹爪几何；携物阶段更新附着几何。预期手指—目标接触与其他障碍接触分别处理。
- 真实执行同步跟踪底盘与手臂轨迹，保留跟踪误差、接触与失败结果；不能仅验证 FK 后宣称联合规划可用。

### 4.5 连续执行与公开入口

- Panda 接入现有场景构建/站位生成、`evaluate-stations`、`collect-lastmile` 及物化入口；不只新增一个绕开生产流程的演示脚本。
- 从 S0 初始化一次，连续完成导航、到站、局部联合运动、抓取和保持。开始后不通过重置、传送、改写 qpos 或恢复标定快照完成阶段切换。
- 沿用真实抓取判据：双指承力、目标离开支撑面、抬升至少 5 cm 并连续保持至少 2 s；相机视频辅助确认，不能替代物理判定。
- Panda 与 RBY-1 使用相同流程入口；现有 RBY-1 操作、导航和数据读取保持可用。

### 4.6 Recorder 与数据集

- recorder 保存本体标识、时间、阶段、实际状态、下发目标、必要相机和操作结果；保留命令与反馈区别，导航和操作之间不中断记录。
- 按语义定义 Panda 的 state/action 字段、关节顺序、单位、参考系、绝对/增量约定和时间对齐，再决定训练导出的 flatten 顺序；本轮需求不指定 11D/12D。
- Panda 数据不填入虚构的 RBY-1 `20D/state22`。复用现有记录与导出管线，在本体数据布局处做最小适配，保持历史 RBY-1 数据可读。
- 贯通成功轨迹引用、物化、独立读取和相机/动作/状态时间对应；失败记录保留作诊断，不混入成功示范。
- 交付至少一个由真实 S0→S1→pick 生成、可物化并读取的 Panda 示例样本；本轮不承诺大规模产量或训练后的策略性能。

## 5. 验收与证据

| 验收项 | 通过条件 |
|---|---|
| 移动参考系对齐 | 在非零平移、yaw=0/90/180°及多个随机底盘/臂组合姿态下复核 pivot、TCP/FK；转换包含实际局部规划参考系 |
| 独立导航 | 有非零平移和转向的真实闭环路线，至少包含一条需绕障路线；到达误差满足运行配置，臂/lift 保持有效，无禁止的整机障碍接触 |
| 独立联合规划 | 至少一个真实案例中底盘与机械臂都发生实际运动并完成目标；只有手臂动作或只有规划器输出不算通过 |
| 站位与标定 | Panda 实际相机筛选、完整逐站位试验和成功率计算可重跑；结果区分失败类型，配对由实测率产生 |
| 连续闭环 | 至少一个合格配对真实完成 S0→S1→局部底盘—机械臂联合运动→pick→保持；导航结束后不重置，抓取成功符合原物理标准 |
| 数据链 | 上述同一次成功 attempt 可记录、引用、物化及读取；样本带正确 Panda 语义布局与时间对应 |
| 原功能回归 | 受改动影响的 RBY-1 导航、规划、记录与读取检查通过 |

沿用已确认的数值门槛：pivot 位置 ≤1 mm、旋转 ≤0.001 rad；随机 TCP/FK 目标位置 ≤2 mm、旋转 ≤0.005 rad，允许最大值位置 ≤5 mm、旋转 ≤0.01 rad，超过最大值判未对齐。默认 20 个随机姿态。导航、控制和保持使用明确的现有配置值，必要的 Panda 调整在执行前写入配置；不为本轮另造更严格的审计门槛。

端到端演示需明确记录起点/终点、路径、实际底盘位移、联合轨迹、抓取事实和样本位置。最小成功用例证明流程可用，不据此宣称跨场景成功率；失败尝试按实际结果说明，不用专门调好的固定 Cup 单站位结果替代本轮验收。

## 6. 推荐交付顺序与范围确认

1. 导航与站位的语义接口接入，验证 Panda 相机、几何筛选和真实绕障导航。
2. cuRobo 移动模型与同步执行，验证局部底盘—机械臂联合运动及坐标/碰撞对齐。
3. 逐站位完整标定、S0/S1 配对及同次运行的连续闭环。
4. recorder、样本引用、物化与读取，交付运行命令、必要视频/数值结果和 Markdown 实施报告。

当前需求默认：以上四项全部接入；lift 继续固定；使用全向仿真底盘；固定底盘模式保留作对照；MolmoBot/VLA、真实轮系、大规模数据生产与 benchmark 另议。后续实施方案再确定场景规模、试验预算、局部规划范围和数据布局细节。

## 7. 本次梳理结果

已核对当前站位采样、导航、Panda V2 模型、站位标定/配对、采集编排和数据导出源码。确认需移除的主要障碍为：头部专用站位初始化、导航双臂及固定切片、Panda 规划模型锁定底盘，以及 recorder/导出固定 `20D/state22`。本次仅新增需求文档并更新首期文档的当前状态与关联；未修改实现或运行 GPU 验收。

## 8. 实施状态

本轮已实施并完成小规模真实验收：完整标定、两个连续 S0→S1→联合运动→pick 配对、记录、物化与读取均通过；生产场景构建另接受一个 Case2 场景。具体结果与未验证边界以关联实施报告为准，不将本次小规模验证扩展为跨场景性能结论。

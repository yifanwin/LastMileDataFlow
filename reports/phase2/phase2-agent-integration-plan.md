# 阶段二外部 Agent 接入方案

## 本次执行摘要

- 依据[阶段二场景构建参考报告](phase2-scene-editing-reference.md)的机制取舍，以及[各 case 构建方案](phase2-case-build-plan.md)提出的逐 case 构造结构，给出**外部 Agent 在场景编辑构建中的接入设计**。
- 本次**只给设计方案，不改代码、不跑仿真、不调用任何外部 API**。
- 目标是回答一个问题：当前构建流程"大量规则化"，其中**哪些判断本来就该由语义模型来做**，交出去之后边界划在哪、证据怎么留。

**建议结论：把 Agent 从"规则卡住时的兜底复查者"提升为"构建期的主要取舍者"，但它取舍的对象必须是程序生成的有限命题集合。程序负责生成候选、执行、测量与验证；Agent 负责在候选之间做语义判断。这一改动不放开任何硬物理门槛，也不需要增加 Agent 数量。**

---

## 一、问题的实质不是"规则太多"，而是"规则在做它做不好的事"

参考报告 7.1 给出的立场是"视觉 Agent 按需调用，零调用也是合法路径"。这在**接口与降级**层面仍然正确，但在**默认策略**层面与当前目标有偏差：现在实际是"规则做主、Agent 兜底"，于是大量本应由语义判断决定的取舍被硬编码成了数值阈值。

一个例子足以说明问题：一个规则分支说"如果部件方向角超出容差就换候选"。这本质是一个语义判断被写成了数值阈值。阈值对不了所有资产、所有房屋——杯子把手与柜门把手、深柜取物与桌面取物，同样的角度含义完全不同。参考报告已明确指出这类数值容差不能作为通用验收标准。

所以这次改动要做的，是**把判断按性质重新归类**，而不是增加或减少规则的数量：

| 判断性质 | 现在的归属 | 建议归属 | 理由 |
|---|---|---|---|
| 测量与执行 | 程序 | 程序（不变） | 位姿、距离、接触、穿透是事实，不是判断 |
| 安全门槛 | 程序 | 程序（不变） | 硬检查不能由模型覆盖 |
| 语义取舍 | **规则阈值** | **Agent** | 这正是模型擅长、阈值做不好的部分 |
| 证据与身份 | 程序 | 程序（不变） | 可追溯性不能交给模型 |

**"交给 Agent"的准确含义是：把第四行从第三行里拆出来。** 现在它是被折叠进规则阈值里的。

---

## 二、先划清不可交出的部分

参考报告 3.3 与 3.4 已给出两条底线：Agent 不能把已检测到的严重穿模判为通过；硬门槛不能被视觉判断覆盖。落到本工程的场景构建上，以下判断必须始终留在程序一侧：

1. **真实静置后的物理结论**——物体是否仍在指定支撑面上、有无严重穿透、是否持续运动、邻近资产是否被挤落。这是测量，不是判断。
2. **编辑的执行权**——谁真正修改场景、推进仿真、提交或回滚事务。Agent 只能提议。
3. **成功定义与阈值**——参考报告已明确不让 Agent 修改成功定义、物理参数和保护规则。
4. **精确位姿**——参考报告 1.1 与 4.3 的立场：Agent 选区域与候选，程序算坐标。这一条在部件级判断上尤其重要。
5. **保护集合的解除**——Agent 可以**提议**保护某对象，不能自己放开保护。
6. **基础设施异常与物理失败的区分**——参考报告 4.5 的分类必须由程序保持。

**这六类之外，都是可以重新分配的。** 下一节逐项处理。

---

## 三、应该交出去的判断

每一项都是当前被写成规则分支或配置常量的语义判断。按"为什么该交、交出什么、什么留在程序"三段说明。

### 3.1 距离困难带是否真的构成"够不到"

距离区间现在是人工写死的配置常量，对新房屋、新桌面、新目标都不可迁移。

- **交出**：给定机器人初态、目标所在支撑面的俯视图与目标局部图，判断程序算出的若干距离候选中，哪些在语义上构成"够不到"、哪些仍然从容可及。Agent 返回候选的排序或子集。
- **留下**：实际距离测量、支撑区域边界、初态合法性。
- **注意**：Agent 判断的是"这个距离在这张桌子上意味着什么"，不是"距离是多少"。

### 3.2 侧向差异中"哪两侧值得对比、哪一侧真的窄"

参考报告已指出"北/南/西侧"必须绑定明确参照系。但当前连"挑哪两侧来对比"都是人手决定的。

- **交出**：给定家具局部坐标系下的多视角图与周边候选自由空间，判断哪两个方向真的构成通行差异、哪一侧窄到值得记录。
- **留下**：净空的实际几何计算、参照系变换、候选生成。
- **注意**：参考报告已明确"接近走廊和距离困难只能是构建启发式"。Agent 的结论仍然只是构建意图，不是导航证据。

### 3.3 把手在哪、朝向对不对、这个资产值不值得用

这是四类 case 里规则化最重的一项，也是与 10k 场景目标冲突最直接的一项——**把手标注现在是人工输入项。**

- **交出**：给定目标资产的多视角图（带构件标注），判断哪个子构件是把手、把手轴大致指向哪、该资产的把手是否清晰可用（否则换资产）。
- **留下**：Agent 指认的构件必须真实属于该目标，否则拒绝；由构件几何计算出的轴向量由程序导出，**Agent 只给构件名与方向语义，不给数值**；参考报告"不能默认模型 `+X` 就是把手方向"这条继续成立。
- **收益**：把把手标注从"人手写的一句声明"变成"模型观测 + 程序几何导出"，既摆脱人工输入，可追溯性反而更强。

### 3.4 摆放后的障碍是否构成"有意义的障碍"

障碍的位置、资产、走廊偏移与距离带现在全部硬编码。参考报告已明确"接近走廊只能是启发式"，但"这个布局像不像一个要绕的坎"目前是靠数值区间判断的。

- **交出**：给定障碍摆放静置后的场景图，判断该布局在语义上是否构成接近受阻、是否退化成完全堵死（参考报告 4.5 要求避免后者）、是否需要换障碍资产或调整位置。
- **留下**：落位正确性、穿透检查、周向无遮挡候选数、保护约束。
- **注意**：**Agent 不能删障碍，也不能解除障碍的保护。** 这一点必须由程序强制执行。

### 3.5 候选之间的取舍、修复方向、是否放弃

这三项是同一类：都是"在有限选项里选一个"，而现在是靠跨量纲线性加权排序加写死的重定位逻辑。

- **交出**：
  - **候选取舍**——在程序生成的候选集合上选一条并说明理由。这直接替代线性加权打分：Agent 比一个加权函数更会权衡"距离差一点但朝向更好"这类取舍。
  - **修复方向**——给定失败诊断与静置前后对比图，判断下一轮该往哪个方向调。参考报告的修复方向清单已经给出候选集，**由谁选**这一层应该归 Agent。
  - **是否放弃**——判断该场景还有没有修复价值，还是换候选。
- **留下**：修复方向的可执行性校验、编辑权限、事务回滚、预算计数。
- **注意**：参考报告已给出"已确认方案可缓存，但场景改变后仍需重验"的边界，这一条要保留。

## 四、观察包要补什么

参考报告 7.1 已给出基线：俯视、目标局部、机器人视角、必要侧视，加实例 ID、区域 ID、候选编号与几何事实；并且要求区分编辑前、编辑后未静置、静置后三态。在这个基线上，要支撑上面五类判断，还缺三项：

1. **候选集合本身要进观察包。** 现在的观察包里有候选字段但实际是空的——**Agent 目前根本没有候选可选**，这是最直接的一处缺口。补上之后，Agent 才谈得上"取舍"。候选项应包含编号、操作类型、涉及实例、所属区域，以及程序已算出的几何量（距离、方向角、净空），但不含精确位姿，避免模型回抄数值。

2. **构件级视图。** 目标整体特写不足以支撑"哪个构件是把手"这类判断，需要能指认构件的多视角或分割视图。

3. **对比图要成对提供。** 修复判断和障碍语义判断都依赖"静置前后"的对照，不能只给结果态。并且**最终判断只使用当前版本的证据**——参考报告已强调这一点。

**另有一条约束要保持：诊断视图（俯视、剖视、局部特写）是给人看和给 Agent 看的，不能顺手变成机器人或 VLA 的输入。** 现在的实现已经在标记诊断用途，这个标记必须在整条链路上保持。

## 五、决策协议：从"一句话复查"扩到"有界选择"

现在工程里其实已经有两层能力，但**只有较弱的那一层被接通了**：一层是只返回"通过/不通过/不确定"加一句理由的语义复查；另一层是支持"选候选、提修复、请求补图、查询几何、放弃"的结构化决策网关。后者已实现，却与实际使用的模型后端对不上——**接口有了，线没接上**。

建议的方向是：**保留严格结构化决策协议作为唯一入口，把语义复查收成它的一个动作**，并按本方案需要扩展动作类型：

| 动作 | 用途 | 约束 |
|---|---|---|
| 选候选 | 3.1 / 3.2 / 3.3 的候选取舍 | 候选必须属于当前版本 |
| 提修复 | 3.5 的修复方向 | 只能从程序声明的可执行方向里选 |
| 请求补图 | 看不清时主动索取 | 视图枚举受限 |
| 查询几何 | 查两个物体的距离或接触关系 | 区域 ID 受限 |
| 放弃 | 判定该场景不值得继续 | 必须带原因 |
| **指认部件** | 3.3 的把手构件指认 | 返回构件名，**不接受数值** |
| **确认布局语义** | 3.4 / 3.2 的布局是否成立 | 只能给通过/不通过/不确定，语义层 |
| **给出偏好序** | 可选，替代单选 | 候选集合必须与当前版本完全一致，不得多不得少 |

**所有决策必须绑定版本与观测标识**，过期决策一律拒绝。参考报告的必测故障里有"使用编辑前的候选版本"这一条，属于硬要求。

**核心原则：Agent 给的是选择与语义判断，不是数值。** 越靠近"精确量"的判断越要留在程序一侧——这条与参考报告"不让 Agent 从图片猜精确坐标"完全一致。

## 六、语义判断与物理检查如何合流

这是最容易出错的地方。建议三条规则：

- **规则一：Agent 通过不产生任何豁免。** 选中的候选仍要走完整执行、真实静置和全部物理检查。Agent 说可以，不减少任何检查项。
- **规则二：Agent 拒绝立即生效，不需要理由充分。** 保守方向的决策应快速生效——"这个资产的把手看不清"就直接换资产，程序不必复核。这能显著省预算。
- **规则三：硬检查失败时 Agent 的"通过"无效，但它的判断要留存。** 例如 Agent 认为障碍布局有意义，但静置后障碍穿进了桌面：编辑回滚，同时把 Agent 的原始判断与真实失败对照记录。**这个对照本身就是有价值的数据**，它记录了语义判断在物理上落空的实例。

由此得到三个**必须分开存储**的结论，与参考报告 4.2 的三层要求一致：

1. **场景是否有效**——物理层，程序判定。
2. **是否符合构建意图**——程序测量 + Agent 语义确认，**逐项标注它是几何测量、物理证据还是模型语义判断**。
3. **机器人是否完成任务**——留给阶段三真实试验，构建期保持未知。

第二层的强度标注是关键。参考报告已警告不要照搬论文的视觉语言模型评分当作物理保证；**把"模型看图的判断"从"几何测量"里显式分离出来，正是落实这条警告**。否则下游会把一句"看起来合理"误读成物理证据。

## 七、预算、降级与不降级的边界

参考报告 7.3 已定"冻结候选数量、编辑轮数、总静置时长、Agent 调用数和单场景超时"。在此基础上明确三点：

1. **Agent 调用默认关闭，需要它的 case 显式开启。** 这样既有配置的解释不变，也保留参考报告"零调用是合法路径"的要求。
2. **每次调用要能按用途分别计数。** 否则无法判断预算是被"选候选"吃掉还是被"提修复"吃掉。
3. **降级链必须逐 case 明确，且有一类不能降级。**
   - 距离困难与障碍布局这两类，Agent 不可用时可退回规则路径，但要如实记录决策来源是规则。
   - **把手朝向这一类不能退化**——没有可靠把手标注就不能构建，应标记为未构建，而不是猜一个把手方向。参考报告"资产池不能用一个可抓取布尔值"在这里体现为：依赖项缺失就是缺失。

还有一条：**预算耗尽与"规则判定通过"必须在数据里可区分。** 预算用完是一回事，规则判定合格是另一回事，两者混在一起会让产出率统计失真。

## 八、工作记录

参考报告与架构文档已要求记录模型与提示模板版本、结构化决策、采用与否、预算与时间。接入之后需要补的重点是三类对照关系：

- **决策用途与观测阶段的绑定**——能复核"Agent 当时看的是哪个时刻、哪张图"；
- **采纳结果与物理结果的对照**——尤其是"Agent 判定通过但物理检查失败"和"Agent 判定不通过但程序本会通过"这两类分歧，它们是评估判断质量的主要依据；
- **不记录不可见的内部推理，不保存密钥。** 现有实现只记录错误类型与状态码、不落响应体，这个做法要延续。

## 九、实施顺序

顺承各 case 构建方案的顺序（距离困难 → 障碍布局 → 把手朝向 → 侧向差异），Agent 接入穿插其中：

| 阶段 | 内容 | 完成标志 |
|---|---|---|
| **一** | 把候选集合真实送进观察包；接通结构化决策协议与模型后端 | 一次真实"选候选"决策被接受并留档 |
| **二** | 增加部件指认与布局语义确认；补构件级视图 | 把手朝向一类的指认走模型，且构件归属校验生效 |
| **三** | 用 Agent 取舍替代线性加权排序；规则排序保留为备用路径 | 同一场景在两种模式下都能产出候选，并如实记录决策来源 |
| **四** | 接通修复方向选择与偏好序 | 完成一次"模型提修复 → 程序执行 → 静置复检"的闭环 |
| **五** | 分歧统计与提示模板版本化 | 能按 case 报告判断与物理结果的分歧率 |

**最优先的是第一阶段**：候选进观察包、协议接通后端，这两件事都是最小改动，却是后面所有能力的前提——现在模型即使想看候选也看不到。

## 十、必测故障

在参考报告已列的故障之外，针对 Agent 接入补充：

1. 决策引用了过期版本的候选 → 拒绝执行。
2. 部件指认返回了不属于目标的构件，或试图返回数值 → 拒绝，轴由程序导出。
3. 模型判定通过但物理检查失败 → 回滚编辑，保留双方结论的对照。
4. 模型提议的修复违反保护约束（例如删除必要障碍）→ 程序拒绝，记为越权提议。
5. 模型反复建议同一失败候选 → 拦截，不重复消耗预算。
6. 模型不可用、超时或返回非法结构 → 按 case 降级；把手朝向类标记为未构建而非猜测。
7. 调用预算耗尽 → 记录原因并换候选，不静默转为规则通过。
8. 诊断视图被误当作机器人或 VLA 输入 → 诊断标记在全链路保持。

## 十一、对参考报告的修订建议

参考报告整体仍然成立，本方案只调整两处**默认策略**，不推翻任何硬边界：

| 参考报告 | 本方案建议 |
|---|---|
| "视觉 Agent 按需调用，零调用也是合法路径" | 保留为接口与降级立场；但在把手朝向、障碍布局两类的**默认策略**上改为主动调用，因为这两类的核心判断本就是语义性的 |
| "不照搬论文的视觉语言模型评分" | 完全保留，并新增"模型语义判断"这一强度标注，把它从物理证据中显式分离 |

其余结论——零编辑优先、最小编辑、保护与回滚、任务候选交付、外循环反馈分类——不变。

## 十二、本次范围与限制

- 本文只给设计方案，**未修改任何代码，未运行仿真，未调用任何外部 API**。
- 未评估任何具体外部模型的判断质量。本文只设计职责划分、权限边界与证据要求，**不对模型准确率作任何声明**。
- 参考报告引用的两篇论文及其本地代码未在本次复核，本文只沿用其结论。
- 构建结论仍全部为几何、物理或模型语义判断。**是否真正构成操作困难，只能由第三阶段真实试验判定。**

## 一、四类 case 共享的构建原则

### 1.1 构建产出的是任务候选，不是成功标签

四类 case 都只输出"在哪个场景、操作哪个目标、从什么初态、执行什么操作、满足哪些构建要求、还需要阶段三验证什么"。**场景是否有效、是否符合构建意图、机器人是否完成任务，三个结论分开记录。** 前两个在构建期给出，第三个构建期一律保持未知。

参考报告已明确这一边界，四类 case 没有例外。

### 1.2 判断按性质归类，而不是按难度分配

| 判断性质 | 归属 | 说明 |
|---|---|---|
| 测量（位姿、距离、接触、穿透、稳定性） | 程序 | 事实，不是判断 |
| 安全门槛（严重穿模、错误支撑、异常掉落） | 程序 | 不可被模型覆盖 |
| 语义取舍（哪个候选更符合意图、部件在哪、布局是否成立） | Agent | 规则阈值做不好的部分 |
| 证据与身份（版本、来源、事务日志） | 程序 | 可追溯性不交给模型 |

**当前的问题不是规则太多，而是"语义取舍"被写成了规则阈值。** 四类 case 的改造都围绕这一句。

### 1.3 程序生成有限命题，Agent 在命题内取舍

Agent 不从图片猜精确坐标，也不给出连续数值。程序枚举候选、算好几何量、给出编号；Agent 做选择、做指认、给出偏好序或明确放弃。**这条界定了四类 case 里 Agent 能做什么、不能做什么。**

### 1.4 零编辑优先，最小编辑其次

先检查当前场景是否已满足 case 要求。满足就跳过编辑，仍走完整验证，并如实记录"未编辑"。不满足才进入最小改动。参考报告已强调"不是每个场景都需要编辑"。

### 1.5 一次只改少量对象，改动事务化

每次改动是一个可提交或可回滚的小事务。相互依赖的少量操作可以合并为一个事务（例如先安置桌面物体再移动桌子），但不做全屋重排。复杂支撑链优先拒绝或换场景。

### 1.6 保护与失效要成对

已通过的要求进入保护；任何改动导致相关对象或区域变化时，**受影响的旧结论立即失效并重验**。删家具前查依附物；旋转目标后重查把手空间；修复不得破坏先前已通过的朝向或保护要求。

## 二、四类 case 的构建设计

每类按"构建意图 → 程序侧 → Agent 侧 → 冻结证据 → 留给阶段三"五段说明。

### 2.1 距离困难

**构建意图**：目标位于合理支撑面上，机器人初态合法，且该初态到目标的距离在语义上构成"够不到"的困难，而其他可站位置仍能成功。

**程序侧**
- 检索含合适支撑面的场景与目标；
- 计算目标与初态的实际水平距离、目标高度、支撑区域边界与边缘余量；
- 枚举有限的距离候选（沿支撑区域局部方向取样，不是全区域网格）；
- 执行编辑事务，真实静置，检查支撑正确性、稳定性、穿透与邻近资产副作用；
- 判定机器人初态是否合法。

**Agent 侧**
- 判断程序给出的距离候选中，哪些在语义上构成"够不到"、哪些仍然从容可及；
- 判断该初态在该桌面上的意义——同样的距离，在空旷桌面和堆满杂物的桌面上完全不同；
- 返回候选的排序或子集，不返回距离数值。

**冻结证据**：实际使用的机器人初态、目标位姿、支撑区域标识与边界、实测距离及其测量来源、编辑事务记录（或"未编辑"）。

**留给阶段三**：原地是否失败、其他站位是否成功。构建期**不记录**任何"不可达"结论。

---

### 2.2 侧向差异

**构建意图**：在家具的明确局部参照系下，两个方向到目标的距离与通行条件形成可记录的差异。

**程序侧**
- 确定参照系（家具局部坐标），枚举有限的方向对；
- 计算各方向到目标的距离差与几何净空；
- 检查侧向点是否真的位于家具外侧、是否处于合理高度、是否指向自由空间；
- 在候选方向上做廉价的站立可行性查询（比包围圆更接近"能不能站"）；
- 执行并静置。

**Agent 侧**
- 判断哪两个方向**真的**构成通行差异，哪一侧窄到值得记录——而不是数值上差值最大的那两对；
- 判断该差异在语义上是否成立（例如一侧对着墙、一侧对着开阔地面，与两侧都是开阔地面，含义不同）；
- 若程序枚举的方向对都不理想，请求补充方向或换家具候选。

**冻结证据**：参照对象及其局部向量与世界坐标两份、两侧的距离与净空、净空所用方法的性质（是几何代理还是站立查询）、编辑事务记录。

**留给阶段三**：各侧真实的通行、站位与操作差异，分别记录。**构建期的净空差异只是几何代理，不构成导航证据。**

**需要特别注意**：方位含义必须绑定参照系，不能随相机视角改变。这条在四类 case 里只有这一类会出现，必须显式落到证据里。

---

### 2.3 把手朝向与操作侧不匹配

**构建意图**：目标资产有清晰可用的把手，其世界朝向与要求的操作侧不匹配；通过旋转使其朝向符合要求，且旋转后仍稳定落在原支撑面上。

**程序侧**
- 从合格资产池选择目标资产（不导入任意模型）；
- 提供带构件标注的多视角图与候选朝向；
- **校验 Agent 指认的构件确实属于该目标**；
- **由构件几何导出实际轴向量**，不由 Agent 给数值；
- 执行旋转事务，真实静置，检查落位；
- 检查旋转的针对性后果：把手是否伸出支撑面边界、是否插入邻近物体、杯体是否因接触变化而滑移；
- 不使用全局统一的穿透容差——按资产类型区分。

**Agent 侧**
- 判断哪个子构件是把手（这是四类里最重的一项语义判断，也是目前唯一必须人工输入的环节）；
- 判断把手朝向大致指向哪、该资产的把手是否足够清晰可用（不清晰就换资产）；
- 旋转后复查静置图，确认把手方向符合意图、周围没有遮挡。

**冻结证据**：把手标注的来源证据、把手构件的身份、旋转前后的世界方向角、旋转增量、旋转后的落位检查结果、编辑事务记录。

**留给阶段三**：是否确为把手抓取（而非杯身或杯沿），以及不同操作侧的规划与执行结果。**构建期只能保证朝向满足要求，不能宣称把手抓取成功。**

**这一类不能降级**：模型不可用时，标记为未构建，而不是猜一个把手方向。

---

### 2.4 抓取路径障碍

**构建意图**：目标本身保持不动，在其接近侧形成有效阻挡，同时保持侧向或绕行的理论余地。

**程序侧**
- 保持目标位姿不变（这是本类与其他三类的关键结构差异）；
- 在支撑区域局部坐标系下枚举障碍位置候选（不使用世界坐标偏移）；
- 障碍来自合格资产池，新增时走与目标相同的落位与静置验证，不用启发式估算高度；
- 检查障碍与目标无严重穿透、落位稳定；
- 计算周向仍存在的无遮挡接近方向数量，作为"可绕行"在构建期唯一能拿到的凭证；
- **障碍一经提交即进入保护**，任何触及障碍的改动都记为显式编辑。

**Agent 侧**
- 判断该布局在语义上是否构成接近受阻，是否退化成完全堵死（后者要避免）；
- 判断障碍的位置和资产选择是否让这个 case 有意义——一个明显挡不住的障碍和一个把目标围死的障碍，都不算成功构建；
- 判断是否需要调整位置或换障碍资产。

**冻结证据**：障碍身份与来源（原有还是新增）、走廊在支撑区域局部坐标系下的表达、周向无遮挡方向数、障碍进入保护的记录、编辑事务记录。

**留给阶段三**：是否真的阻断规划、是否存在其他可行路径。**构建期不记录"路径被完全阻断"这类结论。**

**必须防住的一种失败**：修复流程把障碍删掉。这会让构建通过而 case 意图消失，是四类里最容易漏检的一种。

## 三、四类共用的构建流水线

```text
任务契约（case 类型、目标、初态、操作、要求、预算）
        ↓
检索：静态粗筛 → 加载少量候选 → 提取真实几何与支撑区域
        ↓
零编辑检查：已满足？──是──→ 跳过编辑，仍走完整验证
        ↓ 否
程序生成有限候选（逐 case 的几何工作）
        ↓
Agent 在候选内取舍 / 指认 / 确认语义（按需，逐 case 不同）
        ↓
权限与前置检查 → 执行编辑事务
        ↓
真实静置 → 落位、穿透、稳定性、邻近资产检查
        ↓
失败 → 回滚 → 有限修复（修复方向由 Agent 从可行集里选）
通过 → 更新事实，相关旧结论失效并重验
        ↓
最终复查全部硬要求 + 全场基础异常扫描
        ↓
冻结任务候选 → 独立恢复验证 → 交给阶段三
```

四类 case 在这条流水线上走的是同一条路径，**差异只在"生成什么候选"和"判断什么语义"两处**。

**零编辑分支要显式化。** 现在只有障碍这一类有零编辑入口，另外三类没有统一处理。建议四类统一把"零编辑即满足"作为第一个分支，并在记录里明确标注是否编辑过——这既是省预算的手段，也产出一批合法的、未被编辑的样本。

## 四、Agent 侧的共性设计

### 4.1 观察包

基线是：俯视、目标局部、机器人视角、必要侧视，附实例编号、区域编号、候选编号与几何事实；并区分编辑前、编辑后未静置、静置后三态。

四类 case 各自还需要补的：

| case | 补充视图 | 原因 |
|---|---|---|
| 距离困难 | 候选分布与目标的位置关系 | 判断"距离意味着什么"需要看到桌面全貌 |
| 侧向差异 | 家具局部坐标系下的多角度视图 | 方向判断必须能绑定参照系 |
| 把手朝向 | **构件级标注视图** | 目标整体特写不足以指认"哪个构件是把手" |
| 抓取路径障碍 | 静置前后成对对比图 | 判断"是否构成阻挡"依赖对照 |

**一条贯穿全链路的约束**：诊断视图是给人和 Agent 看的，不能顺手变成机器人或 VLA 的输入。

### 4.2 决策内容

Agent 的决策归为五类，四类 case 按需取用：

1. **选候选**——距离困难、侧向差异的候选取舍；
2. **指认部件**——把手朝向的构件指认，只给构件名，不给数值；
3. **确认布局语义**——侧向差异、抓取路径障碍的"这个布局是否成立"；
4. **提修复方向**——四类共用的失败后调整，只能从程序给出的可行方向里选；
5. **放弃**——判定该场景不值得继续，必须带原因。

所有决策绑定版本，过期决策一律拒绝。

### 4.3 合流规则

- **Agent 通过不产生豁免**：仍走完整执行与全部物理检查。
- **Agent 拒绝立即生效**：保守方向的决策快速生效，省预算。
- **硬检查失败时 Agent 的"通过"无效，但判断要留存**：两者对照本身是有价值的数据。

由此产生的构建要求要**逐项标注强度**：是几何测量、物理证据，还是模型语义判断。参考报告已警告不要照搬视觉语言模型的评分当作物理保证，这个标注就是落实那条警告的具体做法。

### 4.4 预算与降级

- Agent 调用默认关闭，需要的 case 显式开启；零调用仍是合法路径。
- 按用途分别计数，否则无法判断预算被哪类判断消耗。
- **降级逐 case 不同**：距离困难、抓取路径障碍在模型不可用时可退回规则路径（如实记录来源为规则）；**把手朝向不能退化**，标记未构建。
- **预算耗尽与"规则判定通过"必须在数据里可区分**，否则产出率统计失真。

## 五、实施顺序与门槛

顺序由两个因素决定：几何工作与已有能力的复用度，以及对模型判断的依赖强度。

| 顺序 | case | 理由 | 主要门槛 |
|---|---|---|---|
| 1 | 距离困难 | 已有闭环，几何工作最轻，不依赖 Agent 就能跑 | 冻结初态与距离来源可复现；不同布局不被混为同一身份 |
| 2 | 抓取路径障碍 | 与现有几何、资产池、新增操作复用度最高，且能立刻暴露新增资产的静置与保护问题 | 障碍落位正确且不穿透；修复流程不能删掉障碍 |
| 3 | 把手朝向 | 瓶颈在"可靠把手标注从哪来"，这是全流程最长的一条依赖 | 构件指认经校验；朝向满足要求；旋转后落位稳定 |
| 4 | 侧向差异 | 最容易"构建期通过、阶段三被否"，需要前三类把强度标注跑顺之后再上 | 参照系落到证据里；方向语义由语义判断而非数值差决定 |

**先做统一的强度标注与坐标系规则，再做 case1。** 这两件事四类都要用，且不改变现有外部行为——先把地基铺好，避免后面逐个返工。

### 必测故障（在参考报告已列之外，为四类各补一条）

| case | 故障 | 期望行为 |
|---|---|---|
| 距离困难 | 冻结初态被绕过，距离改用当前初态计算 | 拒绝或标记测量来源不一致 |
| 侧向差异 | 侧向向量指向家具内部 | 前置检查拒绝，不生成候选 |
| 把手朝向 | 把手标注只有单侧证据 | 不得标为已验证，不得作为把手抓取依据 |
| 抓取路径障碍 | 修复流程删除障碍 | 被保护拦截，或记为显式编辑并留证 |

这四条的共同特征是"**能通过现有校验但构建意图不成立**"，是当前结构下最可能漏掉的一类。

## 六、本次范围与限制

- 本文只给设计方案，**未修改任何代码，未运行仿真，未调用任何外部 API**。
- 未覆盖第四、五阶段的 case 类型；参考报告已把持物放置、柜体、容器、门体等放在后续阶段。
- 未评估任何具体外部模型的判断质量，**不对模型准确率作任何声明**。
- 四类 case 的构建结论仍全部为几何、物理或模型语义判断。**是否真正构成操作困难，只能由第三阶段真实试验判定。**

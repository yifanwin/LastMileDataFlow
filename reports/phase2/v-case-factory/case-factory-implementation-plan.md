# Case 工厂分阶段实施计划

更新：2026-10-07。**本文是计划，尚未修改代码或配置。** 设计依据：

- [数据管线重构提议](pipeline-restructure-proposal.md)（下称“重构提议”）；
- [Case 描述具体化提议](case-definition-proposal.md)（下称“定义提议”）。

已确认的前提：

- 所有任务都围绕“底盘移动后是否更好”，用配对比较判定；构造阶段用 L1（规划级）判定，正式交付要求 L2（执行级），L3 以后再定。
- 任务构造分两个分支：不编辑场景（优先）和编辑场景。
- 只使用纯场景，不使用 benchmark；正式运行用 train 集，调试用 val-103。
- `same_edge` 单独保存为“同边平移类”。
- 需要自行生成 RBY-1 抓取候选。
- Agent 先接入 ① 资产语义标注和 ③ 合理性复核；②、④、⑤ 留到主链路跑通后做对照。

本文中的“第 0–8 阶段”是 case 工厂的实施顺序，与工程原有的“五阶段”不是一回事。它们大致覆盖原方案的阶段二到阶段五。每个阶段都对应重构提议第八节中的里程碑 R0–R9。

## 全程适用的约束

以下约束沿用 `AGENTS.md`，每个阶段都必须遵守：

1. 不导入或调用 `lastmile_pipeline`；不修改原始 XML、外部资产或已有结果；每次运行使用唯一 ID，不覆盖。
2. 机器人位姿只在初始化时设置；`Simulation.begin()` 之后不恢复快照、不传送。
3. 场景编辑只通过构建会话的事务、静置、检查和回滚完成。
4. 构造通过、case 成立、任务成功分别给出结论；未测试的保持 `unknown`。“规划无解”记为“预算内无解”。
5. 算法放在领域模块，编排放在 `workflows/`，真实运动只经过 `runtime/`。
6. 每个阶段：先写单元测试，再做真实运行验证；阶段结束时在 `reports/` 下写交付报告，如实区分已实现、已验证和未验证的部分。

## 第 1 阶段：离线基础（R1、R1b、R2、资产索引）

四项任务互不依赖，可以并行。

### 1A 机器人能力标定（R1）

| 任务 | 内容 |
|---|---|
| 1A.1 | 从 RBY-1 模型读取底盘足迹、夹爪手指宽度、长度和最大开口，写入能力配置 |
| 1A.2 | 在底盘坐标系下，对目标相对位置 (x, y, z)、躯干高度、若干抓取朝向做逆运动学采样，左右臂分别统计，生成可达范围表 |
| 1A.3 | 提供查询接口：给定底盘位姿和目标位置，返回“可达 / 不可达 / 边界”及余量 |

**位置**：`robots/capability.py`，生成脚本放在 `bin/` 或 CLI 子命令。

**验收**：查表结果与阶段三已有站位结果（S000、S026 成功，S001 预算内无解）一致；边界附近抽样用逐点逆运动学复核，并统计不一致的比例。

### 1B RBY-1 抓取候选生成（R1b）

| 任务 | 内容 |
|---|---|
| 1B.1 | 单独的夹爪模型（从 RBY-1 模型中提取手指和掌部的碰撞几何） |
| 1B.2 | 几何采样：在资产碰撞网格表面采样法向相对的点对，宽度小于开口减余量；绕连线采样接近方向和深度 |
| 1B.3 | 几何过滤：预抓取和抓取位姿下，夹爪与物体不穿透 |
| 1B.4 | 仿真过滤：物体放在平面上，夹爪闭合、抬升、小幅晃动，保留物体不掉落的抓取，并记录质量分数 |
| 1B.5 | 缓存：物体坐标系下的位姿、开口、分数，附带资产版本和夹爪配置摘要；接口支持按区域筛选（供 case2 只抓把手使用） |
| 1B.6 | 接入站位规划：`planning/curobo.py` 和 `stations/` 改为读取新的抓取缓存，旧的 DROID 文件路径不再使用 |

**位置**：新增领域模块 `grasping/`。

**验收**：
- THOR 中常见的可抓类别（杯、碗、瓶、罐、水果等）都有缓存；
- 每类随机抽 1–2 个资产，在真实场景站位上用 strict-pick-v3 执行，能真实抓起。

### 1C 场景几何索引（R2）

| 任务 | 内容 |
|---|---|
| 1C.1 | 对每个场景做静态解析：支撑面尺寸和高度，各条边，边外侧地面带的宽度和深度（考虑墙和家具），面上物体 |
| 1C.2 | 写入 SQLite 索引，扩展现有 `catalog/index.py`，复用 `scenes/geometry.py` |
| 1C.3 | 前提查询：根据 CaseSpec 的前提返回“场景 + 支撑面 + 目标 + 边”候选，支持按房间类型、桌型、目标类别分层抽样 |

**验收**：
- val-103 的索引结果与仿真中实测的几何一致，人工抽查 10 个支撑面；
- train 集全部建好索引，能对四类前提查询，并统计每类前提的候选数量。

### 1D 资产索引（THOR 优先）

| 任务 | 内容 |
|---|---|
| 1D.1 | THOR 资产的尺寸、能否加载、根节点类型 |
| 1D.2 | 可抓目标的类别白名单；落地障碍物按足迹尺寸分档 |
| 1D.3 | 预留 Objaverse 接入接口（坐标轴和尺度适配），本阶段不要求接通 |

**位置**：扩展 `catalog/library.py`。

**验收**：所有 THOR 资产都有加载状态和尺寸记录；加载失败的资产记录原因。

## 第 2 阶段：主链路——不编辑分支 + case1（R3）

**目标**：跑通“前提检索 → 原始站位图 → 选 S0 → 配对比较 → 冻结”。**这是整套方案的关键检验点。**

| 任务 | 内容 | 位置 |
|---|---|---|
| 2.1 按边站位采样 | 在支撑面每条边外侧的地面带上采样站位，朝向目标；做初始化检查（地面、碰撞、限位）。现有 `coarse_samples` 是围绕目标按半径和朝向采样，需要增加按边采样的模式 | `stations/sampling.py` |
| 2.2 reach_ok | 带躯干、不考虑环境碰撞的逆运动学，用第 1 阶段的抓取候选；先用可达范围表预筛 | `validation/` 或 `planning/` |
| 2.3 plan_ok | 复用固定底盘 cuRobo；按“先 reach_ok、边界加密”的顺序分配预算 | `planning/curobo.py`、`stations/` |
| 2.4 选 S0 | 在站位图的失败区域里，按 CaseSpec 挑选合理起点：贴边、朝向目标、头部相机可见；判定移动类型（`yaw_only` / `same_edge` / `switch_edge`）；检查 S0 到 S1 有无碰撞的地面路径 | `stations/start_selection.py` |
| 2.5 配对比较 | C0（不移动）、C-yaw（原地转向）、C1（平移后），使用同一组抓取候选和同一份预算；判定 L1；对 L1 通过的任务在 S0 和 S1 上做 strict-pick-v3 严格执行，判定 L2 | `validation/comparison.py`，复用 `validation/pick.py` |
| 2.6 归因 | 按 CaseSpec 的归因规则，给出 case1、同边平移类，或未归类 | `validation/comparison.py` |
| 2.7 编排和命令 | `case-factory` 命令：输入规格、数据范围、种子、预算；输出任务记录、站位图、比较证据和漏斗表 | `workflows/case_factory.py`、`cli.py` |
| 2.8 冻结 | 冻结场景版本、S0、S1、站位图和证据；格式符合第 0 阶段定义 | 复用现有冻结和记录模块 |

**验收**：
1. val-103 上整条链路跑通，输出完整的漏斗表；
2. 与阶段三 Cup_30 的已有结果交叉核对，结论不矛盾；
3. train 子集上产出**至少 5 个 L2 级 case1**（`switch_edge`），同边平移类单独统计；
4. 漏斗中“预筛通过但真实验证失败”的比例有统计。

**判断点**：如果预筛与真实验证差距太大，先回到 1A 校准可达范围表，再进入后续阶段。不要通过放宽判定条件来提高产出。

## 第 3 阶段：不编辑分支扩展到 case3、case2，接入 Agent ①（R4）

| 任务 | 内容 | 位置 |
|---|---|---|
| 3.1 case3 判定 | 抓取通道 `corridor(e)` 的几何计算；反事实对照：在构建会话中临时移除通道内杂物，重算 S0 的 plan_ok，然后回滚 | `validation/`、`runtime/build_session.py` |
| 3.2 Agent ① 资产语义标注 | 对资产渲染图做视觉识别：把手、盖子位置，类别校正，是否适合当目标；每个资产一次，缓存；把手标注需人工抽查后才能使用 | `agents/asset_annotator.py`，复用 `agents/case_gateway.py` |
| 3.3 case2 判定 | 用把手区域筛选“只抓把手”的抓取子集；反事实对照：去掉只抓把手的限制，S0 能抓杯身 | `grasping/`、`validation/comparison.py` |
| 3.4 产出统计 | 两类 case 在 train 子集上的自然产出，按房间和目标类别统计；列出产出不足、需要编辑分支补充的缺口 | 报告 |

**验收**：case3、case2 各自给出产出统计；有产出的，至少各 1 个 L2 任务；没有产出的，写清原因和缺口。

## 第 5 阶段：合理性复核 ③（R6）

按重构提议 10.5 节实施。

| 任务 | 内容 |
|---|---|
| 5.1 固定相机组 | 头部图、俯视图、各边斜视图；编辑分支提供编辑前后两张；在图上给相关物体画框编号 |

**位置**：`agents/plausibility_reviewer.py`，`recording/` 中的固定相机组。

**验收**：误杀率和漏检率达到约定的阈值（阈值在 5.4 校准后与您商定）；不编辑分支原始场景的误杀率低。

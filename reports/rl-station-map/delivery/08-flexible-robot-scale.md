# SAC 可配置机器人尺寸适配

## 实际改动

RL 配置新增必填 `scene.robot_scale=0.9`，比例相对于原始 factory 资产。主仿真与 RL 共用 `load_robot_spec`，在原 spec 中增加缩放父 frame，保留原有 frame 的位姿与默认类。训练、评分、评估均使用同一有效配置；尺寸字段随配置保存至 checkpoint。旧 checkpoint 配置不含该字段时不能直接 resume 或评分，避免静默套用新尺寸。

Panda 默认初态不再写死夹爪开口，由适配器从模型关节范围填入；显式指定开口仍按米使用。position-v1 和 robocasa-v1 共用初态解析。RL 场景准备与站位准备使用自动开口，夹爪动作和 reset 从实际关节范围生成，宽度奖励与观测使用实际最大开口，升降位置按实际范围归一化。观测字段元数据同步标明模型参考尺度。

站位支撑半径由最终模型底盘碰撞几何相对 base_site 测得，排除升降支架及其后代，不再使用旧半径常量。TCP 动作距离、升降速度和成功门槛维持物理单位配置，不随尺寸自动改变。

修改 `configs/rl/val103_cup30.json` 的 `scene.robot_scale` 即可开展其他尺寸的独立实验。Home 升降高度需处于对应模型范围。尺寸变化使用新 run 从头训练；旧结果保留原来的实验含义。当前研究路径不使用规划器，主链 cuRobo 的 0.9 URDF / 碰撞球资产不随 RL 比例改写，不能把本改动解释成主链任意尺寸规划已支持。

## 执行与验证

- 真实 Panda 资产 CPU 编译与 RL 场景初始化：0.9 / 0.8 两种比例均完成，手指单侧上限分别为 0.036 / 0.032 m，初始开口自动匹配。
- 最终共享装配实现的真实资产 XML 导出/重载，两种比例均成功，22 个 body；检查过程中发现额外 spec attach 会产生空 default class，因此改为在原 spec 中添加缩放 frame，避免该问题。
- 29 项相关测试通过。新增测试覆盖两种尺寸的自动开口，以及带原始位移 frame 的缩放、关节范围、质量比例和 XML 重载。
- 最终实现全套回归执行 427 项：413 通过，4 跳过，9 错误、1 失败。9 错误为研究环境缺少 cuRobo / rtree；失败为此前已知的 `test_task_identity_survives_body_renumbering`。新加的第二项尺寸测试在随后 29 项相关测试中单独覆盖，不重复运行全套。
- 启动前查询 GPU 0–7，选择空闲 GPU 0。最终源码真实 GPU smoke：2 个环境、5 步随机动作、2 次 SAC 更新；更新数值有限，局部 reset 保留另一槽位 qpos，正常退出。不是训练成功或抓取验收。
- 全套测试使用研究环境 native EGL 库路径；首次禁用 GL 的全套检查还产生了子进程 EGL 错误，补齐文档已有运行库路径后不再出现。

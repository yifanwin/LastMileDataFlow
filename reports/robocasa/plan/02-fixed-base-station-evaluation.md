实验问题是：给定同一厨房、目标杯和一组候选底盘位姿，哪种方法能选出固定底盘后更容易完成抓取的位置？检验分两项：全域内与 cuRobo 闭环执行成功率的排序一致性，以及在看得见目标的站位上给 π0.5 带来的选位收益。两者各自产生一张成功率图。

## 2. 场景搭建与人工选集

从同一冻结厨房派生两组场景，一组加入指定的原生可动物体，一组加入尺寸和物理属性明确的规则几何。各组内使用同一障碍，生成远置及左右侧置变体；在共同站位上检查初态和目标可见性，再由人看图选择并冻结配对组。首轮以 layout 1 的台面取杯为例，生成参数、两种接入路径、出图和入选依据见[场景搭建专项方案](03-pick-scene-construction.md)。

## 3. 先生成一张站位表，再标出两个评测域

沿用原生采样：以目标碰撞包围盒中心为圆心，半径 0.941 m、网格间距 0.110 m，每个 XY 一个正对目标的 yaw。初始臂和升降柱取冻结姿态，检查机器人初始接触和底盘落地。历史三个厨房各有 233 个候选，分别通过 40、47、33 个。这个域是初态合法点集合；其边缘包含抓取不可达、规划可能失败的站位。当前只有目标相对航向偏移 0°，作图应按该口径显示；扫偏航属于另一个实验设置。

- cuRobo 覆盖全部初态合法点。B0、B1、B2 和质量头都给同一张表打分；方法在困难点给零分或显式失败，按预定规则计入排名。
- π0.5 在两路机身相机至少一路同时满足 FoV 和无遮挡要求的站位执行。建议在落位后的初始姿态分别记录目标投影中心与边界、同相机只渲染目标的参考像素数、实际可见像素数及两者比值。参考掩码过小或出画与遮挡分开标记；半出画目标即使像素比为 1 仍可能不合格。阈值用小样目检定下后冻结，保留每层门控的计数。腕相机继续作策略输入。可移植[已有分割比较](../../../src/lastmile_dataflow/station_map/sampling/visibility.py)的计算方法，需适配原生相机名、视觉 geom 和图像方向。
- 对 π0.5 再按到原生或示范站位的距离、相对方位分层报告。没有演示位姿分布时，将到出生点的距离标作代理。两评测器直接比较时用共同可见站位，另行报告 cuRobo 全域结果。

## 4. Baseline 与学习方法

| 方法 | 相同站位上的打分 | 搭建与校验 |
|---|---|---|
| B0 距离启发式 | 可用 exp(−(r−r₀)²/(2σᵣ²))；保留朝向项时，本轮所有点正对目标，该项恒定 | 在开发集预先定 r₀、σᵣ。相同杯、相同基座位姿的配对变体应给相同分 |
| B1 Classic IRM | 对 1.0 比例 PandaOmron 采样关节，经 FK 建 6D RD；按扩展可操作度考虑关节限位、自距与奇异性；逆变换给出目标抓姿下的直立地面 ORM | 先对齐 native base、arm root、TCP 和目标抓姿。保存离线采样量、分辨率、体素聚合、升降自由度设置；用已知 FK 位姿核对 ORM。单点 IK 成功布尔值不足以复现这项排序 |
| B2 轨迹 IRM + 静态碰撞 | 同一抓法的接近、抓握、提起路点逐一查 ORM，取最小值；各路点检查是否存在满足环境碰撞规则的 IK 解 | 明确允许的指尖–目标接触、IK 搜索预算。记录 ORM 最小值与碰撞淘汰原因。离散构型之间的连续路径和闭环执行留给评测器 |
| Ours 初版 | 可参考 station-quality：冻结控制策略的严格成功标签拟合独立成功概率模型，输入名义目标、静态抓法、扰动强度与附近几何，按扰动和抓法聚合到站位 | 在新域准备抓法与标签，质量预测和控制 PPO 的回报价值分开。Max 对应能选抓，Uniform 对应平均抓法；固定主口径并说明 π0.5 是否能接收抓法。附件的瓶颈软标签作为备选设计 |

B1/B2 的出处为 Vahrenkamp、Asfour、Dillmann，*Robot Placement based on Reachability Inversion*，ICRA 2013，§II–IV、式 (3)。原论文的轨迹 ORM 对每个基座位姿取多路点最小值，§VI 还检查轨迹点的无碰撞 IK。本实验需为 PandaOmron 实现或接入 IRM，明确 B2 附加的场景碰撞规则。附件另提 B3 但未定义打分方式，本轮保留 B0/B1/B2；cuRobo 承担独立执行评测。所有需要抓法的方法共享同一场景抓法池和聚合规则，并记录抓法来源及 TCP 约定。

**迁移质量头时先对齐标签。** station-quality 用 0.9 比例 PandaOmron，严格标签要求双指垫法向力均超过 0.5 N、脱离支撑并抬升至少 1 cm、保持 0.25 s。RoboCasa 用 1.0 比例模型、原生双指判定、保持 1 s。建议把直接使用原权重标为零样本迁移，把按 RoboCasa 判据重新采集冻结 Actor 标签、拟合质量头标为同域训练，分别报告。原场景留出站位的平均成功率 Spearman 为 0.921，同一 Actor 在编辑场景 04 为 0.71；换成独立 seed 7 Actor 时，原场景 Uniform 分数与其实测成功率的相关约 0.265。这些数字对应不同控制器或场景，正好说明为何需要两个独立执行器。[质量分数定义与实测](../../../../station-quality/reports/rl-station-map/analyze/2026-11-23-station-quality-estimand.md)

## 5. 双评测器与统一判据

| | cuRobo 规划 + 原生物理跟踪 | π0.5 原生策略 |
|---|---|---|
| 输入与动作 | 从冻结场景导出 1.0 机器人坐标和碰撞世界，标明目标、支撑和可碰对。先对齐 FK/TCP、夹爪与升降语义。基座固定，在 RoboCasa 中跟踪接近、抓握、提起并保持，逐步读取原生状态 | 沿用三路图像、原生状态和已核查的 12D 动作协议。固定底盘需在执行端约束 XY/yaw，核对 arm/base mode。逐步记录基座实际位姿和最大漂移，两评测器采用一致升降权限 |
| 重复与干扰 | 附件的 K=15–20 及轻微扰动先用于这个评测器，例如各站共用一组 ±1 cm、±1° 停靠误差。记录名义位姿、实际位姿、seed 和规划预算；初态扰动后不可落位也记录，预定其是否计为停靠失败 | 首轮可沿用每站 3 个策略 seed、相同物理初态，单独报告 K。沿用 50 s 可作开发起点；正式回合时限和动作权限提前固定。记录原始底盘命令及漂移，可定位策略对移动的依赖 |
| 回合结果 | 分开记录规划无解/预算耗尽、跟踪失败、接触、抓取或保持失败、成功。规划器的有限预算参与这个成功率定义 | 记录成功步、最大抬升、保持时长、环境接触和视频。已有 50 s 运行复核为 175/360 次 pick 成功，其中 133 次无环境接触；包含原生移动权限，仅作历史参照 |

统一采用 [PickJudge](../../../src/lastmile_dataflow/operation/outcomes/robocasa_pick.py)：指定目标持续满足原生双指抓握、脱离环境支撑、相对本回合初始高度升高至少 1 cm，按控制步连续 1 s。报告 pick 成功和无环境接触的 pick 成功两列。基础设施报错单列并披露有效回合数。冻结底盘需对实际漂移设容差；若允许升降，两种评分模型与执行器对齐其行程或固定高度。cuRobo 最小接通证据是一条原生厨房从复位到判据通过的完整执行记录；现有 LMDF 规划入口不能直接证明此链路成立。

## 6. 指标与呈现

每个场景、每个评测器先单算 S(q)=成功回合数/有效回合数，方法和评测器按同一 scene_id、station_id 连接。配对变体划分开发/测试时按父厨房分组，避免同一杯和布局同时出现在训练与跨厨房测试。分别报告每厨房结果与场景等权平均。

| 要回答的问题 | 指标与口径 |
|---|---|
| 全图排序是否一致 | Spearman ρ、Kendall τ-b，保留并列；记录站位数、K、成功率分布。常数图标记未定义 |
| 选高分站有无收益 | Top-1、Top-5 的站位等权实测成功率，与同域均匀选位比较。Top-k 平均 regret = 域内实测最高 S − 前 k 站平均 S；k=1 即单点 regret。对分数相同的一组在截点按名额等权。最高 S 是有限次试验估计，可用独立回合复评所选站 |
| 能否排除高分陷阱 | AUROC 的正类为 S≥0.5；单类场景报未定义。同时列各法 Top-5 里 S<0.5 的站数及单侧障碍相对对照的变化，便于解释假阳性 |
| 在线打分成本 | 同一硬件报告单点和整图批量耗时，写明 N、warm-up、GPU 同步、是否含场景编码或碰撞检查。100 点速度测试另列，实际场景少于 100 点时按实报 N。IRM 离线建图、质量模型训练、第三方 rollout 各单列 |

每个评测域一行五列热图：执行成功率、B0、B1、B2、Ours。标注障碍和目标、无效站与 FoV 排除点，并给出成功率色标和预测分数色标。主表尽量给按站位配对重采样的区间；π0.5 每站 3 次时只有四档经验成功率，需连同并列比例解释。

## 7. 实施顺序与本次核查范围

1. 完成原生障碍与自定义长方体两组候选的生成、重载、机身相机可见性检查与人工选片。交付选集、每例全图和代表站位视图。
2. 同一选中场景跑通固定底盘 π0.5 与 cuRobo 各一条完整动作链，核对实际漂移、判据及失败原因。先建立可产生真实执行结果的站位表。
3. 实装 B0、离线 B1、离散 B2；接入冻结的学习评分器；在同一站位小表核对帧、分数和排名，再扩到已选场景。
4. 依照 outputs/RULES.md 将快照/清单、方法分数和逐回合记录放入对应 run，总览和统计放 analysis，结论回到 reports。本次交付为工作区与框架梳理，核查了论文、源码、历史快照和回合数据。上述新场景、基线和固定底盘评测尚待实施。

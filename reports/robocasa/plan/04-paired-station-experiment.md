**首版只验证同一把壶从远处移到杯左侧以后，哪些站位变难，哪些评分能预测这种变化。** 集成位置为 `robocasa-station-eval`，PPO 算法基础为 `station-quality`。实验分别测量两件事：评分在每个场景能否选出闭环成功率高的站，以及它能否预测同站位的成功率降幅。框架验收看能否可靠测出这两项；Ours 是否优于 B1/B2 由正式结果决定。

## 1. 先合并，再适配

## 3. 两个独立执行器，共用一个物理结果定义

**动作与抓取判据。** 回合先重置、落位，再锁住世界平面的 x/y/yaw。首版建议保留原生升降自由度；PPO、cuRobo、B1/B2 都按同一行程、初始高度和各自声明的搜索预算使用升降。π0.5 保持 12D 原生映射，保存策略原始 base/mode 命令，在执行边界强制 arm mode、屏蔽平面命令，保留手臂、夹爪及原生升降语义。原生环境对三个平面关节施加可按站位设置的物理约束，mjlab 复用固定平面基座。每回合量实际最大平移和转角；建议冒烟验收设为 ≤1 mm / ≤0.1°，若超限先查控制器或约束。用带非零底盘命令及真实接触的轨迹验证。同步检查 TCP、升降实测量和原生相机，避免固定底盘时误冻结手臂。沿用已有 20 Hz 的 PickJudge，目标原生双指抓握、脱离环境支撑、相对该回合初始高度抬升 ≥1 cm，连续保持 ≥1 s，中断则重新计时。另报全程无非目标机器人–环境接触的成功率及水壶接触、位移。[原生回合实现](../../../src/lastmile_dataflow/lastmile_benchmark/robocasa_policy.py) · [原生判据](../../../src/lastmile_dataflow/operation/outcomes/robocasa_pick.py)

| 执行器 | 首轮协议（建议冻结值） | 首对正式预算 |
| --- | --- | ---: |
| cuRobo + 原生物理跟踪 | 40 站全覆盖。15 组预生成的停靠误差，台面局部 x/y 各均匀 ±1 cm、yaw 均匀 ±1°，同站两场景用同一误差和规划 seed。杯和水壶保持冻结，避免约 4 mm 净距下扰动杯造成初始穿插。用实际停靠状态规划，全池搜索、固定预算，执行接近、抓握、提起和保持。主成功率包含误差导致的非法落位，另报合法落位条件下的结果。 | 2 × 40 × 15 = **1,200**。若预先选 K=20 则为 1,600。 |
| π0.5 + 原生控制器 | 同一 39 站各跑 3 个策略 seed（42/43/44），两场景配对；冻结物理初态，不注入上述扰动。沿用三路图像、原生状态、提示 Pick up the cup.，建议 1,000 控制步 / 50 s。 | 2 × 39 × 3 = **234**。总预算 **1,434**，不含开发小样、训练、标签采集和可选独立复评。 |

**cuRobo 的最小接通证据**为从选定快照产生可跟踪的轨迹，在原生仿真内达到 PickJudge 成功，并能从失败记录区分落位、无可用抓法、IK/规划预算用尽、跟踪偏差、未抓住、抬升不足或保持中断。开发时检查杯与手指的允许接触、抓稳后的携物碰撞、机械臂–壶/柜台接触和壶的位姿变化；允许指尖接触不能绕过壶的碰撞世界。π0.5 至少在 far 正面站尝试完整回合，逐步核对原始/执行动作、夹爪与升降方向、基座漂移。若三个代表站在 far 均未抓起，先复核设置并记录失败分布，避免用整批零成功数据调评分。历史原生 50 s 的 175/360 有底盘移动权限，仅作选择时间预算的参考。[历史 π0.5 设置](../delivery/02-pi05-pick.md)

## 4. 待比较的站位评分

共用目标局部坐标下的 cup_3 抓法表。先查具体资产的可用抓姿；若缺少可用标注，则根据该杯的实际几何和 Panda 开口构建一份小型侧抓候选，保存物体到 TCP 的变换、接近方向、夹爪宽度及 grasp_id，用坐标轴叠图与原生夹起验证。对同站两场景冻结同一份候选及顺序，记录各法消耗的抓法和搜索预算；不按壶位置或第三方结果预删困难抓法。

| 方法 | 实现 | 首版验收 |
| --- | --- | --- |
| B0 距离启发式 | 对目标距离按以 r₀ 为中心、σᵣ 为尺度的高斯打分。朝向项在本轮恒定。参数在开发阶段固定。 | 同站移壶前后得分相同，差分图为零。 |
| B1 Classic IRM | 1.0 机器人离线关节采样/FK 建 6D 可达性分布，记录位姿体素的可操作度、限位和自碰撞规则。逆变换到候选底座查询抓握位姿的 ORM。升降在统一行程上分层，固定层表与聚合。 | 已知 FK 姿态能查回；报告采样数、离散分辨率与空体素率。同站同抓移壶后得分相同。 |
| B2 轨迹 IRM + 离散避障 | 同一抓法沿接近、抓握、提起三段的代表路点查 ORM，取最小值；各路点在该站寻找满足对应阶段接触规则、行程与自碰撞约束的 IK。未通过的抓法给零。 | 可复核是哪个路点、哪一碰撞对淘汰了哪条抓法；其余保留连续 ORM 分数。 |
| Ours v1 | 直接基于合入的 PPO 控制代码，独立拟合冻结 Actor 的逐抓法终局成功概率，积分得到站位分数。 | 导出逐抓法概率、站位分数、方法版本和冻结 checkpoint，能在同一名义场景上独立重算。 |

B1/B2 的方法依据见 [Vahrenkamp 等，ICRA 2013](https://h2t.iar.kit.edu/pdf/Vahrenkamp2013.pdf)。评分口径建议预先固定：B1、B2、Ours 的主表均对同一站候选抓法等权平均，反映选站后不同抓法的平均质量；可预先选抓时另报三者的 Max。π0.5 自主决定如何抓，cuRobo 从整池规划，两者结果各自保留。附件中的 B3 没有独立的评分定义；首版记录 cuRobo 在线规划时间作工程参照，进入主排名的方法为上表四项。

### PPO 训练、场景编码与质量标签

1. **准备原生到 mjlab 的物理输入。** 从选定快照恢复 1.0 机器人、冻结初始关节、目标与支撑、可动障碍和近场碰撞几何。将目标和抓法统一到基座系，核对原生与训练端 FK/TCP、夹爪开闭、壶/杯世界位姿及接触。在相同输入上逐控制步对照未抓、开始抓、脱离支撑、掉杯/成功保持等样例的原生与训练标签；替换来源分支的 0.9 模型和 0.25 s 成功窗口。
2. **训练控制 Actor。** 保留 PPO Actor、回报价值 V_ctrl、DLS 和原有训练/监控入口，从新域随机初始化。先在开发站无扰动学会接近、闭合、抬升、保持，再扩到均匀抽取的合法站和固定抓法池，最后加入轻度停靠微扰。用独立开发 seed 检查冻结 Actor 的真实 pick、超时和碰撞，按预先固定的开发标准选 checkpoint。若 Actor 在开发站只有常数标签，先修控制或课程，再采质量标签。
3. **环境编码。** 沿用来源分支的实体有向包围盒、有效掩码、目标/底盘双查询编码。核对近置壶、杯旁支撑和邻近柜体进入有效节点；节点数上限处检查被截掉的实体。实际状态送 Actor/V_ctrl。质量端只收未加噪的名义场景编码、目标状态、显式静态抓法与扰动强度 σ。
4. **拟合与推理。** 冻结 Actor，在开发站逐抓法、分 σ 执行，使用与原生 PickJudge 对齐的终局二值标签。沿用独立五成员质量模型与二元交叉熵，输出逐抓法概率和模型间分歧。主分数先按预设 σ 分布积分，再在抓法池等权平均。保留源实现五个 σ 层作为起点，并声明所对应的物理幅度；标签量可按场景 × 训练站数 × 抓法数 × σ 层数 × 重复数精确列账。附加瓶颈软标签可在这一接口上另定版本。
5. **预先划分数据。** 建议把 kettle-left-125mm 整体留作未见障碍位置。Actor 训练、质量拟合与调参使用 kettle-far 的训练/开发空间块，可在独立开发厨房补充障碍经验；同一 XY 的所有抓法、σ、seed 必须同组。对 far 与 left 的全部站仍给出部署式全图；严格留出表另取两边共同的测试空间块并标注实际站数。若只有一个父厨房，结论限定为同厨房站位与障碍位置迁移。两个第三方执行器的试验结果只用于评测，不参与选 checkpoint、定阈值或拟合质量头。

```text
冻结厨房 + 名义站位 + 杯抓法
  ├─ 实际落位/扰动 → 动态观测与实体编码 → PPO Actor → DLS/夹爪 → 物理回合
  │                                      V_ctrl ← 塑形回报与 GAE
  ├─ 冻结 Actor 的逐抓法回合 → 对齐原生的终局标签 Y
  └─ 名义实体编码 + 名义目标 + 静态抓法 + σ → 独立质量模型（训练目标 Y）
                                              → 逐抓法概率 → 站位分数
同一名义站表 → B0 / B1 / B2 / 冻结质量模型 → 分数表
同一名义站表 → cuRobo 全域 / π0.5 共同可见域 → 各自的逐回合结果 → 配对分析
```

## 5. 逐站统计、归因和交付物

- **场景内排序与选位。** 每个执行器分别算 S=成功次数/有效试验数。报告 N、K、成功数、逐站区间、Spearman ρ、Kendall τ-b、Top-1/Top-5 平均成功率、相对同域均匀选站收益、regret=max S−前 k 站平均 S，以及以 S≥0.5 为正例的 AUROC。Top-k 遇并列按剩余名额等权；常数图、单类别或过小子集的相应指标记 NA。主表同时给两套评测域，直接横向对照时取共同站。
- **同站差分。** 对每个执行器计算 ΔS=S_far−S_left，对每个方法计算 ΔQ=Q_far−Q_left。正值表示左置后下降；保留负值。报告差分的 ρ、τ-b、左右站分布、两场景同尺度热图及 Δ 图。B0/B1 的零差分是机制检查，常数向量的相关系数为 NA。各方法在两场景共享分数尺度，不逐图重归一化。置信区间按站位或空间块成对重采样，并保留同试验号的 far/left 配对。
- **π0.5 的 OOD 与视觉解释。** 先在全部 39 站报告，再报 33 站初态机身可见比例恒定子集。另列 Clean 胜任子集：3 次 seed 下 S_far≥0.7 等价于 3/3。用同三次回合选组再算降幅会高估下降，此表仅用于描述；如要以胜任子集作确认性结论，另出独立 seed 复测两侧，不占首轮预算。初态 FoV 和同站配对可控制部分差异，π0.5 降幅仍包含视觉响应；结合 cuRobo 的配对降幅、机械臂–壶接触、壶位移和失败视频解释。
- **图与耗时。** 每个执行器按 far、left、差分三行，列为实测、B0、B1、B2、Ours。标记杯、壶、非法与 FoV 排除点。并列列出几何高分但执行低成功率的站和对应回合。测同机预热并同步后的单点、实际全图 N=40、另列标准 100 查询批次耗时，注明场景编码/碰撞检查是否计入。离线 IRM 建图、PPO 训练/采标签与执行器 rollout 单独计时。
- **记录与续跑。** 一个实验单元，runs 下按真实运行存配置、输入路径、commit、站表和切分、方法版本/分数、逐回合数据、关键帧或代表视频；analysis 从原始表再生统计图；结论进 reports。分数键用 (variant_id, station_id, method_version)，执行键用 (variant_id, station_id, evaluator, trial_id)。保存名义/实际位姿、seed、漂移、成功条件、接触对象、失败阶段、耗时。设施错误同键补跑并保留错误记录；规划超时和任务失败计入分母。汇总前核对预计、有效、失败、设施缺失和重复键。

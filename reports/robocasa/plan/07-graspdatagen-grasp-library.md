## 1. 目标与优先级

为任务目标物体离线生成物体系 TCP 抓取库，最终交给 RL 的共享抓取池为 16 个。优先级：

1. **真实可用**：在原生 RoboCasa + cuRobo 与 mjlab 两侧都能抓起（PickJudge `robocasa-pick-bottom2cm-0.5s-v2`）。
2. **生成效率**：单物体分钟级完成，不引入新的仿真栈。
3. **分布均匀**：16 个在抓取位置与接近方向上尽量分散，轴对称物体不在仅差方位角的重复抓法上浪费名额。

试点物体：cup_3（kettle-far 场景，轴对称锥形杯，无把手）、cup_5（官方示教 episode_000098 场景）。

## 2. 现状与问题

| 环节 | 现状 |
|---|---|

## 3. 方案

GraspDataGen（GDG）的三段：夹爪定义（IsaacLab）→ 几何候选 `grasp_guess`（warp）→ PhysX 拉扯验证 `grasp_sim`（IsaacLab）。本方案**沿用其采样与判定思路，在 MuJoCo 中实现**，不安装 IsaacLab：

- 物理口径：成败最终由 RoboCasa 原生 MuJoCo 与 mjlab 判定；GDG 的 `franka_panda.usd` 与 RoboCasa Panda 夹爪不是同一模型，PhysX 结果不能直接代表本项目。
- 张开宽度：本项目 cuRobo 规划夹指固定 ±0.04 m、RL 从张开态接近，执行时总是全开接近。GDG 为每个候选搜索“最宽无碰开口”的多开口机制在这里退化为“全开是否无碰”，无需移植其多开口夹爪数据格式与 warp kernel。
- 几何一致：碰撞检查直接用场景里目标的碰撞几何（cup 各 48 片凸分解）与原生夹爪碰撞几何，与仿真接触同源。

### 3.1 流程

| 步 | 内容 | 来自 GDG 的部分 / 新增 |
|---|---|---|
| 1 夹爪 | 从 RoboCasa Panda（`robot_scale=1.0`）取全开夹爪的碰撞几何（手掌、两指、两指垫），以 `gripper0_right_grip_site` 为 TCP：+z 接近、x 闭合；测指垫内表面网格（沿用 `pad_rays`） | 对应 GDG 夹爪定义，开口只取全开 |
| 2 候选 | 在目标碰撞网格表面按面积采样点 p 与外法向 n；闭合轴取 n，绕 n 取 `num_orientations` 个接近方向（随机起始角均分）；指垫 A 置于 p 外 `standoff`，沿闭合轴向两侧打指垫射线，把 TCP 沿闭合轴平移使两侧间隙相等（指垫居中） | GDG finger-pad placement + center finger opening |
| 3 几何检查 | (a) 指垫成对射线命中比例 ≥ 阈值；(b) 全开夹爪与目标、与固定场景几何（支撑台面 + 固定家具，不含会随变体变化的可移动物体）的距离 ≥ 间隙阈值；(c) 沿接近轴后退扫描，记录无碰后退长度 `approach_clear_m`（上限 0.10 m，步长 5 mm） | (a)(b) 对应 GDG 碰撞检查；(b) 场景部分与 (c) 新增 |
| 4 物理验证 | 场景内（目标自由体 + 支撑 + 固定家具），夹爪挂 mocap：从预抓取点沿接近轴到抓取位姿 → 原生执行器闭合 → 抬升 → 保持，按 PickJudge 口径判定；每个候选再加若干次位姿扰动（约 5 mm / 5°，与 RL `target_m` 噪声同量级），得到稳健度 | 替代 GDG PhysX 拉扯验证 |
| 5 选 16 | 稳健度 ≥ 阈值 → 轴对称物体以对称轴为准把抓法规范到统一方位后去重 → 在（位置，旋转）度量上 FPS 取 16（沿用 `select_grasps`） | 新增 |
| 6 输出 | `grasps.npz` 保持现有字段（`transforms`、`source_rows`、对称性字段）供 RL；另写原生扫描格式（`object_to_tcp`、`grasp_id`、`kind`）供 cuRobo 逐抓法扫描 | 新增 |

### 3.2 关键约定

- **预抓取通道长度不固定**：第 3 步只记录每个候选的 `approach_clear_m`，过滤阈值看 cup_3 / cup_5 的分布再定；第 4 步预抓取点取 `min(approach_clear_m, 物理验证的接近长度)`。RL 的 `pregrasp_offset_m`（0.1）与 cuRobo 接近长度（0.08）是否随之调整，验收时再定。
- **场景只取固定部分**：同一 layout 的变体只差可移动障碍；抓取库是物体级，不随变体变化。障碍引起的不可达留给站位质量评估。
- **不考虑站位可达性**：16 个所有站位共用，按训练站可达性挑选会让站位质量图带偏；可达性由 RL / 质量模型体现（用户 2026-11-24 同意）。
- **对称性**：cup_3 轴对称，输出规范方位的抓法与 `symmetry_axis_local` / `symmetry_center_local`，RL 用 `align_to_tcp: true` 取最接近当前 TCP 的等价变体；原生扫描时把每个抓法绕杯轴转到朝向机器人的一侧。cup_5 不对称，直接 FPS。
- **类型覆盖**：先按 FPS 结果看是否自然覆盖杯沿 / 侧面 / 把手；明显缺类时再按类型分配名额。

## 4. 验收

沿用 04 号原生逐抓法扫描入口与判据：

- cup_3：kettle-far 三个名义站位，新 16 个对照旧 152 个解析池（旧基线：抓起且无环境接触 56/456 = 12%；规划成功中抓起 87/114）。报告规划成功率、抓起率、抓起且无环境接触比例。
- cup_5：示教场景站位上同样扫描（cup_5 的 RL 场景另行导出，不阻塞抓取库）。
- 抽查若干抓法用 05 号跨仿真回放确认原生与 mjlab 一致。

实现中对 §3 的两处修正：

- 碰撞体包含第 7 连杆（与法兰刚性相连）。只查夹爪时，0° 水平侧抓几何上可行，但原生规划全部失败；解析池 48 个 0° 侧抓中 38 个在抓取位姿上第 7 连杆就碰固定场景。
- 物理验证中，夹爪是带自由关节的刚体，以 weld 约束连到 mocap，并开重力补偿。若夹爪直接作为 mocap 的子体，求解器看到的夹爪速度恒为 0，摩擦不会带动物体，原生成功的抓法也会全部滑脱。

一、依赖方向：三层，箭头只向下

docs/architecture.md 的三个长期约束：领域模块负责算法，workflows 负责串联， runtime 是唯一真实运动入口。因此调用只能自上而下：编排层调领域层，领域层需要真实运动时调 runtime； runtime 不反向依赖任何业务模块。

五、编辑事务：BuildSession.transact() 的六步



  

    

      
步动作对应方法

      
1预算与可序列化检查canonical(operations)

      
2存检查点，记录事务前状态snapshot()

      
3权限 / 合法性预检_precheck()

      
4逐个执行，必要时重编译_pose() / _rebuild()

      
5真实静置 → 检查settle() → validate()

      
6通过 = committed；失败 = 回滚restore()

    

    

      事务是整组原子的：要么全部提交，要么全部回滚。失败记录照样写入
      transactions/，证据不丢。

op处理代价

rotate同上（编译期已算出新位姿）快

      
add / deletespec 改动 → _rebuild() 重编译慢
